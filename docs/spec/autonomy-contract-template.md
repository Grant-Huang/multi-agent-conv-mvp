# 授权契约模板

在让一个 agent 会话**连续自主**完成一组任务之前，由用户（或经用户批准）写这份契约，放在该任务的草稿 PR 正文或任务卡开头。它回答“这次可以自己做到哪一步、什么时候必须停下来问人”。规则见 [DEV_STANDARD.md](../../DEV_STANDARD.md) 第 5 节。

和[交接说明](handoff-template.md)的分工：授权契约在**开工前**写，定边界；交接说明在**收尾时**写，报结果。下面代码块里是模板正文。

```markdown
## 授权契约

| 项目 | 内容 |
|---|---|
| 批准人 / 日期 | <用户>，YYYY-MM-DD |
| 特性 / 需求 | <特性 ID>；REQ-…（状态须为“已确认”） |
| 有效期 | 到 YYYY-MM-DD，或到 <里程碑> 准出 |

### 可以自己做
- 任务包：……（列出可拆分的子任务）
- 可修改的路径：……
- 可运行的命令或工具：……

### 不能做（即使在任务包内）
- `AGENTS.md`“先停下来问人”中的文件和操作
- 改共享契约、宪章；扩大范围；降低任何检查的强度
- ……

### 预算
- 时间：……；重试次数：……；外部调用或费用上限：……

### 必须停下来升级的情况
- 需要改上面“不能做”的内容
- 验收用例需要修改断言
- 连续 N 次失败、预算用完、发现安全或数据问题
- ……

### 完成时交付
- 交接说明（见 handoff-template.md）
- 证据：命令、退出码、测试结果；未运行的检查如实写“未运行”
```
