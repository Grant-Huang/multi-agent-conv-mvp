# 特性档案模板

复制到 `docs/features/<特性 ID>/README.md`，特性 ID 与 `docs/testing/features.json` 的 `id` 一致。写法规则见 [DEV_STANDARD.md](../../DEV_STANDARD.md) 第 3、4 节。下面代码块里是模板正文。

```markdown
# <特性名称>

| 项目 | 内容 |
|---|---|
| 特性 ID | <与 features.json 一致> |
| 状态 | 设计中 / 开发中 / 已发布 / 已废弃 |
| 所属层 | 产品外壳 / 交互与决策 / 执行引擎 / 工业业务能力 / 世界 / 横切 |
| 服务宪章 | PRODUCT.md 第 N 节第 M 条 |
| 核对基线 | 远端 master 的 <提交>（日期） |
| 当前版本 | <最近一次发布的 tag，未发布写“未发布”> |

## 1. 意图

为什么做、为谁做、解决什么问题。写给没参加讨论的新接手的人。

**不做什么**：……

## 2. 需求

| 编号 | 需求 | 验收标准 | 状态 | 用例 | 引入版本 |
|---|---|---|---|---|---|
| REQ-<特性>-01 | …… | Given … When … Then … | 已确认 | E2E-… / RT-… | — |

状态：提出 → 已确认（用户确认）→ 已实现 → 已发布；或 已废弃（写明原因）。

## 3. 设计

结构、接口、状态、数据。一张图或一张表说清各部分怎么配合。太长时拆子文档，这里保留要点和链接。

**引用的共享契约**：

| 契约 | 条目 | 本特性怎么满足 |
|---|---|---|
| identity-and-approval | A1 | …… |

## 4. 实现入口

| 部分 | 位置 |
|---|---|
| 主要代码 | `crates/...` |
| 接口 | `GET /api/...` |
| 配置 | `[...]` |
| 前端 | `web/src/...` |

## 5. 质量

- 用例：见 testing/CASES.md 中的 ……
- 证据：docs/testing/evidence/……
- 已知缺口：……

## 6. 版本历史

| 版本 | 变化 |
|---|---|
| vX.Y.Z | …… |

## 7. 决策

| 决策 | 一句话 |
|---|---|
| decisions/YYYY-MM-DD-主题.md | …… |

## 8. 待决定

- ……

## 9. 来源（迁移时填写）

| 老文件 | 处理 | 新位置 |
|---|---|---|
| docs/... | 并入 / 拆分 / 保留为子文档 / 归档 | 本档案第 N 节 / … |
```
