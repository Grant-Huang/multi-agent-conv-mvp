# 交接说明模板

会话结束、团队到检查点、或分支要交给另一个会话继续时使用。写在该分支**草稿 PR 的正文**里（没有 PR 就先开草稿 PR），不另建文件，避免多一个需要维护的地方。

新会话接手时：先读交接说明，再读其中列出的特性档案和需求，不依赖之前的对话记录。下面代码块里是模板正文。

```markdown
## 交接说明

| 项目 | 内容 |
|---|---|
| 分支 | <分支名> |
| 截至提交 | <提交号>（YYYY-MM-DD） |
| 特性 / 需求 | <特性 ID>；REQ-…、REQ-… |
| 状态 | 可合并 / 部分完成 / 卡住（写原因） |

### 已完成
- ……（附用例编号和证据位置）

### 未完成（按顺序）
1. ……
2. ……

### 改过哪些文件
- `...`：改了什么

### 验证情况
- 已运行：命令 → 结果（贴关键输出）
- 未运行或失败：……（写原因）

### 需要别人决定的事
- ……

### 接手须知
- 容易踩的坑、临时开关、与其他分支的冲突风险
```
