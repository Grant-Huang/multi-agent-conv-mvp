# AgentNexus AI Desktop V1.7 实施计划

适用输入为 [设计规格](DESIGN.md)、[原始特性清单](agentnexus_ai_desktop_design_checklist-2.md)和 [HTML 参考原型](agentnexus_ai_desktop-5.html)。交互路径和断言使用 [目标 Feature Map](FEATURE_MAP.md)，实现按 [仓库测试约定](../testing/README.md)执行。  
对照现状的缺口与和 WP1/运营桌面的挂靠见 [GAPS.md](GAPS.md)；系统打通工作包见 [INTEGRATION_PLAN.md](../INTEGRATION_PLAN.md) §0。

## 1. 交付顺序

**首个交付快速搭建完整前端。** 先贯通产品入口、S1/S2/S3 和 SMT-03，再并行补齐其余已确认功能。A 的出口要求所有已确认前端流程均可通过正常入口使用。后端暂缺能力由 Mock 驱动，移动语音和跨设备流程也可模拟。每个后续交付均运行同一套完整前端。服务替换按能力逐项进行。

| 里程碑 | 工作顺序 | 出口 |
|---|---|---|
| A 完整前端与测试底座 | A1 壳层与导航，A2 草稿、阅读与上下文，A3 证据与历史，A4 助理、设置、交互与响应式，A5 异步、协作、审批、移动及跨设备流程。各模块由真实现有接口或注册的 Mock 驱动 | 能从真实前端入口走通所有已确认场景。Feature Map 对应 Playwright 全量通过，契约与集成验证可重复。所有 Mock 有替换负责人及门槛 |
| B 服务端连续性 | B1 可靠受理，B2 Run 与事件恢复，B3 关联、检索、个人配置及同步 | A 全回归；新增真实 HTTP/SSE/SQLite 集成，含重复提交、断线、重启与版本冲突。按能力切换运行时来源 |
| C 组织与受控执行 | C1 组织身份、对象及来源权限、频道与检索，C2 动作审批、网关和消息投递 | A/B 全回归；验证跨角色撤权、审批版本、实际副作用、结果核对与通知去重 |
| D 手机语音与跨端 | D1 实时语音和插话，D2 转写、语音任务确认及跨端续接 | A/B/C 全回归；用真实媒体链路和两设备验证权限、连接恢复、草稿冲突及语音指标 |

A 的交付开发顺序：

1. 在同一前端入口完成桌面、工作区、面板与移动布局。现有会话、任务、运营入口按兼容协议接入。
2. 用两个独立 Task 和 Conversation 数据种子验证路由、草稿、阅读位置、异步响应归属，并立即补可执行红绿记录。
3. 接入统一的有状态 Mock，补齐证据、设置、异步任务、审批、权限、语音等路径。每接一个能力就增加其 Feature Map 步骤和自动化。
4. 从干净浏览器上下文执行完整场景矩阵，修复卡片、键盘、语言输入、窄屏和返回路径问题，再完成里程碑验收。

## 2. Mock 开发和替换

Mock 由应用数据边界提供，前端组件、用户操作与请求契约保持一致。优先使用测试 harness 内的有状态 HTTP/SSE 服务；浏览器路由拦截用于少量故障注入。每次运行初始化独立种子，测试可推进时钟、延迟或丢弃响应、重放和乱序事件。系统公开可观测的请求计数与业务状态供断言。模拟和真实数据模式明确标注。生产配置禁用 Mock 及测试控制入口。

| Mock 记录 | A 阶段开发 | 预定替换及验收 |
|---|---|---|
| M1 对话、任务、上下文、历史与卡片 | 种子包含 SMT-03、产品改进、独立会话和多入口。模拟受理、拒绝、延迟、误关联、纠正 | B1/B3，复用现有接口并接入可靠受理及关联。查验一条消息一次派发，历史与关联持久 |
| M2 Run、进度、产物与事件 | 状态机、受控时钟、等待输入、取消、失败、重试；提供可读产物和包括重复、过期游标在内的事件夹具 | B2，真实执行及持久事件，HTTP/SSE 重连和重启后对账 |
| M3 助理配置、记忆、偏好与已读 | 可修改配置，模拟保存失败、版本冲突、条目纠正及未读行为 | B3 接基础设置和同步，C2 接真实记忆建议与投递。检查配置持久、版本及已读同步 |
| M4 频道、RelOS、MOM 和证据权限 | 可浏览来源与对象，两个角色，切换或撤回权限。模拟来源失效；沿用现有可用 MOM 视图 | C1，组织身份与授权查询生效后验证读取、搜索、引用和下载 |
| M5 动作审批、业务写入与提醒 | 绑定方案版本，模拟批准、拒绝、超时、回执未知。模拟去重、静默及紧急消息，使用副作用计数 | C2，真实动作网关及可控集成环境，核对权限、审计和一次副作用 |
| M6 语音及跨端 | 脚本化麦克风状态、部分/最终转写、插话、断线与切换文字。两个浏览器上下文测试续接与草稿冲突 | D1/D2，真实媒体链路和设备。采集首响应、插话停止、误打断及任务识别结果 |

每项替换依次执行：冻结请求和错误契约；以同一套契约测试对比 Mock 与真实服务；在混合接入模式跑完整 Playwright；验证真实持久性或副作用；从真实运行路径移除替身实现；更新注册表的状态、替换版本和证据。测试保留有价值的故障夹具。替换失败时只在明确的测试或演示模式切回 Mock，真实环境报告能力不可用。实际交付前指定每条记录的组件负责人。

## 3. 严格验收与回归

1. 在 A 开发前，以原始清单章节和条款文本建立逐条追溯记录。字段包含原文锚点、Feature ID、Case ID、覆盖层、所需环境、当前状态和证据位置。包括全部已确认、待实现及已演示行为；开放问题与建议记录决议，其落地部分纳入用例。章节覆盖表只是索引。
2. 功能实现前定义用例并取得符合预期的 Red 证据。环境失败不算 Red。已存在行为先记基线。场景包含正常、失败、恢复与受限行为，不随代码修改已冻结的断言。
3. 每个里程碑都运行三层检查。全前端 Playwright 在受控环境跑完整 Feature Map。集成套件跑前端、HTTP/SSE、数据和事件契约以及交叉模块流程。真实服务套件验证已替换能力的身份、存储、恢复及业务侧效果。
4. 沿用仓库 `npm run test:map`、`npm run verify` 和现有 CI 门禁。将具体路径和用例登记在 `docs/testing/features.json`、`CASES.md`，由 `docs/feature-map/COVERAGE.md` 记录覆盖证据。实现前的计划状态与证据状态独立。
5. Release 要求每条必验清单有对应自动化结果和环境标签。若限定为 Mock，保留真实服务的待验记录。任何必验失败、跳过、无法复现或清单无映射都阻断里程碑。保存 commit、Case ID、运行模式、退出码、trace/日志、状态断言和清理记录。

每次交付邀请未参与实现的验证者从 Feature Map 独立复跑 SMT-03 和至少一个失败恢复场景。发现步骤缺失、定位歧义或判据不可观察时修订地图，保留固定输入与断言后复跑。
