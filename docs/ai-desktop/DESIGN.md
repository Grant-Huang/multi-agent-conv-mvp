## 1. 目标与交付顺序

AgentNexus 是组织级 AI 工作桌面。用户可以提问、委派、取证、协作和授权执行。展开工作区或离开任务时，按各自的归属保存草稿、阅读位置、任务上下文和后台执行。S1、S2、S3 分别是日常桌面、分屏工作区、专注工作区，三者共用任务与会话数据。

| 交付 | 内容 | 完成条件 |
|---|---|---|
| A 完整前端 | 快速搭建全部已确认的桌面与移动交互，建立可运行 Mock、Feature Map、Playwright 和集成测试 | 从首个交付即可走通完整前端，可重复验证正常、失败、恢复及权限反馈 |
| B 服务端连续性 | 按能力替换会话受理、任务关联、恢复、事件、配置及历史 Mock | 全前端回归通过，迁移能力另有真实服务集成证据 |
| C 组织与受控执行 | 替换频道、RelOS、NexusOps、动作审批、内省和主动消息 Mock | 全前端回归通过，真实权限、来源和副作用可验证 |
| D 手机和跨端 | 替换实时语音、插话、转写、确认和跨设备续接 Mock | 全前端回归通过，真实语音和多设备行为取得独立证据 |

A 优先完成完整前端外壳和贯通场景，再补齐各功能的决策与异常路径。已确认功能从 A 即可在前端操作。暂缺的后端在边界处使用有状态的 Mock，演示数据和真实服务模式明确标识。B 到 D 每次交付均保留完整前端路径和全量可运行回归，按能力替换 Mock。替换必须通过共用契约与真实服务集成测试。生产模式缺少服务时显示明确的不可用状态，测试替身通过独立模式启用。

在 A 中，SMT-03 是首条贯通路径。运营桌面入口复用 MOM 视图及其「看板、任务、资源」信息架构。手机语音、跨端、权限与动作可以用模拟后端走完 UI 流程。真实麦克风、跨端服务、授权及业务副作用分别核验。

实施顺序、Mock 生命周期及门禁见 [实施计划](PLAN.md)；Mock 注册与取代明细见 [MOCK_REGISTRY.md](MOCK_REGISTRY.md)。每项用户路径、自动化操作及断言见 [目标 Feature Map](FEATURE_MAP.md)。对照现状与已确认方向见 [GAPS.md](GAPS.md)（单轨桌面、A1 一次换壳、SMT-03 可纯 Mock）。

## 2. 导航、工作区与面板

应用由全局导航、工作侧栏、内容区、底部输入区和侧边面板组成。默认进入「我的 AI 桌面」，固定「我的工作」「Agent 工作」「为你关注」分区。推荐由结构化模型驱动固定组件。用户可固定、隐藏、关注和查看推荐原因。局部状态更新保留焦点卡片位置，用户结束操作后再调整排序。侧栏保留助理、历史、任务和最近频道。

| 入口或操作 | 落点 | 返回与恢复 |
|---|---|---|
| 首页卡片、关注任务、历史任务 | 共用按 Task ID 打开逻辑。首次进入 S2，续接按设备恢复 S2 或 S3 | 返回原来的卡片、历史位置及筛选 |
| 首页 SMT-03「查看证据」 | `TASK-2026-018` 的工作区及证据预览 | 先关闭证据，再返回首页推荐 |
| 频道消息、RelOS 对象的任务链接 | 对应 Task，可按来源定位消息或证据 | 恢复原频道或对象面板 |
| S1 简单问答 | 桌面浮层，下一轮沿用会话 | 收起后从历史恢复 |
| S1 委派 | 同一浮层显示受理结果与任务引用，输入保持可用 | 用户主动展开工作区后进入任务 |
| 浮层「展开工作区」 | 沿用 Conversation ID。已有 Task 时打开任务，独立会话可使用工作区外壳 | 返回浮层。关联建立后才提供任务专属动作 |
| 浮层「转为任务」 | 就地确认标题、业务对象和共享范围，建立逻辑关联 | 原消息与 ID 保留 |
| S2 收起任务信息、S3 展开任务信息 | 同一工作区切换布局 | 保留草稿、执行卡及阅读锚点 |
| 「执行」及「产物」 | 执行在会话内展开。产物在面板中打开可读详情 | 回到触发位置 |
| 助理头像、「与我的助理交谈」、主动消息 | 同一个人助理面板 | 恢复下层界面与焦点 |
| 「设置与管理」、场景内设置捷径 | 唯一设置中心。捷径直达分类 | 关闭返回原工作。身份编辑和记忆详情各自返回原分类 |

S2 任务栏展示标题、状态、ID、业务对象、来源、负责 Agent 和上下文策略，另一侧展示会话、执行与输入。S3 收起任务栏并保留任务标题和恢复入口。通过工具条、首页按钮和浏览器回退触发的导航使用一致的来源记录。结构为入口 ID、目标类型及 ID、源视图、位置锚点和面板层级。源对象失效时返回最近可访问父视图。

证据、历史、设置和助理消息共享一个主要侧边面板。详情作为下一层，关闭恢复上一层。切换面板前保存编辑。审批弹窗结束后恢复原工作。宽度至少 1024 CSS px 时默认并排，窄屏用可关闭覆盖面板且保留原布局偏好。验收 360、768、1024、1440 CSS px。使用原生可聚焦控件，支持 Escape 与系统减少动态效果设置。中文输入法组合期间 Enter 用于选词，结束后 Enter 发送、Shift+Enter 换行。

## 3. 草稿、阅读位置与上下文

| 数据 | 保存范围 | 恢复规则 |
|---|---|---|
| 草稿、附件引用、上下文选择 | 当前用户和组织、Conversation ID、Task ID 或无任务 | 输入时更新，离开前保存。首版单机使用本地存储命名空间；接入真实身份后以服务端认证身份为准 |
| 阅读锚点、执行卡展开状态 | 同一工作范围加设备 | 首条可见 `Message.id` 加像素偏移。记录不可见时选最近可见消息。首次打开定位最新 |
| S2 / S3 | 用户、设备、工作区 | 留存用户选择，窄屏临时替代布局不覆盖选择 |
| 来源、筛选、滚动、面板层级 | 导航记录 | 返回时恢复，权限变化时丢弃无权访问的目标 |
| 会话、任务、执行和产物 | 服务端稳定 ID | 局部刷新，切换和返回继续使用原记录 |

发送前固定本次 `conversation_id`、目标 Task、输入正文及草稿版本。响应只更新其归属会话。页面切换后迟到的请求不可覆盖当前会话。服务端确认后仅清理已发送版本，用户在等待期间追加的输入仍保留。失败显示行内错误并保留文字。现有发送接口的超时结果可能未知，先回读消息与任务确认，再由用户选择重发。交付 B 的幂等接口允许以原操作 ID 自动重试。

输入区显示自动关联、继续当前任务或开始独立话题。自动关联考虑可访问任务、业务对象和明确指令，显示采用结果及原因。用户指定继续时固定 Task ID。选择独立话题创建独立会话并留存原现场。遇到歧义就地列候选及「保持独立」，普通问答不创建 Task。误关联通过撤回旧关系与建立新关系修正，保留原消息及审计。旧关联已触发执行时独立显示该执行及处置选项；修正关联本身不会取消或重新派发工作。

## 4. 源码核对与兼容协议

以下为基线实际注册路由及前端调用。源码定位见 [HTTP 路由和处理器](../../crates/server/src/lib.rs)、[会话运行时](../../crates/runtime/src/conversation.rs)、[任务编排](../../crates/runtime/src/orchestrator.rs)、[持久化与事件](../../crates/runtime/src/store.rs)、[核心结构](../../crates/core/src/lib.rs)、[Web API](../../web/src/api.ts)、[前端会话刷新](../../web/src/App.tsx)。

| 已有协议 | 返回与约束 | 桌面接法 |
|---|---|---|
| `GET /api/conversations`、`POST /api/conversations` | 列表和新建。新建可传 `title`，响应为 `Conversation` | 复用历史及独立话题创建；首版沿用现有 ID |
| `GET /api/conversations/{id}/messages` | `MessageView[]`，包含消息的卡片字段，目前无游标参数 | 复用真实会话历史及确认卡。保留返回卡片和现有消息 ID |
| `POST /api/conversations/{id}/messages` | 请求 `{"text":"..."}`，返回 `TurnOutcome { reply, decision, task }`。HTTP 等待回合结果。服务端将回合放在独立 Tokio 任务，派发后 Task 由编排器推进 | A 保留现有请求和响应。客户端可在等待中切换界面。收到带 Task 的响应后才显示已经关联，失败或超时时先回读 |
| `GET /api/tasks?conversation_id=…` | 返回 `TaskRecord[]`。按当前归属会话筛选，可省略该过滤条件 | 用于当前会话任务列表。本地模式可直接使用；组织级桌面接入用户与对象 ACL 后才聚合 |
| `GET /api/tasks/{id}?after=…` | 返回 `{task,events}`。刷新前冲刷事件写队列；`after` 是任务事件 ID，找不到时回传当前可用历史 | 任务头部读取 `task`；执行卡按事件 ID 合并并去重。重连或回到详情时补读 |
| `POST /api/tasks/{id}/cancel`、`POST /api/tasks/{id}/approve` | 分别返回 `{cancelled}`、`{approved}`。常规批准路由按任务 ID 调用 Orchestrator，冲突返回 `409` | 当前运行时任务审批与取消沿用原协议。生产业务写入选用动作级审批 |
| `GET /api/events?conversation_id=…` | SSE 事件名 `task_event`，数据为 `TaskEvent`。源自运行时 broadcast；落后帧跳过，未实现 SSE 游标重放 | 作为刷新信号。打开或重新连通时补读消息及任务，展开执行卡时按任务事件 ID 补齐。流式片段只临时展示，最终以落库消息为准 |
| `POST /api/feedback` | 接收 `message_id`、原始及纠正动作和角色，可带说明 | 用于现有路由反馈。实际撤回或重关联另走关系写入 |
| `GET /api/mom/desk` 及 case 详情、频道入口和未读；`/api/introspection/*` | 运营桌面在脚本 MOM 与开关条件下挂载；内省有独立结论与未读读模型 | 使用模块原有数据和链接标识。MOM case ID 与 Task ID 各自保留，通过类型化引用关联 |

核心现状为 `Conversation {id,title,created_at}`、`Message {id,conversation_id,role,content,task_id,created_at}`、`TaskRecord {id,conversation_id,goal,role,status,route,policy,result,review,assignment,created_at,updated_at}`。任务展示标题可先用 `goal`，任务拥有一个归属会话。应用层使用 `Message.id` 作为消息锚点。未来的关联表保留此消息 ID 和旧任务归属。现有 `AppError` 返回 `{"error":"..."}`，前端包装兼容 `message` 和 `error`。新结构化错误只在扩展协议内引入。

现有 `TaskStatus` 原值为 `CREATED`、`QUEUED`、`RUNNING`、`VERIFYING`、`NEEDS_HUMAN`、`COMPLETED`、`FAILED`、`CANCELLED`。桌面映射为已创建、排队、执行中、核验中、需人工处理、完成、失败、取消，保留源状态。只有具体等待原因表明是审批时才显示「待审批」。候选、归档、暂停与详细等待原因在各自新增模型中表达。

`TaskEvent` 包含 `id,conversation_id,task_id,kind,status,message,stream_id,created_at`。现有类型包括 `status_changed`、`progress`、`assistant_message`、`assistant_delta`。最后一种为临时流式片段。任务时间线合并使用事件 ID，消息合并使用消息 ID。当前事件历史有保留窗口，找不到旧游标后的回传结果仅覆盖当前保留的数据。会话切换应关闭旧订阅，同时用请求所绑定的会话 ID 拒绝旧响应写入当前视图。

运营审批接口 `POST /api/mom/desk/cases/{id}/approve` 使用 `scope,plan_revision`，过期方案返回冲突。它使用 [现有的运营脚本链路](../../crates/server/src/mom_ops.rs)，[服务入口](../../crates/server/src/main.rs)对脚本 MOM 作 loopback 限制。企业身份接入前，界面仅展示模拟审批语义。MOM 事项、审批对象和 AI Task 按业务归属保存。

## 5. 扩展协议与数据模型

下面为 B–D 的新增协议提案。首批前端工作复用第 4 节。新增读写接口建议统一使用 `/api/desktop/v1` 命名空间，保持既有 HTTP、配置和 AgentAdapter 签名兼容。实施时按仓库规定更新 Rust 导出及 TS bindings，数据库扩展采用向后兼容迁移。

| 新增接口（路径均相对该命名空间） | 请求与返回 |
|---|---|
| `GET /snapshot` | 返回卡片、计数、未读和一致性游标。卡片含 `zone, card_type, entity_id, priority, actions, updated_at, source_refs` |
| `POST /conversations/{id}/requests` | 请求 `client_operation_id, text, scope, task_id?, attachment_refs?`。在受理记录和消息持久化后返回 `202 {request_id,message_id,status,task_id?,run_id?}`。后台分流完成再更新关联。相同操作 ID 重试返回同一请求；输入不一致返回 `409` |
| `GET /requests/{id}` | 返回受理、分流中、已分流或失败，包含关联 ID 及结构化错误。作为受理响应和事件丢失后的查验入口 |
| `GET /conversations/{id}/messages?before=…` | 返回按持久序号分页的消息与下一页游标；保留既有消息卡片 |
| `PATCH /tasks/{id}/metadata` | 请求业务标题、对象或关联变更及 `expected_version`。冲突返回 `409` 和可读当前版本。执行目标改变走计划变更 |
| `POST /tasks/{id}/links`、`DELETE /tasks/{id}/links/{link_id}` | 建立关系或记撤回。请求带操作 ID、预期版本及来源消息 ID |
| `GET /tasks/{id}/artifacts`、`GET /artifacts/{id}?version=…` | 产物列表及具体版本、预览、引用。每次读取按当前访问权限过滤 |
| `POST /runs/{id}/actions` | 请求动作、操作 ID、预期版本及所需输入；返回当前状态及允许的后续动作 |
| `POST /approvals/{id}/decision` | 请求批准或拒绝及参数版本。授权和实际执行分别校验 |
| `GET /preferences`、`PATCH /preferences` | 读取和修改当前用户配置。修改带预期版本 |
| `GET /memories`、`GET /memories/{id}` | 个人记忆列表与详情（来源、正文、有效期）。首版可由服务夹具权威 |
| `PATCH /memories/{id}`、`DELETE /memories/{id}` | 纠正正文/标题/有效期；撤回（默认列表隐藏，幂等）。首版进程内夹具；持久化表另卡 |
| `POST /assistant/messages/read` | 接收消息 ID 列表，幂等记录当前用户已读 |
| `GET /events?after=…` | 按游标回放并续接授权增量。游标失效返回明确的重取快照信号 |

新增错误返回 `code,message,retryable,request_id`。校验失败为 400，认证缺失为 401，当前用户权限不足为 403；需要避免泄露对象是否存在时统一返回 404。状态、版本或幂等冲突为 409。相同操作的唯一键是服务端解析的租户、用户与客户端操作 ID；消息、操作记录与待派发项在同一次持久化提交中建立。客户端重试和 Worker 重领均复用这组关联。

| 扩展记录 | 字段及边界 |
|---|---|
| 会话与消息 | 逐步补充组织、所有者、可见范围和会话内单调序号，旧 ID 与原消息保留 |
| ConversationTaskLink | `conversation_id,task_id,source_message_ids,created_by,decision_id,created_at,revoked_at`。历史任务所属会话作初始关系，关联查询支持多对多 |
| Context | `id,type,label,business_object_ids,source_refs,visibility`，用于设备、客户、项目和报告等长期上下文 |
| Run | `id,task_id,origin_conversation_id,status,plan_version,attempt,progress,current_step,version,timestamps`。首版每个 Task 一个主 Run，旧数据使用现有 Task 与事件投影 |
| Artifact / SourceRef | 产物记录 Task、Run、版本、类别、访问范围。引用记录类型、来源 ID、版本、定位及采集时间 |
| Approval | `id,run_id,action_type,target,parameters_hash,requested_by,decided_by,status,expires_at` |
| AssistantMessage / Preference / Memory | 消息记录类型、触发原因、引用、任务、优先级及去重键。个人配置按用户和版本保存。记忆另有来源、用途、可见范围及有效期 |

扩展增量事件携带 `event_id,cursor,type,entity_id,entity_version,occurred_at` 及所需的消息、任务、Run 引用。先提交权威状态和待发布记录，再投递。相同事件 ID 只处理一次；实体旧版本不可覆盖新版本，缺版本补读实体。重连时由快照游标向后补，过期则重新拉取快照并保留本地草稿。保留原 `task_event` 订阅供现有页面使用，临时流式片段保持单独语义。生产查询、引用、通知、向量检索及执行都按服务端认证身份与授权范围过滤。权限撤回后清理相应缓存和预览。

## 6. 异步执行、证据与受控动作

C-Agent 对应现有会话入口和回合控制器，Decision Harness 对应意图、关联和路由的分工，O-Agent 对应现有编排与执行组。S-Agent 为后续结果整合职责，首版从 `TaskRecord.result`、核验和任务事件呈现可用结果。RelOS 提供有权限的知识来源和对象。NexusOps 接入真实业务动作时由服务端网关验证身份、允许范围和动作参数。当前执行和事件存储由相关运行时实现，具备新的持久队列和可恢复检查点后才能承诺进程重启续跑。

Run 扩展状态为 `queued → running → completed/failed/cancelled`，运行中可到 `waiting_input`、`waiting_approval` 或 `paused`，接收有效输入、批准或恢复请求后从检查点继续。入队可取消；运行中暂停或取消在可停边界生效。执行失败时展示原因、已完成步骤及可用重试。普通重试创建新 Run；有外部副作用时先确认旧尝试结果，无法确认则等待人工核对。一个任务的历史 Run 保持可查，迟到事件不得覆盖当前主 Run 的状态。

补充要求存为原会话消息。补齐必需输入时继续当前步骤。改变目标、业务范围或授权对象时生成计划新版本并明确影响。业务写入、外发、高风险操作的确认展示目标、关键参数、影响和来源。决定绑定操作者、动作参数版本和有效期；参数变化、过期或权限撤回必须重新确认。拒绝和超时阻止继续执行，已读动作只改变消息状态。执行网关以审批和动作的幂等键防重复，并核对不明确的回执。

产物面板显示标题、类型、时间、版本和执行来源。报告区分事实、推断和待核实项。证据可查看对象、发生或采集时间、来源类型、权限状态和原文定位。审计按执行分组，普通会话只显示有用的执行摘要。下载、引用和查看原文分别校验访问。大件可手动全屏，关闭后恢复预览位置。SMT-03 至少提供质量运营的可读模拟记录、采集时间及业务对象，首页「查看证据」直达预览。空、加载中、失败和不可访问均有明确状态。

频道双向关联 Task，邀请前显示共享范围。RelOS 区分业务事实、推断、系统观测和报告。组织内省的去重、验真和已有未读读模型可作为来源，主动消息仍需独立判断接收资格。个人会话或私人草稿在明确共享前保持个人范围。

## 7. Personal Agent、设置与主动消息

统一设置包括「我的 AI 助理」「工作与桌面」「通知与主动性」「设备与语音」「隐私与权限」「连接与能力」。搜索返回匹配项和分类，无结果保留查询。保存失败保留编辑。版本冲突显示当前值并允许重新编辑。助理身份表单包含名称、头像、工作定位、沟通原则（Soul）、质量偏好（Taste）、记忆原则和主动性；保存后首页、侧栏和会话同步更新。该个人身份与既有执行器管理、诊断及配置卡分别建模。

记忆界面区分个人记忆、当前工作上下文和组织知识。用户能看来源、纠正、撤回和设有效期。长期偏好通过建议、接受、编辑、拒绝或暂缓生效；单次行为不足以直接覆盖显式偏好。组织策略和动作授权优先于个人风格或主动性。

紧急报警可按组织策略即时呈现，决策和审批优先显示，任务完成和关注建议更新消息及相关卡片，技巧与普通总结合并为摘要。普通消息不抢焦点、滚动或打断语音。主动消息展示原因、来源、关联 Task、优先级和可操作入口，可追问、稍后、忽略、静音或反馈。按用户、业务事件去重；静默时段、订阅、频控和跨端已读实际影响投递。用户未回应不构成授权或同意。普通建议经去重与注意力策略后写入个人会话，模型无需常驻。

## 8. 语音和跨设备

手机端由用户主动开启麦克风，持续显示连接、监听、静音、讲话与播放状态。插话停止播报，保留已确认转写与任务。部分转写用于临时显示，最终或经纠正的文本才进入工作判断。权限不足或连接中断时可沿用会话输入文字。

语音识别为工作时展示任务标题、关联对象和共享范围。低风险明确任务可按授权受理，歧义通过短复述和确认卡纠正。外发、共享、审批和写入沿用动作级确认。录音、转写、私有记忆和共享知识各自授权及保留。两端共享身份、Conversation、Task、Run、产物和未读。恢复上次工作时定位同一消息锚点，布局按设备保存。同步草稿使用版本并保留冲突副本，让用户选择。账户切换与撤权时清理相应缓存。

## 10. 完整前端与逐项验收

产品前端共用真实与模拟数据接入层。同一功能在两种模式下使用相同组件、导航、状态归属、异步流程和结果判据。模拟模式使用隔离数据、固定时钟和可注入故障，可重置并可观察请求、状态和副作用。真实模式禁止静默回退到 Mock。按能力替换时，其他能力继续通过 Mock 提供完整流程。

原始特性清单是回归输入。测试登记须按章节和具体条款关联 Feature ID、Case ID 和证据。已确认的用户行为及验收条款纳入每个里程碑的回归，包括样例之外的入口、异常、恢复、权限、键盘和窄屏。原型的已演示项必须重跑；清单中的开放问题须保留决议记录，涉及交付行为的先定可测口径。没有执行的用例保持未验证。

Feature Map 提供可由 Playwright 执行的操作线路和可判定断言。自动化从仓库真实前端入口运行。Mock 证据证明交互和契约行为；生产授权、持久性、实际副作用与语音质量分别由真实实现和测试证明。每个里程碑同时运行全量前端回归、契约与模块集成、已接入能力的真实服务回归。失败及跳过的必验项阻断交付。
