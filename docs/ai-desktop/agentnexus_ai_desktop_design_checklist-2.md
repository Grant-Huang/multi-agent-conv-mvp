# AgentNexus AI Desktop V1.6 — 设计决策与完整特性清单

> 版本：2026-11-20。依据本轮对话中有关 Slack 式组织协作、统一 AI 入口、S1/S2/S3、Conversation–Task–Context、Desktop Service 和组织内省的讨论整理。标记：**[已演示]** 指 HTML 中可交互模拟；**[待实现]** 指需要真实服务、模型或持久化；**[建议]** 指尚待产品决策。原型数据与 Agent 输出均为模拟。

## 1. 产品定位与边界

- [ ] **[建议]** 定位为组织级 AI 工作桌面，而非“带聊天框的看板”或“多人版个人聊天 Agent”。
- [ ] **[建议]** 个人体验借鉴 Muse 式统一入口，团队保留 Slack 式频道协作，组织依托 RelOS 沉淀上下文，工业业务依托 NexusOps 实现受控闭环。
- [ ] **[建议]** 默认进入 AI Desktop；频道继续存在，但不再是所有工作的必经入口。
- [ ] **[建议]** Channel 负责沟通；Task 负责工作；Business Object 负责业务事实；Agent 负责跨三者协调。
- [ ] **[建议]** 个人 / 协作 / 运营是同一平台的不同工作视图，不应形成互不连通的三个产品。
- [ ] **[建议]** “内服”与“外用”共用协作、任务、知识、授权、审计等基础能力；面向组织和工业场景的深度能力是差异化方向。

## 2. 三种自然工作状态（不是三个 Tab）

### S1 日常 AI Desktop
- [x] **[已演示]** 常驻底部 AI 输入框，可直接问答或委派工作。
- [x] **[已演示]** 简单问答在桌面浮层 Conversation Overlay 中显示，不强制跳转页面。
- [x] **[已演示]** 浮层可关闭、继续追问（再次输入）、手动“展开工作区”或“转为任务”。
- [ ] **[待实现]** 浮层完整多轮连续性、跨设备恢复、未读状态、浮层位置/大小和滚动策略。
- [ ] **[建议]** 简单答案完成后可收起；保留可检索的 Conversation 历史。
- [ ] **[建议]** 长任务或多轮复杂工作可以由系统建议升级为 S2，避免每条消息都跳转。

### S2 分屏工作区
- [x] **[已演示]** 点击桌面任务卡自然进入工作区：左侧任务信息，右侧持续会话。
- [x] **[已演示]** 任务信息含 Task ID、状态、业务对象、关联来源、Agent、上下文策略。
- [x] **[已演示]** 点击任务信息收起按钮进入 S3。
- [ ] **[待实现]** 左侧可切换为文档、图表、业务对象详情、审批表单，而不仅是任务元信息。
- [ ] **[建议]** 工作区从 S1 的轻量会话逐步升级，保持同一会话和任务身份。

### S3 专注工作区
- [x] **[已演示]** 收起左侧任务详情后会话自动占据更多空间；可一键恢复 S2。
- [x] **[已演示]** 右上角产物图标打开抽屉；不使用“会话/执行/产物”三 Tab。
- [x] **[已演示]** 执行时间线嵌入会话内的 O-Agent 执行状态卡；顶部另有执行快捷入口。
- [ ] **[待实现]** 长时任务中的阶段执行、工具日志分组、失败重试、用户介入和可恢复执行。
- [ ] **[建议]** 执行状态默认只显示摘要，点击展开，避免把工具日志变成聊天噪声。
- [ ] **[建议]** 产物抽屉支持预览、版本、下载、引用、权限、关联任务；大文档可进入全屏查看。

## 3. Conversation / Task / Context 数据模型

- [ ] **[待实现]** 每个 Conversation 有独立 `conversation_id`；每条消息有 `turn_id`；可选关联 `task_id`、`context_id`、`business_object_ids`、`execution_id`。
- [ ] **[待实现]** Task ID 自动生成、稳定、可审计，不要求用户手动输入；用户看到自然语言任务标题。
- [ ] **[待实现]** Conversation 与 Task 是多对多关联，不要物理强制合并历史；一个任务可由多个会话贡献，一个会话可产生多个任务。
- [ ] **[待实现]** Context 代表业务对象、项目、客户、设备、主题等长期上下文；不是仅由聊天摘要构成。
- [ ] **[待实现]** 普通知识问答不自动创建 Task；需持续追踪的分析、报告、执行、审批才进入任务生命周期。
- [ ] **[待实现]** Task 状态包括候选、待确认、执行中、等待用户、完成、失败、取消、归档；具体状态机需设计。
- [x] **[已演示]** 根据输入关键词模拟简单问答与任务分流，并显示自动关联的 Task ID。
- [x] **[已演示]** 可手动修改任务标题、业务对象、当前上下文选择。
- [ ] **[待实现]** 更改关联 Task、拆分/合并候选任务、撤销错误关联、记录原判断及修正事件。

## 4. 上下文自动判断与用户控制

- [ ] **[建议]** 默认自动、可见、可纠正：不要求每次手动选择上下文。
- [x] **[已演示]** 输入框附近展示上下文标签；点击可选自动判断、继续当前任务、开始独立话题。
- [ ] **[待实现]** C-Agent + Decision Harness 判定意图、话题连续性、是否创建 Task、候选业务对象、权限和风险。
- [ ] **[待实现]** 当前页面/任务、最近活动、候选任务检索、实体关联、时间信息和用户显式指令共同参与判定。
- [ ] **[建议]** 先用强模型/规则收集分类数据；之后评估 JEV 类轻量分类/路由模型，不预设其准确率。
- [ ] **[待实现]** 记录输入、候选、最终决策、模型版本、人工修正、执行后果；构建有标注测试集。
- [ ] **[待实现]** 测量任务创建准确率、错误关联率、漏关联率、澄清频率、用户纠正率、延迟、成本；校准置信度。
- [ ] **[建议]** 对模糊但低风险的关联先采用可撤销逻辑关联；高风险操作、跨权限、外发、写入时必须明确确认。
- [ ] **[待实现]** 不允许分类模型自行突破身份/租户/频道权限，授权由独立策略执行层判定。

- [ ] **[待实现]** 跨频道授权检索，回答附原始消息/文档/业务数据引用与时间戳。
- [ ] **[待实现]** 用户从个人桌面启动任务，在频道邀请协作者，回桌面继续跟踪，Task ID 不变。
- [ ] **[建议]** 临时协作会话按需创建，完成归档；不要每个 Task 都新建永久频道。
- [ ] **[待实现]** 频道与任务双向链接；可查看每条结论来自哪个频道/系统/人/Agent。
- [ ] **[待实现]** 原始会话、任务事实、AI 摘要、RelOS 知识分层保存；摘要可重建，证据不可由模型随意改写。
- [ ] **[待实现]** 组织级数据保留、访问控制、删除与合规策略。

## 8. C-Agent / O-Agent / S-Agent / RelOS / NexusOps

- [ ] **[待实现]** C-Agent 负责每轮交互、会话连续性、轻问答、意图识别和任务上下文展示。
- [ ] **[待实现]** Decision Harness 负责上下文关联与路由规则；权限和执行策略需独立强制执行。
- [ ] **[待实现]** O-Agent 负责复杂任务规划、编排、执行、恢复和状态反馈。
- [ ] **[待实现]** S-Agent 按需整合复杂结果、证据、报告和交付产物。
- [ ] **[待实现]** RelOS 关联业务对象、组织知识、历史事件和来源；区分推断、报告、系统观测与已验证事实。
- [ ] **[待实现]** NexusOps 连接 MES/QMS/ERP/设备和操作服务，写回遵守任务级授权与动作级网关控制。
- [ ] **[待实现]** 组织内省发现跨频道重复问题、需求、Bug、经验和趋势；去重、验真、形成建议或任务。
- [ ] **[建议]** Desktop Service 是确定性业务服务，而非每次渲染都调用大模型的 Agent。

## 9. 关键风控与设计约束

- [ ] **[待实现]** 租户隔离、用户身份、频道 ACL、业务对象权限、工具最小权限。
- [ ] **[待实现]** 跨频道总结不能泄露未授权消息；授权在检索、生成、卡片展示、执行每一阶段都有效。
- [ ] **[待实现]** 外发、审批、业务写入及不可逆操作需明确授权，且操作记录可审计。
- [ ] **[待实现]** 任务状态与模型输出分离；LLM 无权直接改写权威业务事实。
- [ ] **[待实现]** 关联错误可回退，保留更正前后的来源和判断依据。
- [ ] **[待实现]** 任务执行的幂等性、重试、超时、取消、补偿与回滚。

## 10. 分阶段实施建议

**P1：交互与基础数据**：S1/S2/S3、浮层、工作区、Conversation/Task/Context 模型、手动纠错、基础历史。  
**P2：智能路由**：C-Agent + Decision Harness、候选任务检索、真实权限感知检索、分类日志和评测。  
**P3：事件驱动桌面**：Desktop Service、任务事件、SSE/WebSocket、局部更新、卡片排序与用户偏好。  
**P4：组织内省与工业闭环**：RelOS 关系沉淀、跨频道洞察、NexusOps 受控执行、主动决策卡。

## 11. 仍需产品评审的开放问题

1. S1 快速会话是否在用户离开页面后保留为可恢复的 mini-conversation？建议保留。
2. 自动创建 Task 的阈值如何定义？建议“可持续追踪目标”而非“所有工具调用”。
3. Task 与 Conversation 的多对多关系在 UI 上如何展示？建议默认简化，详情中可查看关联图。
4. S2 左侧除了任务元信息，是否支持切换业务对象/文件预览？建议支持。
5. S3 的执行轨迹是否支持多个 Run 并排对比？建议后续版本实现。
6. 产物是否拥有独立版本与审批生命周期？建议是。
7. 推荐卡片是否允许 AI 自动新增分区？建议首版不允许。
8. 组织内省提出的建议何时转为正式任务？建议用户确认或符合预先授权的规则后创建。
9. 如何区分“我的私有 AI 会话”和“频道可见的共享任务”？需要明确可见性与分享动作。
10. 如何防止桌面通知过载？建议聚合、阈值、频率预算和用户反馈闭环。

## 12. 原型操作指南

- 首页底部输入“什么是 OEE？”：显示 S1 轻量会话浮层。
- 浮层点击“展开工作区”：进入 S2；也可点击“转为任务”。
- 首页输入“分析 SMT-03 良率异常”：模拟 AI 自动识别并关联 Task，进入 S2。
- S2 左侧点击收起按钮，或顶部任务详情图标：进入/退出 S3 专注模式。
- 工作区右上角“▤”：打开产物抽屉；“⌁ 执行”：展开执行时间线。
- 输入框的上下文标签：手动改为自动识别、继续当前任务或独立话题。
- 任务信息中的“修改任务 / 上下文”：修改 AI 提取的任务标题和业务对象。
- 顶部“↻”：模拟事件推送，展示局部更新。
- 右上角设置：查看个性化布局约束示例。

## 14. 本次确认新增：个人专属 AI Agent 身份与配置（2026-11-20）

- [x] **[原型已演示]** S1 首页突出个人专属 AI 助理：独立身份视觉、名字、问候、工作伙伴定位及配置入口；不把 AI 桌面变成数字人占屏的聊天产品。
- [x] **[原型已演示]** 左侧导航提供常驻个人 Agent 身份入口；点击打开统一配置面板。
- [x] **[原型已演示]** 可编辑 Identity（名称、头像符号、工作定位）、Soul（交流原则）、Taste（质量标准）、Memory（记忆原则）和 Autonomy（主动性）。演示修改即时反映在首页、侧栏与会话标签；页面刷新后不持久化。
- [x] **[原型已演示]** 个人记忆与偏好查看入口，区分个人长期记忆、工作上下文、RelOS 组织知识（示意信息，未连接记忆服务）。
- [ ] **[待实现]** 配置持久化、版本记录、变更回退；Soul/Taste 不直接作为无约束系统 Prompt 拼接。
- [ ] **[待实现]** Personal Agent 作为持久用户身份与配置层，底层复用 C-Agent、Decision Harness、O-Agent、S-Agent 和业务 Agent，而不是重复建设独立执行栈。
- [ ] **[待实现]** 用户可管理真实记忆条目、来源、纠错、删除/保留策略；明确私有信息和组织共享信息的边界。
- [ ] **[待实现]** 组织级 Policy 优先于个人 Soul/Taste/Autonomy；技能与执行授权不能通过个人配置提升。
- [ ] **[建议]** 数字人形象可选，先以身份连续性、工作风格、记忆与语音自然度建立个性化体验。

## 15. 本次确认列入后续设计：手机语音、跨设备连续性、语音任务确认

以下三项**已纳入设计特性清单，但本次不在 HTML 原型中实现**。

### 15.1 手机端实时全双工语音
- [ ] **[确认纳入 / 待实现]** 手机端一键进入专属 Personal Agent 实时语音界面，支持边听边说、自然插话、语音播报中断与恢复、实时转写、中英文混合和噪声环境。
- [ ] **[待实现]** 语音通道可插拔：评测原生实时语音模型与 ASR→LLM→TTS 流水线，保持与桌面共用的 C/O/S-Agent 任务系统。
- [ ] **[待实现]** 明确录音/会话状态、权限与用户主动开启；不默认全天候监听。
- [ ] **[待实现]** 评测首响应延迟、插话停止延迟、误打断率、语音任务识别准确率和持续会话稳定性。

### 15.2 跨设备会话与任务连续性
- [ ] **[确认纳入 / 待实现]** 手机、桌面共享身份、Conversation ID、Task ID、Context/业务对象关联、历史与执行状态；手机语音交代任务后可在桌面 S1/S2/S3 无缝继续。
- [ ] **[待实现]** 语音会话结束形成可查看的转写/摘要（依据用户授权和保留策略），可回到相关任务；同步任务状态与产物，而不是复制两套执行体系。
- [ ] **[待实现]** 跨设备冲突、离线恢复、隐私保护与权限变化后的访问控制。

### 15.3 语音自动识别 Task 与确认交互
- [ ] **[确认纳入 / 待实现]** 语音输入经 C-Agent + Decision Harness 判断：普通聊天、继续已有 Task、新建 Task 候选、个人记忆候选或组织知识候选。
- [ ] **[待实现]** 默认自动识别并显示可见上下文标签；用户可纠正任务标题、业务对象、关联任务和共享范围，避免每句话都弹确认。

## 16. 本次确认新增：异步会话与后台任务连续性（2026-11-20）

- [ ] 用户发出长任务后，C-Agent 立即确认已接收并返回任务引用；O-Agent/业务 Agent 在后台异步执行，个人 Agent 仍可继续响应新消息。

- [ ] 会话历史按事件时间线显示用户消息、Agent 回复、后台任务状态、主动消息；执行日志可折叠，不将所有工具日志直接塞入聊天正文。

- [ ] 用户对执行中任务补充指令时，明确区分“追加约束”“调整计划”“取消并重启”；关键修改通过 O-Agent 重新规划并记录版本，避免悄悄覆盖已运行步骤。

## 17. 本次确认新增：可成长的个人工作伙伴与克制的主动会话（2026-11-20）

**设计决策：Personal Agent 是可持续学习、可主动发起消息的长期工作伙伴，但主动性必须有明确触发条件、注意力预算和用户控制。** 以下均为 **[确认纳入 / 待实现]**。

### 17.1 主动消息的场景与交互
- [ ] 个人 Agent 可以在**个人助理会话中独立发起新消息**，不要求用户先发送一轮；区别于只在桌面看板新增卡片。
- [ ] 支持消息类型：`alert`（报警/重大风险）、`attention`（建议关注）、`tip`（工作技巧/提示）、`summary`（日/周/项目总结）、`task_update`（任务进展/完成）、`decision_request`（需要决策或审批）、`memory_suggestion`（偏好/记忆更新建议）。
- [ ] 每条主动消息标记触发原因、来源/证据、关联 Task/业务对象、优先级和建议动作；用户可追问、转 Task、暂缓、忽略、静音此类提醒或反馈无关。
- [ ] S1 个人 Agent 区域显示有价值的最新主动消息和未读数；S1 浮层或 S2/S3 会话可直接查看与回复；手机端按优先级推送，避免重复跨端轰炸。
- [ ] 对同一事件进行跨频道/跨任务去重与聚合；报警升级、普通建议合并、低价值 Tips 定期汇总。
- [ ] 主动消息不等于自动对外行动：个人会话中的建议不能未经授权自动发布到组织频道、修改业务系统或创建共享知识事实。

### 17.2 克制的主动性（Attention Policy）
- [ ] 分级策略：P0 紧急报警可即时打断（遵循安全及组织策略）；P1 需要决策优先显示；P2 关注建议在合适时机提示；P3 Tips/普通总结进入摘要或等待用户空闲。
- [ ] 支持静默时段、工作时间、免打扰、按类别订阅、频率上限、批量摘要、稍后提醒；组织强制告警策略与个人偏好分开管理。
- [ ] 用户正在语音讲话、专注输入或会议中时，除允许打断的高优先级事件外不主动插话；低优先级消息排队，语音模式可只显示文字提示。
- [ ] 避免“为了显得聪明而发消息”：主动消息需有可解释的触发依据、明确行动价值和质量阈值；同类建议反复被忽略后降低频率。
- [ ] 每条建议可反馈“有用 / 不相关 / 太频繁 / 不要再提醒”，并记录偏好；不得将用户未回应误判为赞同。

### 17.3 逐渐了解用户的成长机制
- [ ] Soul/Identity 相对稳定，由用户明确控制；Taste（判断与验收偏好）、工作节奏和关注主题可从长期互动中生成**候选**更新，不静默覆盖核心配置。
- [ ] 个人 Agent 在恰当的会话节点克制地建议：例如“我发现你多次要求技术方案包含风险与替代方案，是否设为默认工作标准？”用户可接受、编辑、拒绝或稍后处理。
- [ ] 区分显式设置、行为推断、短期工作上下文、长期记忆和组织事实；候选记忆需标注来源、时间、置信度/证据、可见范围与有效期。
- [ ] 支持个人记忆浏览、纠正、撤回、过期和变更历史；避免由单次对话过度推断长期偏好。
- [ ] 学习“何时不打扰”也是成长的一部分：根据用户对建议的反馈优化内容相关性和触达时机，而不是仅增加主动消息数量。
- [ ] 个人记忆不得自动提升组织权限；私有会话内容不能未经授权进入共享 RelOS 或跨用户推荐。

### 17.4 架构分工与验收
- [ ] 事件源（Task、RelOS、NexusOps、内省、定时摘要）产生候选提醒 → 规则/权限/去重/注意力策略 → C-Agent 生成合适表达 → 以 `assistant` 发起的主动消息写入个人 Conversation → Desktop/手机推送。
- [ ] O-Agent/业务 Agent 负责后台执行；C-Agent 保持可用、决定何时汇报；S-Agent 按需形成高质量总结。主动消息投递必须有可追踪的 `event_id`，不要求模型始终在线等待。
- [ ] 验收 A：设备严重异常 → 个人会话出现带来源的报警消息 → 用户追问 → 关联业务 Task，且权限正确。
- [ ] 验收 B：低优先级重复 Tips → 合并为摘要，不打断当前工作；用户设为“不再提醒”后停止同类建议。
- [ ] 验收 C：多次用户反馈某种输出偏好 → Agent 在合适时机询问是否写入 Taste → 用户确认后后续输出体现该偏好，且可撤回。
- [ ] 验收 D：后台任务完成时用户不在线 → 个人会话保留主动结果消息 → 手机/桌面恢复后看到同一消息与 Task 链接，不重复通知。

**原型状态：** 本次只更新设计确认清单；现有 HTML V1.1 未实现上述异步运行与主动消息交互，后续原型迭代应新增演示。
