# AgentNexus AI Desktop V1.7 目标 Feature Map

本索引用于 [完整前端实施计划](PLAN.md)。各路径从 A 起通过实际产品前端操作，后端可使用记录在计划中的 Mock。从 B 起，已替换能力另外以真实服务验证。下面的 ID 为待登记的用例；运行证据由仓库覆盖文档记录。HTML 原型仅作视觉与交互参照。

## 执行约定

沿用 `web/e2e/harness.mjs` 和 Playwright。每例使用新浏览器上下文及隔离种子。使用区域、按钮、对话框、文本框的可访问角色和名称定位。以可观察状态和网络事件等待，不用固定休眠。运行同一套页面操作于全 Mock 和混合模式；集成测试启动服务边界，检查实际 HTTP、SSE、存储和可控副作用。用例登记到 `docs/testing/CASES.md` 与 `features.json`，证据在 `docs/feature-map/COVERAGE.md` 记录。

基准种子包含 SMT-03 `TASK-2026-018`、产品改进、独立会话、质量频道、证据记录、两种角色和模拟移动端。故障种子包括等待、拒绝、过期、撤权、断线和重复事件。每个 Feature 对应至少一个 Playwright 用例；服务专有行为另有 HTTP/运行时断言。

| Feature / 用例 | 操作路径 | 必须观察到的结果 |
|---|---|---|
| AD-NAV / E2E-AD-NAV | 首页卡、侧栏、历史、质量频道逐一打开 SMT-03。返回各自入口。访问 RelOS 和运营抽屉 | 同一个 Task ID，源焦点、位置和筛选恢复；可见入口可操作或有明确受限状态 |
| AD-LAYOUT / E2E-AD-LAYOUT | S1 打开调查，展开执行、滚到旧消息，S2→S3→S2；关闭并重开，窄屏往返 | 任务、会话、锚点和执行展开保持，桌面布局可恢复 |
| AD-DRAFT / E2E-AD-DRAFT | 两项任务分别写草稿。延迟 SMT-03 发送响应并切走，返回继续写 | 草稿隔离，实际请求和保存记录落在原任务，迟到反馈不覆盖新输入 |
| AD-SCOPE / E2E-AD-SCOPE | 上下文菜单切换自动、继续和独立，转为任务，再纠正关联 | 普通问答无新 Task；显式作用域生效；原消息及修正记录可追溯 |
| AD-HISTORY / E2E-AD-HISTORY | 按对象、标题、时间查询会话及任务，打开后返回；固定、隐藏、关注卡片 | 历史筛选恢复；推荐理由可见；偏好实际改变排序或可见性 |
| AD-EVIDENCE / E2E-AD-EVIDENCE | 首页「查看证据」，读预览、来源，逐层退出；空、失败和过期夹具各复跑 | 来源、时间、版本及任务匹配；错误可解释，返回原现场 |
| AD-S1 / E2E-AD-S1 | S1 先问答，后交代复杂任务。后台工作时继续会话，手动展开任务 | 不强制导航；提交中与受理有区别；同一任务在卡片、会话和执行中一致 |
| AD-PROFILE / E2E-AD-PROFILE | 从正在编辑的任务打开助理设置，改身份、保存、查看记忆、关闭；注入保存冲突 | 一处编辑，内容同步，记忆详情回到原分类，草稿和焦点保留；冲突不覆盖草稿 |
| AD-INPUT / E2E-AD-INPUT | 在 360、768、1024、1440 CSS px 使用键盘遍历、Escape、中文选词、缩放布局 | 控件可达，焦点回到触发处，选词不发请求，遵循减少动态效果 |
| AD-ACCEPT / E2E-AD-ACCEPT、RT-AD-ACCEPT | 丢弃受理回执，检查 UI 待确认状态及查询，再按契约重试 | 现有模式先回读；可靠模式相同操作仅一次受理及派发，不同内容返回冲突 |
| AD-RESUME / E2E-AD-RESUME、RT-AD-REPLAY | 并行两个任务，运行、等待输入、取消或重试；断线、重复事件、游标过期、重启 | 前端状态不串、不倒退；真实替换后同一 Run 从检查点继续。任务卡与产物对账 |
| AD-SOURCES / E2E-AD-SOURCES | 两角色从频道和对象打开任务，读证据后撤权，再从搜索、摘要、通知与原文件访问 | 撤权后所有入口一致，缓存移除。拒绝不影响其他有权工作 |
| AD-APPROVE / E2E-AD-APPROVE、RT-AD-APPROVE | 审批后改参数；分别验证拒绝、超时、结果未知和重复执行请求 | 原审批失效；拒绝不执行；结果未知先查证；有效动作副作用只发生一次 |
| AD-ATTENTION / E2E-AD-ATTENTION | 正在输入时送普通建议、聚合消息和紧急事件，暂缓并静音；接受或撤回记忆建议 | 普通事件不抢焦点，静音改变实际投递，告警规则生效，偏好变更可追踪 |
| AD-VOICE / E2E-AD-VOICE | 开启麦克风、插话、实时转写、纠正归属，断线切文字；另测拒绝麦克风权限 | 播报可停止，部分转写不执行，确认后关联正确，可继续同一会话 |
| AD-HANDOFF / E2E-AD-HANDOFF | 手机发起工作，桌面打开并续写；两端各编辑草稿，再处理冲突 | 同一 Task/Run 与读取位置，草稿冲突可选，未授权转写不共享 |

## 清单追溯入口

按 [V1.6 原始清单](agentnexus_ai_desktop_design_checklist-2.md)编号组织。开发前将章节内每条适用要求拆到可断言的 Case ID 并补齐本索引下的用例登记。必须区分模拟与真实证据。

| 原始章节 | 对应 Feature 或检查 |
|---|---|
| 1 产品定位、2 工作状态 | AD-NAV、AD-LAYOUT、AD-S1 |
| 3 数据、4 上下文 | AD-DRAFT、AD-SCOPE、AD-ACCEPT |
| 5 历史和协作、6 内容和布局 | AD-HISTORY、AD-SOURCES、AD-NAV、AD-INPUT |
| 7 刷新与推送、8 服务分工、9 风控 | AD-RESUME、AD-ATTENTION、AD-EVIDENCE、AD-SOURCES、AD-APPROVE；契约和运行时断言 |
| 10 分阶段、11 开放问题、12 操作指南、13 参考 | 里程碑记录、决议记录、操作指南逐路径回归；参考项记录适用性 |
| 14 助理配置、15 语音与跨端 | AD-PROFILE、AD-VOICE、AD-HANDOFF |
| 16 异步会话、17 主动和成长、18 设置 | AD-S1、AD-ACCEPT、AD-RESUME、AD-ATTENTION、AD-PROFILE |
| 19 连续性、20 导航、21 回归修复 | AD-NAV、AD-LAYOUT、AD-DRAFT、AD-EVIDENCE、AD-INPUT 及所有可见入口遍历 |

每次发布输出逐条清单结果，记录到具体条款、对应断言、运行模式和证据。手工点击和截图可用于补充视觉证据。测试必须自动判定 URL 或视图、实体归属、可见状态、焦点、数据变化与预期副作用。UI 可点击但无结果、产生不可解释的层级跳转或使草稿丢失，均为失败。
