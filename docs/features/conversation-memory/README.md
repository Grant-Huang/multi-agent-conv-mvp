## 1. 意图

让用户在继续会话时少重复背景，同时能知道助手参考了什么、信息从哪里来、如何修改或撤回。从历史自动形成的个人记忆、画像和组织规则只是提议，经相应的人确认后才生效；每次回答都能说明用了哪些记忆；记忆与检索内容只是带来源的资料，其中指令无效（CH-G1、CH-G5）。业务内省为这条线提供带证据的发现，具体主题和发布闸门继续由[业务内省方案](../../memory/INTROSPECTION_PLAN.md)定义。组织业务事实仍以 RelOS、MOM 和对应源系统为准。

## 3. 设计

3.1～3.7 为 2026-11-26 用户确认的设计层规则（[2026-11-26-memory-layers-and-history](../../decisions/2026-11-26-memory-layers-and-history.md)），表格与数值可在实现切片中按决策流程调整；宪章只锁定 CH-G1、CH-G5，不锁这些表（[宪章 v1.6](../../decisions/2026-11-26-charter-v1-6-memory.md)）。3.8 为既有实现基线。第 5 线负责上下文选材和记忆生命周期，第 1 线负责用户看到的来源、预览和编辑入口，第 4 线负责会话调用和任务交接语义，第 3 线负责工业来源及其核验，第 2 线负责注入与隔离复验。

### 3.1 分层模型（L0～L5）

| 层 | 内容 | 谁写入 | 生命周期 | 默认进上下文 |
|---|---|---|---|---|
| L0 工作现场 | 本轮、当前任务草稿、打开的证据、执行中的步骤 | 系统 | 随任务 | 总是 |
| L1 会话摘要 | 本会话谈过什么、定了什么，带来源 | 系统生成，可纠正 | 随会话 | 续问时 |
| L2 历史记录 | 全部历史消息、任务、审批、回执 | 系统原样保存，不改写 | 按保留规则 | 不默认带，按需检索 |
| L3 个人长期记忆 | 事实、偏好、风格 | 本人确认后生效 | 至撤回或过期 | 按相关度 |
| L4 组织知识与判断标准 | 已发布知识、制度、taste | 有权限者发布，带版本 | 按版本 | 按授权与相关度（REQ-03，移交第 4 线） |
| L5 内省发现 | 业务数据分析出的模式 | 内省产生，待核实 | 核实后可能晋升，不自动晋升 | 相关提问中按需引用并标「待核实」（REQ-04） |

### 3.2 哪些从历史沉淀、何时生效

- L1 会话摘要：自动生成，只在本会话使用，可纠正。
- L3 事实、偏好、风格与画像：可从历史抽取或归纳，**只作提议**，本人确认后生效（CH-G1）；单次行为不覆盖显式偏好；画像只当假设、只服务本人。
- 设置里的沟通原则 / 质量偏好：视作已确认风格进风格卡（保存即确认、全会话生效；默认值视作未设置）。**边界**：个人质量偏好是个人风格（CH-G2 个人层）；组织判断标准（taste）属组织，只经发布流程带版本管理，不经个人设置注入。
- L4：**不从聊天沉淀**，只能经发布流程；聊天中的好做法只作为建议提交负责人。
- L5：来自业务数据，不来自聊天。

### 3.3 按场合选材（程序判断场合，不交给模型猜）

| 场合 | 必带 | 可带 | 不带 |
|---|---|---|---|
| 随口问答（首页 S1、新会话） | L0 | L3 偏好风格、相关 L4 | 他任务现场、L5 |
| 回到老任务 | 该任务 L0、L1、上次停留位置 | 相关 L2 片段 | 其他任务 |
| 执行、委派 | 目标、约束、相关 L4 制度 | L3 事实 | 风格偏好、L5 |
| 审批、业务写入 | 方案原文、版本、影响、来源、相关制度 | 同类历史审批（L2） | 画像与风格不影响内容（CH-G2b）；L5 只作提示 |
| 运营值班、提醒 | 当前异常、相关案例 | 已核实的 L5 | 个人闲聊记忆 |
| 跨设备续接 | 上一设备的 L0 | — | — |

时间规则：同等相关时近期优先；L3 事实有效期过后不带；回到任务、审批到点、异常发生时按事件调入，不常驻；工作时段外不主动推内省（用户可调）。每轮记录并可展示「带了哪些记忆、为什么」（CH-G1、G3）。

### 3.4 克制的内省

门槛不够不发（沿用阈值 4、样本门槛 10）；每天上限 1 条，计入注意力预算，输入中不弹；只在相关提问或值班时出现；永远标推断与证据、样本量；核实前不晋升；不推断情绪、健康、能力、绩效（CH-G2d）；可静音、可反馈，反馈只积累不自动改规则；每次推送的依据与用户反应留痕（CH-G3）。初值先试运行，再按标注数据调整。

### 3.5 历史消息检索（L2）

| 规则 | 内容 |
|---|---|
| 范围 | 先只检索本人参与的会话与任务；频道、共享会话待服务端身份可验证后按授权接入（与 REQ-03 一起） |
| 保留 | 原始记录默认长期保留；检索默认只看最近 180 天，更早需明确指定 |
| 分级 | 用户消息、系统事件、审批、回执是「记录事实」；AI 历史回答一律标「当时的回答」，不作事实来源（CH-G5）；被纠正或撤回的带标记，优先给纠正后版本 |
| 引用 | 必须带时间与出处 |
| 删除 | 个人会话中本人删除的消息真删除；任务、审批相关记录保留原件供审计，但不再进入检索与引用 |

### 3.6 用户能编辑什么

| 内容 | 本人可以 | 不可以 |
|---|---|---|
| L3 事实、偏好、风格 | 查看、修改、撤回、设有效期 | — |
| 画像 | 查看、纠正、删除 | 管理员默认不可看 |
| L1 会话摘要 | 纠正（纠正单独记录，原消息不变） | — |
| L2 历史消息 | 删除或隐藏自己的消息；加「更正」注记 | 改写原文 |
| 审批、回执、系统事件 | 查看 | 任何人不可改 |
| L4 | 提异议、反馈 | 仅有权限者经发布流程、带版本修改 |
| L5 | 标有用 / 没用 / 有错 | 改结论（核实由负责人） |

### 3.7 注入八道防线

1. 资料块封装：记忆与检索结果以带来源、类型的资料块交给模型，资料内指令无效（CH-G5）。
2. 权限与动作只由程序判断，资料内容无法改变（CH-P1、P7）。
3. 写入闸门：只有本人确认的内容写入个人记忆；外部文档、工具输出、他人消息不能直接写入，只能成为待确认候选；写入时扫描可疑指令与敏感信息。
4. 隔离：个人记忆按人隔离；共享层按授权读取；频道消息不写入任何人的个人记忆。
5. AI 回答不回流为事实。
6. 可追溯与一键撤回，并能查出被污染记忆影响过哪些回答（CH-G3）。
7. 资料块长度与总预算上限，防止挤占。
8. 注入测试集：历史消息、文档、频道夹带指令时，验证指令不生效、权限不变、记忆不被写入（扩展现有 CASES「资料中包含指令时的处理」）。

### 3.8 既有实现基线与候选流程

候选流程为「固定本轮会话、操作者和任务范围 → 读取获授权的候选资料 → 校验来源、版本和有效性 → 按预算选取 → 作为有来源的数据交给模型」。已在回答路径落地（5.1），并按判断、路由、执行路径分别提供最小材料（S4 / S5-route / S6-exec）。复用现有模型上下文预算，确保补充材料挤不掉当前请求和必需指令。检索超时或证据不足时继续处理当前轮，并保留可查的原因。日志记录来源引用和筛选原因，避免记录私密正文（事件 `session.materials` 记 `selected` / `memories` / `style` / `skipped` 与原因；「为什么带了」的展示扩展随 REQ-06 切片登记）。

共享权限与撤权沿用[身份与审批 A7](../../contracts/identity-and-approval.md)；事件追踪沿用[事件与追踪](../../contracts/events-and-trace.md)。上下文中的文本按资料处理，业务授权继续由既有策略和审批决定。含私密资料的外部模型调用沿用现有外发边界，接入前验证相关出口。
