## 1. 意图

让用户在继续会话时少重复背景，同时能知道助手参考了什么、信息从哪里来、如何修改或撤回。业务内省为这条线提供带证据的发现，具体主题和发布闸门继续由[业务内省方案](../../memory/INTROSPECTION_PLAN.md)定义。组织业务事实仍以 RelOS、MOM 和对应源系统为准。

## 3. 设计

以下为候选设计。第 5 线负责上下文选材和记忆生命周期，第 1 线负责用户看到的来源、预览和编辑入口。第 4 线负责会话调用和任务交接语义，第 3 线负责工业来源及其核验。首个实现切片在受控环境使用会话内资料，可与真实首页委派并行推进。

| 信息范围 | 来源和归属 | 模型如何使用 |
|---|---|---|
| 当前回合、会话与任务 | 消息、带来源的摘要、明确绑定的任务资料 | 当前请求优先，按会话和任务范围选材 |
| 个人长期记忆 | 用户保存的资料、个人偏好与风格、待确认的画像 | 按用户作用域检索，编辑与生效沿用历史决定 45–47 |
| 团队与组织 | 已授权频道或业务对象、已发布知识、组织判断标准（taste） | 按授权和版本检索，组织判断标准沿用原有评审门槛 |
| 业务内省 | 可追溯的分析发现及核实状态 | 按需引用，区分观测、推断和业务事实 |

候选流程为「固定本轮会话、操作者和任务范围 → 读取获授权的候选资料 → 校验来源、版本和有效性 → 按预算选取 → 作为有来源的数据交给模型」。先在回答路径验证，再分别为对话判断、路由和执行设计所需的最小材料。复用现有模型上下文预算，确保补充材料挤不掉当前请求和必需指令。检索超时或证据不足时继续处理当前轮，并保留可查的原因。日志记录来源引用和筛选原因，避免记录私密正文。

共享权限与撤权沿用[身份与审批 A7](../../contracts/identity-and-approval.md)；事件追踪沿用[事件与追踪](../../contracts/events-and-trace.md)。上下文中的文本按资料处理，业务授权继续由既有策略和审批决定。含私密资料的外部模型调用沿用现有外发边界，接入前验证相关出口。

## 4. 实现入口

当前基线的近期消息读取与任务背景拼装位于 `crates/runtime/src/conversation.rs`，预算位于 `crates/llm/src/budget.rs`，业务内省位于 `crates/runtime/src/introspect/`。桌面已有 [T-71 记忆列表与详情](../../testing/evidence/ai-desktop-t71-memory-list.md)及 [T-72 纠错与撤回](../../testing/evidence/ai-desktop-t72-memory-write.md)，均使用进程内服务夹具。分层检索、生命周期及会话注入尚待实现。

5.1 首个切片（2026-11-23 开工）：回答路径会话资料注入，实现在 `crates/runtime/src/session_materials.rs`（候选收集、校验、预算内渲染、降级），`conversation.rs` 挂接；`store.rs` 新增只读按会话链接查询。资料源接口可注入，供超时/错误降级测试。
