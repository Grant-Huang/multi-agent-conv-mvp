# 阶段 2：合并前 AI 审查（影子模式）

## 目标

开发与审查分离。合并前自动留审查痕迹，**先不阻断合并**；积累 2～4 周后与人工结论对比误报率，再决定是否升级为必需检查。

## 实现

工作流：`.github/workflows/pr-shadow-review.yml`

触发：`pull_request`（opened / synchronize / reopened / ready_for_review）

行为：

1. 运行 `tools/ci/risk_classify.py`，得到 L0–L3。
2. 在 PR 上发布（或更新）一条影子审查评论，包含：
   - 风险等级与审批要求
   - 对照 `REVIEW.md` 的检查清单（范围、证据、高风险文件、测试弱化）
   - 明确写：**影子模式，不阻断合并**
3. 不修改代码、不批准、不合并。

## 何时升级为阻断

- 误报率可接受（团队约定，建议连续两周无「整条评论作废」级误报）
- 分支保护与 bot 身份已就绪（见 BOT_IDENTITY.md）
- 再把该 job 设为必需检查，或要求「影子审查结论为 pass」标签

## 与夜间评审的关系

| 机制 | 时机 | 作用 |
|---|---|---|
| 影子审查 | 合并前 | 提醒；不阻断 |
| 夜间评审（REVIEW.md） | 合并后 | 找问题、台账、预审修复 PR |

二者互补：影子审查不能替代夜间评审的独立验证。
