# R-20261117-M1 / L1 修复证据（DES 开发分支）

来源：[2026-11-17 代码审查](../../review/2026-11-17.md)。用户要求在 DES 开发分支 `claude/relaxed-fermi-u38fye` 上修复这两条。
已有的修复 PR #84（M1）与 #85（L1）基于阶段③合并之前的 master，现在与 master 冲突；而且 #84 的缓存不感知阶段③新增的仿真干预和"执行后继续推演"。本次把两者的测试和思路移植过来，并按阶段③调整；#85 的测试原样移植，断言未改。

## 改动
- `des/engine_link.rs`：`DesReplay` 增加不序列化的遥测缓存（状态克隆之间共享），键为"已记录干预数 + 推演到的时刻"。创建时与执行回调时直接放入刚推演的结果；干预增加时失效；场景结束后需要延伸时一次多推演 720 分钟。时钟刷新、工厂视图、预测、what-if 共用缓存。
- `des/scenario.rs`：拒绝抽样累计预算 100,000 设备·分钟（移植自 #85）；单元测试用的重新推演计数器（移植自 #84，计数点改为阶段③的 `rerun`）。
- `server/src/mom_sim.rs`：所有 DES 接口（含阶段④的审核接口）在 `spawn_blocking` 中执行（移植自 #85）。

## 对移植测试的调整
- RT-DES-22：`observe::observe` 在阶段③多了干预和备件两个参数，调用处补 `&[]`、`false`；期望遥测改用 `rerun(..., &[], 0)`。断言本身不变。
- RT-DES-23：#84 原断言"重放输入只有 3 个持久字段"，其意图是"遥测不持久化"。阶段③之后持久字段是 5 个（新增干预、备件丢失），所以改为直接断言"没有遥测或缓存字段"。其余断言不变。
- 新增 RT-DES-22b：覆盖阶段③特有的路径，即执行干预后、以及场景结束后的推进不逐分钟重放。
