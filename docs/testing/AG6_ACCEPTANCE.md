# AG.6 端到端验收清单（在用户本机用真实助手执行）

日期：2026-11-17。目的：在真实环境里走通 AG 设计里的 J1–J8 流程。自动化浏览器用例（`web/e2e/agents.spec.ts`）用的是模拟助手，证明的是流程；这里证明的是**真实助手**也能用。

## 准备

- 最新分支：`git pull origin claude/serene-cerf-lpx1bs`，然后 `CARGO_TARGET_DIR=target cargo build --release` 和 `cd web && npm run build`。
- 记录本机环境：`uname -a`、`node --version`，以及要验收的助手各自的版本（例如 `claude --version`、`agent --version`）。
- 备份：`data/agents.managed.toml`（如果有）。验收中的修改都可以用"撤销"或删除这个文件恢复。
- 要验证 J1 的"首次打开"，请用新的浏览器窗口（或清除本站点的本地存储）。
- 对话里管理助手（J1、J4、J5 的对话方式）需要 `[conversation] agent_management = true`；**AG.4 评测达标前，只在验收时临时打开**，验收后改回。

## 每一项记录什么

结论（通过 / 不通过 / 跳过及原因）、截图、关键接口输出（`GET /api/agents/catalog`、`GET /api/agents/config`），以及不通过时的 `logs/agentnexus.jsonl.<日期>` 相关片段（按 `event` 过滤 `agent.*`）。

## 清单

| 编号 | 场景 | 操作 | 通过标准 |
|---|---|---|---|
| J1 | 已安装的助手 | 新窗口打开 → 发现卡；或在对话里说"有哪些助手可以用" → 点"接入" → 确认 | 从开口到可用不超过 2 次点击；结果卡"已连通"；之后让它做一个小的写代码任务，任务卡上的执行者是它 |
| J2 | 想用但没安装 | 选一个没装的助手（例如 ZCode），点"看安装步骤" → 按步骤安装 → "我装好了，重新检测" | 安装步骤能直接复制使用；装好后检测结果变为已连通或给出明确的下一步 |
| J3 | 检测失败 | 制造一个失败：例如退出某个助手的登录，或临时改坏它的命令 → 重新检测 | 结果卡给出分类原因（需要登录 / 缺依赖 / 连接失败 / 超时）和下一步，用词是大白话 |
| J4 | 设为默认 | 「助手」页签点"设为默认"，或对话里说"以后写代码交给 X" → 确认 | 确认卡写明原来是谁、以后是谁；之后新的写代码任务交给 X |
| J5 | 停用 | 停用一个助手 → 确认 | 正在做的任务照常做完；之后不再分给它；若是最后一个写代码的助手，确认卡有警告，之后让它改代码时对话用大白话回复 |
| J6 | 撤销 | 在结果卡或页签上点"撤销" | 1 次确认即恢复上一版，页签状态同步 |
| J7 | 自定义助手 | "添加自定义助手"，填一个支持 ACP 的命令 → 确认 | 确认卡完整显示将执行的命令；接入后检测结果正确；env 写明文值时被拒绝 |
| J8 | 排查 | 依赖 AG.5，完成后再验 | — |
