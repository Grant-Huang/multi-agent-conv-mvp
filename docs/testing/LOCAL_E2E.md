| 编号 | 工作 | 回答的问题 | 节奏 |

## 2. W1 可部署性

### 2.1 检查项

| 编号 | 场景 | 做法 | 通过标准 |
|---|---|---|---|
| D1 | 冷启动安装 | 干净的机器或新用户账号，**只看** `README.md` 与 [docs/manual](../manual/README.md)，从零装到能在桌面问答 | 不需要看代码或问人；记录总耗时和每个卡点 |
| D2 | 配置完整性 | 对照 `crates/runtime/src/config.rs` 的 `AppConfig` 各节，检查 `config.example.toml` 是否都有说明 | 每个用户可配的节都有示例与注释；默认值能启动 |
| D3 | 真实模型接入 | 按文档接本地模型（如 llama.cpp）和一个云端模型 | 两种都能用；连接失败时界面有可理解的提示 |
| D4 | 本机 agent 接入 | 按 [03-connect-agents](../manual/03-connect-agents.md) 接 Claude Code、Codex 等 | 检测、体检、实际执行一致 |
| D5 | 升级 | 用上一版本（tag，如 `v1.0.0`）部署并用 W2 数据集写入数据，再升级到最新 `master` | 自动迁移成功；会话、任务、记忆、审批记录都在；无需手工改库 |
| D6 | 回滚 | 升级后退回上一版本 | 能启动；明确告知哪些新数据不可用，不损坏旧数据 |
| D7 | 备份与恢复 | 按文档备份数据库和配置，删除后恢复 | 恢复后数据一致（W2 数据集校验脚本通过） |
| D8 | 清理与卸载 | 停服务、删数据 | 不留后台进程；文档写清数据位置 |
| D9 | 多平台 | macOS 为主，Linux 与 Windows 至少各一次 | 差异写进文档 |

## 3. W2 本地测试数据集（“本地演示厂”）

### 3.1 原则

- **走公开接口写入**：用种子脚本调用 HTTP API 创建数据，不直接写数据库，确保数据经过真实的校验与迁移路径；接口做不到的再说明原因。
- **可重复**：固定随机种子、带数据集版本号；一条命令重置并重建。
- **不含真实数据**：人名、客户、产品全部虚构；可以参照真实工厂的结构与规模。
- **带期望**：每类数据附校验脚本，W1 的 D5、D7 与 W4 结束时用它检查数据一致。

### 3.2 内容（首版）

**版本**：`fixtures/local/VERSION` → `local-demo-plant` **0.1.0**（scale=`small`）。

| 类别 | 内容 | 用途 |
|---|---|---|
| 人员与角色 | 6 个虚构 principal（`users.json`）：生产主管、质量、设备、运营值班、管理员、班组长 | 隔离、权限、审批 |
| 历史会话 | 每人 30 个「按日会话壳」（标题 `[local-demo YYYY-MM-DD] …`）。**正文轮次**：公开 API 无免 LLM 批量导入，故 small 用可选 `--live-turns` / desktop `requests` 补有限 live 轮；全文 30×(3～10) 列为接口缺口 | 记忆选材、历史检索（L2）、长上下文 |
| 任务 | `POST /api/desktop/v1/snapshot/fixture/reset` 播种多状态夹具任务（需 `[desktop] test_fixtures`） | 任务视图、恢复、通知 |
| 个人记忆 | 每用户 fact/preference/style：确认、未确认、纠正、撤回 + 注入记忆（`memories.json` / `injections.json`） | UX-08、UX-09、生效规则 |
| 注入样本 | 8 道：5 条记忆正文 + 3 条 live 请求文案（`injections.json`） | 注入防线（[分层记忆决策](../decisions/2026-11-26-memory-layers-and-history.md) 第 7 节） |
| 工业数据 | `POST /api/world/mock/ops/ensure-seed`（需 `[mom] world_mock=true`）；定义见 `industrial.json`，素材引用 `fixtures/mom/s1|s2|expert` | UX-07、运营值班、World Adapter |
| 内省样本 | `POST /api/introspection/run`（需 `[introspection] enabled`） | 内省推送节奏与注意力预算 |
| 大体量 | `--scale large` 参数已预留，本版只保证可解析，不生成 10 万级 | W4 与性能 |

### 3.3 交付物

- `fixtures/local/`：数据定义与 `expected.small.json`。
- `scripts/local/seed.py`：`create` / `reset` / `verify`（`--scale small|large`，`--skip-live` / `--live-turns`）。
- 证据：`docs/testing/evidence/local-dataset-2026-11-26.md`。

## 5. W4 长程测试

### 5.1 怎么跑

- 用 W2 数据集（`small` 起步，稳定后用 `large`），启动完整本地部署（真实模型；本机 agent 至少 1 个）。
- 用**用户模拟脚本**（`scripts/local/soak.*`，第 6 线编写）按“一个工作周”的时间表驱动：
  - 上班时段每 2～5 分钟一次提问、委派、追问；
  - 离开与返回、跨会话切换；
  - 审批与执行回执；记忆的纠正与撤回；
  - 下班时段只有后台任务和定时提醒。
- 压缩时钟可选：用配置把日上限、免打扰、合并窗口调短，以便在 24 小时内覆盖多个“日界”；同时至少保留一次不压缩的 72 小时。
- 阶梯：先 8 小时冒烟，再 24 小时，再 72 小时。

### 5.2 观测与阈值（初值）

| 指标 | 采集 | 初值阈值 |
|---|---|---|
| 后端常驻内存 | 每 5 分钟采样 | 预热 1 小时后，24 小时增长 < 20% |
| 子进程 | 每 5 分钟列 ACP / agent 子进程 | 无僵尸进程；空闲时数量回到基线 |
| 文件句柄、端口 | 同上 | 不持续增长 |
| 数据库与日志大小 | 每小时 | 与数据量线性；日志按配置轮转 |
| 回答延迟 | 每轮记录（不含模型本身耗时） | P95 不比第 1 小时劣化 50% 以上 |
| 任务 | 状态分布 | 无“卡在执行中”超过任务超时的；无重复受理 |
| 提醒与内省 | 推送日志 | 无重复提醒；每日内省不超过 1 条；免打扰时段不推普通建议 |
| 数据一致性 | 结束时跑 W2 校验脚本 | 0 丢失草稿、0 丢失会话或审批记录 |
| 错误 | 后端日志中 ERROR / panic | 0 panic；ERROR 逐条有解释 |

### 5.3 结束时

- 产出 `docs/testing/evidence/local-soak-<日期>.md`：配置、数据集版本、时长、指标曲线（可附 CSV）、超阈值项与日志摘录。
- 超阈值的单独开 Issue（标题以“[待归属]”开头，`dispatch` + `line:2`）。

## 6. W5 故障与恢复

| 编号 | 注入 | 期望 |
|---|---|---|
| F1 | 委派任务执行中 `kill -9` 后端，再启动 | 任务状态可解释（恢复或明确失败），会话与草稿不丢 |
| F2 | 模型服务中途停掉、超时、返回 500 | 界面有提示可重试；恢复后可继续；不重复受理 |
| F3 | 本机 agent 执行中崩溃 | 任务失败并给出原因；无残留子进程 |
| F4 | 断网（云端模型）后恢复 | 同 F2；外发脱敏不被绕过 |
| F5 | 磁盘接近满 | 明确报错，不损坏数据库 |
| F6 | 两个后端实例误用同一数据库 | 第二个拒绝启动或明确报错 |
| F7 | 系统时间跨日、跨时区 | 免打扰、日上限、记忆有效期按预期 |
