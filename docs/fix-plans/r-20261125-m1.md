## 推荐实施

1. 回答开关关闭时不调用回答资料/风格渲染，reply_block 与 style_block 均 None；判断请求仍只由 judge 开关决定是否注入。沿用每轮共享收集，不把入口改成只看回答开关。当前还有 route/exec 两个独立开关，不能借本条把它们关闭、把 exec_block 当作回答资料丢弃，或替它们默认为回答开关控制。当前 collect/digest 对 route/exec 的独立性缺陷属于 R-20261126-M1，须另定范围，不声称一并修好。
2. 修改范围优先限定 `crates/runtime/src/conversation.rs` 的本轮块构造与传参；如抽辅助函数只做私有、无新配置/公开签名。不改 collector 的权限/预算、Store、Router、Orchestrator 或模型参数。
3. 核对全部 reply/style/digest 调用点，确保判断、直接回答、续问与已有降级分支都遵守该矩阵；风格仍不能进入 judge 清单。日志保留已有 event，chars/style_chars/judge_chars 表达实际生成并送入各路径的长度；不记录私密正文，不顺带改 R-20261125-L4 的文档欠账。
4. 在新测试文件中复用 `server/tests/judge_materials.rs` 的受控模型捕获方式，不改原测试断言。任务回执、已确认且生效的个人 style/fact、内省发现使用不同 marker，分别断言判断请求与回答请求的系统消息；不能只检查最终回复文本。

## 四种配置验收

| 回答 session_materials | judge 开关 | Then |
|---|---|---|
| false | false | 回答/判断均无额外材料或风格；仅在 route/exec 也关闭的对照中断言不收集 |
| false | true | 回答无资料/风格；判断仍有极简清单且无风格卡 |
| true | false | 回答按既有规则有完整材料/风格；判断无清单 |
| true | true | 两路各用自己的块，判断预算与风格隔离不变 |

矩阵主用例固定 route=false、exec=false，以隔离回答与判断；另加 route/exec 开启的兼容对照，只核对本条回答禁用约定，不伪称 R-20261126-M1 的已知失败已修复。Given 已链接完成任务且相关消息挤出近期窗口，并存在有效 personal style/fact/发现，When 四种配置各续问，Then 捕获的实际模型请求满足上表。关闭回答开关不能由旧缓存带回资料，错误/超时降级也不恢复已禁用块；管理提示轮继续不收集。

先登记新增用例并在原实现得到“回答请求仍含 marker”的业务 Red，再冻结断言修改实现 Green，保留原 RT-JMAT-01～05、RT-SMAT/USTY/FMAT 全部断言，跑全量 preflight、同步实际证据及功能地图。

备选：只在 generate_reply 调用时丢弃参数，可阻止注入，但还会生成不应存在的块和错误的日志字数；推荐在各路径渲染入口明确门控。不能用同时关闭两个开关规避独立性验收。
