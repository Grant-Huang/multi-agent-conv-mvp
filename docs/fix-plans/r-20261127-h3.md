## 推荐修复与备选

1. `session_materials.rs`：使用安全的 `get(..10)` 或等价安全日期解析，避免按字节越界。对 today 也安全解析；无效 today 不能引起 panic。合法日期按真实日历校验，不只检查短横线位置。合法日期早于今天才过期，当天仍有效。旧记录如“长期有效”读取时保留现有不判过期的兼容语义并保证可正常回答；不在修复中批量改库。
2. `desktop_api.rs`：create/patch 在调用 Store 之前统一校验 expires，允许精确的“长期”和有效 `YYYY-MM-DD`，日期应支持闰年。省略 expires：create 保持默认长期，patch 保持原值；显式空串、斜线日期、无效日期和任意自由文本返回 400，沿用现有 invalid 错误形状。校验先于任何写入，patch 同时提交其他字段时也须全部不变。保留现有本人权限、撤回和不存在条目的错误优先级，避免校验泄露资源是否存在。
3. 新增 runtime 单元/对话回归与 HTTP 集成用例（`crates/runtime/tests/`、`crates/server/tests/`）；补 CASES、证据和分层记忆登记项。文档说明“旧数据宽读、新输入严写”，不改 Store、表结构、前端输入组件或共享契约。本轮总结只新增方案和台账；实施时再记录确认后的决策与接口行为说明。
备选是只做安全切片、继续接收自由文本；能止崩溃，但“2026/12/01”仍会被当成永不过期，不推荐作为最终修复。
