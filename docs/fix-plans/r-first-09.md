# R-FIRST-09：解除配对后的双端令牌撤销方案

基线：origin/master 4da7712。来源：docs/review/2026-11-07.md 交接清单第 3 项及 findings.jsonl 中 open 条目，重开次数 0。

## 问题回顾与代码核对

`crates/runtime/src/nodes.rs::unpair` 只删除 AgentNexus 数据库记录、移除注册表 agent 和本地发现状态，不调用节点撤销接口。`crates/node/src/lib.rs::client_of` 继续按 Persisted.tokens 中的长期 Bearer token 判断身份；配对时该令牌已写入 node.json，节点不知道另一端删除了本地记录。因此“任务无法再由该 AgentNexus 路由”不等于“节点不再接受旧令牌”。这与 REVIEW.md 的 I7 及台账描述一致；本轮仅代码核对，未读取实际凭证或向真实节点发撤销请求。

## 推荐方案

1. 在节点协议中新增经过认证的“撤销本次配对凭证”请求，仅允许令牌持有者撤销其自身凭证，不按可重复 client_name 删除其他客户端。为配对增加稳定的 credential_id / generation，认证和在途任务都绑定该身份；原始 token 不进入日志、URL、诊断或错误正文。
2. 节点在独立持久记录中保存吊销结果/代际，先可靠落盘，再确认成功；持久化失败必须返回明确错误且不能产生“响应成功、重启后令牌复活”。撤销重放应幂等；响应丢失后可以安全重试或查询，不能要求一个已吊销的令牌重新获得业务权限。可用受限撤销能力/带认证查询实现确认，具体协议由负责人审定。
3. AgentNexus 接到 unpair 后立即禁止本地新分配，再在有界超时内请求节点吊销。节点在线并确认后，删除本地活动凭证；节点不可达则持久化“本地已解除、远端撤销待确认”，不得返回或展示“远端已吊销”。撤销待办需要保留最小受保护的凭证/能力引用，不能把明文 secret 放入普通任务或 UI；后台有限重试并有明确清理/人工处理策略。
4. 离线场景无法保证即时远端吊销。推荐同时引入有界凭证租期和代际刷新，离线最坏有效窗口由业务负责人确定。撤销或到期后新执行、查询和结果提交均被拒绝；旧 worker 迟到结果不能覆盖任务终态。仅停本地心跳或移除卡片不能作为撤权证据。
5. 节点为每个任务保存 credential_id/generation；撤销时取消该身份拥有的执行及其子进程，等待有界清理并释放配额，其他已配对客户端不受影响。需要触及 orchestrator/registry 的部分单独列入本方案审批，不绕过它们的状态守卫。

## 文件与范围

- crates/node/src/lib.rs：凭证认证、持久化、撤销处理与在途任务所有权。
- crates/runtime/src/nodes.rs：解除配对的双端流程与待确认状态。
- crates/core/src/ 下的节点协议类型、server 节点接口及 web 的解除状态显示：协议字段与用户可见的 pending/confirmed 区分。
- crates/runtime/src/store.rs：如需待办、凭证代际或租期列，附向后兼容迁移；旧节点 token 记录需要明确升级策略。涉及 registry/orchestrator 的撤权取消接线不得在未批准时实施。
- DESIGN 8.3/13、CASES、features.json、功能地图和证据：说明 offline 的最坏窗口与真实撤权边界。导出 TS 类型只由 an-core 测试生成，不手改 bindings。

备选：仅使用短租期、不新增主动吊销。实现更简单，但在线 unpair 后仍存在整个租期的可用窗口，不能声称即时撤销，不推荐作为台账完整修复。直接删除本地 token 的现状不是可接受的撤销替代方案。

## 风险、迁移与回滚

risk_classify.py 的路径规则对 nodes.rs、crates/node/**、remote.rs 为 L3；store/registry/orchestrator 为 L2 且属于 AGENTS.md 的高风险文件。另有公开节点/HTTP 协议及权限策略变化。按 FIX.md 第 0.5、3.3、4 节，本轮只提交方案，不修改实现、策略、配置或既有测试。

旧 node.json、SQLite 的 credential_id、代际、租期、撤销待办必须有兼容迁移；旧客户端不支持撤销时明确显示不支持并按负责人指定的升级策略处理，不静默降级为“已撤销”。回滚必须保留已吊销代际/墓碑，不能恢复已撤销令牌；必要时停止节点并要求重新配对。迁移和回滚均不删除业务数据。

## 验收（Given / When / Then）

- Given 已配对且旧令牌能执行，When 在线解除配对成功，Then 节点上同一旧令牌的执行、查询、提交均被拒绝；AgentNexus 不再分配新任务。
- Given 两个客户端使用相同 client_name，When 其中一个解除，Then 只撤销其 credential_id，另一个客户端仍可正常调用。
- Given 请求重放、响应丢失或节点重启，When 重试/恢复，Then 吊销结果不复活，结果可确认，无重复副作用。
- Given 节点离线或持久化失败，When unpair，Then 本地停用且显示远端撤销待确认/失败；在声明的租期边界后拒绝旧 token，不谎报即时失效。
- Given 撤销时已有执行、排队及子进程，When 撤销生效，Then 对应任务有界取消、释放配额、无残留进程，迟到结果不能复活终态；其他身份任务保持不变。
- Given 伪造、过期或跨凭证撤销请求，When 调用撤销接口，Then 拒绝且目标凭证/任务不变，日志不泄漏 token。

先定义用例及受控节点 HTTP/运行时回归，取得业务 Red，再改实现取得 Green；真实局域网与超时恢复另行实测，不能用本地路由失败冒充节点拒绝旧令牌。最后完成 FIX.md 全套检查。
