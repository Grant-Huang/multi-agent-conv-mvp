# R-20261107-M2：通用文件任务的完成信号方案

基线：origin/master 9e507eb。最新评审：docs/review/2026-11-07.md；当前台账状态 open，重开次数 0。按 FIX.md 第 2 节只写方案，不修改实现或已有测试。

## 问题与阻断依据

`crates/agents/src/general.rs:258` 在 write_file 成功且 answer 非空时立即返回 Succeeded。首段 overwrite 带交付说明会提前结束分段写作。

但已有测试 `crates/agents/tests/report_flow.rs:351` 的 `rt_rep_01_write_with_answer_finishes_without_another_model_call` 明确断言这种输入应当成功，模型调用数必须为 1；`docs/testing/CASES.md` 的 RT-REP-01 也定义了相同行为。仅凭首段内容和 answer，程序无法区分该正常场景与被报告的半成品场景。修复不能通过内容关键词启发式或路径特判保住旧断言。按 FIX.md“修复需要改已有测试的断言……只写方案，由人决定”。本轮未改断言，也不将当前测试当作问题已修复的证明。

## 推荐方案与备选

推荐只认已有协议的 action=final 作为完成信号，write_file 的 answer 仅保留在历史中，不能直接完成任务：
- general.rs：移除工具写入即返回成功分支，更新提示词要求全部写完后输出 final；沿用原有最大步数和取消策略。
- tools.rs：统一写入结果提示，删除“最后一次写入带 answer 即完成”的暗示；保留 append、内容去重和实际产物。
- report_flow.rs：在人明确批准修改既有验收语义后，调整 RT-REP-01/02 脚本和相应调用次数断言；不删除测试。
- 新增回归测试：首段 overwrite+answer 后仍继续 append，只有 final 后成功；步数耗尽且无 final 则失败，并保留已写产物；工具报错不会导致成功。
- 同步 DESIGN 9.5、CASES、features.json、FEATURE_MAP 和证据，明确普通工具循环与固定研究报告流水线的边界。

备选：引入显式 done 字段。它仍是模型输出，并不能独立证明全文完成，还会改变 schema；当前不推荐。模型对 final 的判断也不等于内容质量验收，内容完整性继续由专门验收和 Reviewer 检查，不能承诺任意报告都写全。

## 风险、迁移与回滚

路径规则计算 general.rs 为 L2。常规写文件任务会多一次模型请求，必须评估步数预算和延迟；本方案不改 config.toml、AgentAdapter 或 HTTP API，不改数据库结构。恢复旧实现会重新引入提前成功缺陷；回滚必须连同验收契约说明，由人决定，不能通过删测试回滚。
