状态：助手建议，等待明确批准。本轮仅核对代码与制定方案，未独立重跑报告的临时复现，未实施修复，不声称 Red→Green。依据 FIX 第 0.5、4 节及 AGENTS / PREFLIGHT 第 1 节，涉及高风险文件或 L2 行为须先批准。

## 问题与依据

最新报告继续确认旧问题仍存在。`crates/runtime/src/introspect/job.rs::RunOnceOptions::from_config` 使用 far_lease，固定租约到 9999 年；`store.rs::introspection_fail_stale_jobs` 仅回收已过期 running。进程在领取后退出且未 finish 时，后续手动和定时任务持续 lease_held。现有 RT-INT-14 手工传入过去租约，不覆盖生产配置生成的永久租约。

## 推荐方案与范围

1. 在实际领取前按当前 UTC 和既有 timeout_secs 计算有限截止时间，推荐租约为硬超时加固定清理宽限（建议 30 秒）；沿用 timeout_secs 至少 1 秒与现有取消/超时收尾。租约起点不能是很早构造 options 的时刻。时间相加须检查溢出，使用统一可比较的 RFC3339 格式；异常配置明确报错，不能退回 9999。
2. 推荐本轮采用“固定硬执行期限 + 宽限”，不新增心跳续租或公开配置。任务不能凭续租无限延长既有超时。若后续确有超过硬期限的业务要求，再单独审批续租和 owner 代次方案；当前不引入复杂的永久后台续租任务。
3. 修改高风险 `store.rs`：保持领取的事务原子性；过期回收只作用于 running，finish 按 job_id 且仅 running 条件更新，避免迟到完成把已 failed 任务改回 done。核对 finding/推送写入口：租约已失效的 worker 不能再提交或投递，相关校验和写入须在同一事务仲裁，不能只在 await 前检查一次。
4. 旧版 9999 running 不能靠新租约计算自动恢复。建议在确认旧进程全部停止、取得该数据库单实例运行权后，执行可审计、幂等的兼容恢复：仅把该旧租约 running 标为 failed/interrupted，保留 findings，不推进水位。不能每次启动无条件清全部 running，不能误杀仍存活的另一实例。若无法证明独占运行权，暂停旧数据恢复并请负责人安排维护窗口；不自动删除数据。
5. 文件范围：`introspect/job.rs`、`store.rs`、必要的 `runtime/src/lib.rs` 启动接线；新增 `runtime/tests/introspection_job.rs` 回归及相关测试文档。保留现有 RunOnceOptions 测试注入和公开 HTTP/config 兼容；若实现必须改变公开字段或数据库结构，先补方案及迁移再确认。

备选：心跳续租能支持无固定上限任务，但新增续租生命周期、代次与恢复竞态，本问题已有硬超时，先不采用。只把 9999 换成短常量也不够：未覆盖旧记录与迟到完成覆盖终态。

## 验收（Given / When / Then）

- Given 生产 from_config，When 领取，Then lease_until 有限且晚于当前时刻、与硬超时及宽限一致；边界配置溢出明确失败。
- Given 临时 SQLite 中已持久化租约、进程在领取后被终止，When 重启并将可控时钟推进到到期，Then 旧任务 failed/interrupted，新任务可领取；保留已写 finding，失败不推进水位。
- Given 未到期且仍活跃任务，When 手动/定时同时触发，Then 仍只有一个执行者；租约过期后旧 worker 迟到 finish/写入不覆盖终态或制造推送。
- Given 旧 9999 running，When 经独占维护恢复两次，Then 只恢复一次，done/cancelled/正常未过期记录不变；没有独占证明时不执行恢复。
- 既有 RT-INT-13/14/23 继续通过；采用注入时钟/同步屏障，避免实际等待长超时、放宽旧断言或串行整个测试集。
