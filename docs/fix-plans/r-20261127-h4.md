# R-20261127-H4：文件工具真实路径边界方案

状态：助手建议，待用户明确批准；涉及权限边界与高风险 util 文件，不直接实施。

## 问题与依据

基线 `90a65c11610238ac2015f8b97cad9beef5e5f0b8`，来源 [11-27 日报](../review/2026-11-27.md) 交接第 3 项，台账 open、无重开。
`crates/agents/src/tools.rs:288` 只做词法判断，read_file/list_files/write_file 随后跟随符号链接。工作区的 `link` 指向外部时可以读取、覆盖、创建外部文件。`crates/agents/src/util.rs:282` 的产物读取也有同类风险（既有 R-20261120-M8）。依据为工具模块的工作区限制声明、[MCP 设计](../mcp/DESIGN.md) 的效果边界及 [宪章](../PRODUCT.md) CH-P1/CH-P7。

## 推荐修复与备选

新增 agents 内私有 `workspace_fs` helper，供 tools 与 util 的产物读取复用，不改公开 Tool/AgentAdapter 接口。保留原词法解析函数的纯解析语义；既有 path_guard 使用不存在的 `/tmp/ws`，不能为实路径校验而修改它的断言。

真实 I/O helper 固定已有根目录的 canonical 路径，对目标最长已存在前缀 canonicalize 后检查组件级 starts_with；不存在的后缀逐组件校验后才允许创建。绝对路径、越根 `..`、失效链接均拒绝。写目标是符号链接时无论指向内外都拒绝；建议更保守地拒绝根目录以下的所有符号链接，包括读与列目录，降低三种操作行为不一致的风险。根目录本身允许在初始化时解析一次，随后使用固定根句柄。

仅先检查路径再用字符串路径打开仍有检查后替换（TOCTOU）窗口，不能把它作为安全修复交付。实际读、列举、创建目录、覆盖与追加均须经固定根目录句柄执行，逐层禁止跟随链接，在打开/创建时保持约束；优先选已有受维护的目录能力库，若需新依赖需在实施 PR 列明版本、平台支持与审计结果。不在 util 中新增裸 shell 或 git 命令。目标平台无法提供同等保证时明确拒绝操作，不静默退回原路径读写。实现前明确 Linux/macOS 的可用原语及 Windows 的重解析点处理，不声明仅靠 canonicalize 已解决并发攻击。

修改范围为新的私有 helper、`tools.rs` 三个文件工具、`util.rs` 的 read_text_file、新增 agents 测试、必要依赖声明，以及 CASES/证据/MCP 特性登记。R-20261120-M8 只列为同根因关联，本轮不写它的状态事件；后续实施应证明产物读取同样受保护。
备选只做 canonicalize 和写目标 symlink 检查，能挡静态链接，但留有竞争窗口，不推荐。允许工作区内链接能提升兼容性，但需要更复杂的句柄内解析；本方案选择统一拒绝子路径链接，需用户确认。
