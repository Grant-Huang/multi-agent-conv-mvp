# R-20261127-H2：后端凭据隔离方案

状态：助手建议，待用户明确批准；本次只提交方案。

## 问题与依据

基线 `90a65c11610238ac2015f8b97cad9beef5e5f0b8`，来源 [11-27 日报](../review/2026-11-27.md) 交接第 1 项，台账仍 open、无重开。
`crates/runtime/src/backends.rs:160` 克隆整个 `[llm]`；设置后端自己的密钥后，`crates/llm/src/lib.rs:296` 又用遗留的 `api_key_env` 覆盖它。结果云端、本地后端均可能拿到另一服务的密钥。
依据是 backends 模块的凭据隔离承诺及 [产品宪章](../PRODUCT.md) CH-G4；[连接器契约](../contracts/connector.md) 整体批准状态尚有争议，不把草案当成额外授权。风险为 L2，按 [PREFLIGHT §1](../fencing/PREFLIGHT.md) 先提交方案。

## 推荐修复与备选

只改 `crates/runtime/src/backends.rs` 的客户端配置构造：显式配置了 `[backends]` 时，复制非凭据配置后立即清空 `api_key` 和 `api_key_env`，再只解析当前后端的 `api_key_env`。解析后的值交给 `LlmClient`，不留下会触发第二次环境读取的全局引用。缺失或空值沿用现有明确报错，错误只含变量名，不能含密钥。
没有 `[backends]`、由 `[llm]` 合成 default 时保留旧凭据来源、优先级和错误语义。显式命名为 default 的后端仍属于显式后端，不得误判为合成后端。不改 `LlmClient::new` 的全局优先级，不取消已确认的 env 优先约定。
新增 `crates/runtime/tests/backend_credentials.rs`（或 backends 内新的测试模块），用唯一命名的虚构环境值和回环请求捕获验证；不读取真实凭据、不向外部端点发请求。同步相关 CASES、证据与现有 backend 特性的登记项，保持公开配置字段不变。
备选是改变全局凭据优先级；不推荐，会影响未绑定后端的旧客户端，而且仍不能阻止全局凭据落入本地后端。

## 风险、回滚与清理

显式后端原先误借用全局密钥的部署将改为无凭据或明确启动失败，需要运营者为该后端配置自己的引用。这是安全修复的预期行为，不提供跨后端静默回退。无数据库迁移、无公开字段新增。回滚只撤本项业务提交，保留测试；回滚会重现凭据串用，须人工评估。
所有替身服务只监听回环、使用有期限的请求并在退出时停止回收；环境变量按原值恢复，测试之间不竞争进程全局变量，不打印 Authorization 值。

## 验收与实施证据

- Given 全局及 cloud 分别配置不同的虚构 env 引用，local 不配引用；When 构建并向两个回环替身发请求；Then cloud 仅携带自身值，local 没有 Authorization，全局值两边都不出现。
- Given 全局只有明文 api_key；When 存在显式后端；Then 该明文也不能继承。Given 显式后端名字为 default；Then 同样隔离。
- Given 没有 `[backends]`；When 合成 default；Then 保留 `[llm]` env 优先及明文兼容行为。Given 后端引用缺失或空白；Then 明确失败且错误不含密钥。
- 先运行新增断言得到业务失败，再修改实现，以同一测试得到 Green；临时撤掉隔离语句应再次失败，恢复后通过；最后执行完整自检，实际输出随修复 PR 提交。本次未执行这些新增验收。
