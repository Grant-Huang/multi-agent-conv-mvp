# R-20261106-S1：本机 HTTP Host 校验方案

基线：origin/master e0811a2。来源：docs/review/2026-11-07.md 交接第 3 项与 findings.jsonl 的 open 条目；重开 0 次。

## 问题回顾

主服务 `crates/server/src/lib.rs::api` 与独立 MOM 的 `crates/server/src/mom.rs::router` 没有 Host 白名单。监听 loopback 本身不能拦截浏览器的 DNS 重绑定请求；主服务还暴露任务派发及准入接口，不能把 UI 来源当作授权依据。以上为代码核对，未进行恶意网页实测，不将推断升级为已复现。

## 推荐方案

1. 在 server crate 新建小型内部中间件，主 api 与独立 MOM router 共用；覆盖 API、SSE、静态页、同源 MOM 和已启用的 admission 路由，不靠页面或 CORS 防护。
2. 严格解析 authority，默认只接受 localhost、127.0.0.1、[::1]，端口必须匹配服务实际监听端口；拒绝缺失、重复、非法、带用户信息的 Host。IPv6 不用冒号字符串截断。测试覆盖 HTTP/1.1 Host 及框架支持的 HTTP/2 authority 来源，避免遗漏协议分支。
3. 拒绝返回明确 4xx，在 handler、副作用与数据库写入之前完成。默认不信任 X-Forwarded-Host/Forwarded；使用任意 Host 或宽泛 localhost 后缀均不可绕过。
4. 有远程节点/反向代理需求时，必须由人提供精确额外 authority 列表与可信代理边界；新增配置、bind 适配和文档变更另行审批，不能为了兼容直接允许任意域名。Origin 校验可作为补充，不替代 Host 或后续身份认证。
5. 同步 DESIGN 安全章节、接口错误说明、CASES、features.json、功能地图与证据。不可把该措施宣称为服务已经有完整身份鉴权。

备选：只补 CORS 或只检查 POST。无法覆盖同源重绑定或所有入口，不推荐。将所有非 loopback 使用永久禁掉也可能破坏节点场景，需要负责人决定。

## 风险与边界

risk_classify.py 的路径规则对 server/src/lib.rs、mom.rs 给出 L2，但此行为改变请求准入安全策略；AGENTS.md“修改权限策略”与 FIX.md 第 0.5 节更严格，本轮只写方案。新配置也涉及公开接口，未获确认前不改实现或配置。没有数据库迁移；回滚仅由人决定，回退会恢复原攻击面，不以关闭校验作常规故障恢复。

## 验收（Given / When / Then）

- Given 真实临时服务，When Host 为允许的本机 authority，Then 健康、任务、MOM 正常路径可用。
- Given 非白名单域名、伪装后缀、重复/缺失/非法 Host 或伪造转发头，When 访问 GET/POST/SSE，Then 返回 4xx，处理函数未调用、任务和事件数量不变。
- Given ::1 和随机监听端口，When 合法 IPv6 authority 或错误端口到达，Then 分别允许/拒绝，不误解析。
- Given 本机浏览器以攻击域名发送到 loopback，When 复现重绑定路径，Then 请求在读取/写入业务数据前被拦截；浏览器证据与 HTTP 测试分别记录。

先登记验收并取得业务 Red，再实现 Green，最后运行 FIX.md 全套门禁。单次请求校验不创建进程或后台任务，无新增取消/清理需求；服务测试有超时并停止自己启动的服务器。
