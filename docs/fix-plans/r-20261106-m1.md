# R-20261106-M1：资源预留、到期与独立资源方案

基线：origin/master 9e507eb。任务来源：docs/review/2026-11-07.md 交接清单第 3 项及台账 open 条目，重开次数 0。

## 问题回顾

`crates/runtime/src/mom/engine.rs:298` 把任何其他案例的非空 reservations 都当冲突；`:314` 为所有 S1 写死 tool-32 与 XY-XZ，记录值只有案例 ID，没有到期时间。非终态 tick 不释放到期预留，案例长期 VERIFYING 会阻塞后续执行。只是批次不同不代表资源不同；不能为通过“不相关批次”测试而允许两批使用相同设备并发。

## 方案边界与推荐

完整修复需要让场景明确表达实际资源键与租期。当前 SimulationConfig/world 的白名单既没有资源键也没有预留租期，不能只在冲突判断处按批次隔离。这将扩展公开 HTTP 仿真配置的接受字段，按 FIX.md 第 3.3 节转为方案，不直接修改业务代码。

推荐方案：
1. 在 mom/model.rs 引入内部预留记录 owner、resource_key、expires_at、plan_revision，保持旧数据可读；不要把“租约到期”伪装成“业务动作完成”。
2. 在 mom/simulation.rs 的公开仿真参数中增加显式资源键集合和有界 reservation_ttl_minutes，旧请求默认沿用共享 tool-32、XY-XZ。新增参数必须校验长度、重复键和范围；不能让模型随意改真实资源映射。该能力仍为 Mock M08，不扩大正式授权。
3. engine.rs 下发前按目标资源键与当前有效租约求交集；整组原子预留，任一冲突不修改预算、批准或动作。tick 对到期租约记录事件并释放，使用当前虚拟时钟；重启保留到期时间。
4. 对已 ACCEPTED/UNKNOWN 且可能继续占用资源的动作，默认到期转为待人工核验，不能单凭时间自动授予另一个案例使用权；模拟中仅在已 VERIFIED 或明确未占用时释放。长时间 VERIFYING 但所有动作已核验的案例，不再永久占用资源。
5. docs/mom/DESIGN.md 与 MOCK_REGISTER 的 M08 记录资源键、到期语义和真实系统差距；同步 CASES、features.json、功能地图、事件表和证据。

备选为仅修固定共享资源的到期机制、不增加仿真配置。它不会解决独立资源表示问题，只能部分处理台账，故不建议将其声称为完整修复。

## 风险与迁移/回滚

路径规则对 mom/engine.rs、model.rs、simulation.rs 均为 L2；不修改高风险 orchestrator/store/registry 和权限策略。公开 API 增加可选配置参数需要人确认。SQLite 表结构无需新增，但序列化快照字段必须 serde 默认兼容并有旧数据读取测试；旧的无到期预留不能直接视为已过期，应要求核验或人工释放。回滚前导出快照；若新格式无法被旧版读取，使用兼容迁移或停止回滚，不能丢弃台账。

## 验收（Given / When / Then）

- 同资源、未到期预留：另一案例下发失败且状态/事件/预算不变。
- 显式互不相交的资源键：两个案例可独立下发；仅批次不同且资源相同仍互斥。
- 到期且模拟动作已核验：tick 恰好释放一次并记事件，新案例可执行；持有者无需先关闭。
- 到期但动作 UNKNOWN：不能静默允许资源重用，进入待核验流程。
- 重启前后：到期时间不重置；旧快照可加载且不自动释放状态未知的预留。
- cancel/close/PARTIAL：现有释放语义保持且不重复事件。

先登记验收并写可执行回归，取得业务断言 Red 后实现 Green，再跑 FIX.md 全套检查。

## 需要人决定

是否同意扩展公开仿真配置以显式指定资源键和有界租期，并采用“已核验后到期可释放、UNKNOWN 到期需核验”的策略？推荐同意；租期数值由业务/仿真负责人确定，未确认前不实现。
