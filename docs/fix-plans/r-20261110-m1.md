# R-20261110-M1：准入接口身份认证与审批隔离方案

基线：origin/master 4ca00df。来源：docs/review/2026-11-10.md 交接清单第 2 项及台账 open 条目；重开次数 0。

## 问题与本轮边界

`crates/server/src/admission_api.rs::approve` 仅接收调用者提供的 approver 字符串，`AdmissionLedger::approve` 只检查非空，activate 也没有独立认证。默认 admission.enabled=false 是功能开关，不是身份认证；Host 白名单也不能代替鉴权。报告中的网页攻击场景本轮未实测，不把推断升级为已复现。

接口鉴权、调用者权限、审批人身份都属于权限策略，按 AGENTS.md 与 FIX.md 第0.5/3.3/4节只提交方案，不直接修改业务代码、凭据、配置或 CI。既有 R-20261106-S1 方案仍需独立确认；本轮不把新报告建议当作修改运行配置的授权。

## 推荐方案

1. 在 server 的准入路由边界接入经过认证的 Principal，服务端验证凭据后确定身份和角色。不得把 body.approver、Host、Origin、来源 IP 或“本机端口”当作审批凭据。缺少或无效凭据返回 401，已认证但无权限返回 403，均在 ledger 写入和注册 agent 前拒绝。
2. 将提交者、审查人和激活操作者分离：提交与澄清可用 candidate 权限；approve、activate、revoke 等管理操作仅 admin/reviewer 范围；审批身份来自 Principal，不能由请求正文冒充。Trusted 审批人必须不同于提交者，agent 的执行凭据不能用于自审或激活管理。
3. 审批绑定 agent、契约、binding 修订和凭证代际，修改受保护条件必须使批准失效或走重新准入；R-20261110-H1 的阶段守卫只解决 Active 改写，不能被宣传为已解决匿名审批或所有并发/持久化半完成问题。
4. 凭据通过受保护环境变量/秘密管理入口注入，不能写入 config.toml、Git、URL、日志或错误。若需要新配置字段、协议字段和持久身份/修订列，应在独立实施 PR 明确公开接口兼容方案并附迁移；不在本轮修改 config/。测试只用隔离的一次性假凭据，不访问真实密钥。
5. 分别覆盖主服务内嵌入口和所有实际准入调用路径；未认证请求不能借批量、重启重新注册或转发头绕过。SSE/诊断不能泄露管理凭据；浏览器 CORS/CSRF 防护是补充层，不等同授权。
6. 在上述认证与 Host 边界经负责人验收前，建议保持 admission 默认关闭，不在共享环境启用；当前默认已是关闭，本轮不改变运行设置。更新 DESIGN、部署说明、CASES、功能地图与证据，说明“人工审批”仍需真实身份系统。

备选：仅增加一个本机管理 Bearer token。比无认证好，但不提供可靠的多人职责分离或禁止自审；只能作为负责人明确接受的受限单人模式，不应声称满足多主体审批。Origin/Host 校验或更换 approver 文本都不能作为替代方案。

## 文件、风险与回滚

拟改 server/src/admission_api.rs、共享认证中间件、runtime/admission.rs 的身份/批准绑定及相关测试；如确需 core 协议或 store 持久结构，单列并附兼容迁移，禁止绕过高风险文件审批。路径规则对 admission.rs 和 server 为 L2；权限策略语义及可能的配置/持久化变化按更严格规则要求先确认，不据此自行实施。

不自动撤销已有配对/agent 或删除数据。升级时对没有可验证审批人身份的历史 Active 记录采用负责人批准的隔离/重新审批策略，不能静默视为已认证。回滚不能自动恢复匿名管理接口；优先关闭准入入口或回到受限模式，具体由负责人决定，保留审计与撤销代际。

## 验收（Given / When / Then）

- 未带凭据或伪造凭据调用 approve/activate：401，记录、binding、epoch、审计和 registry 不变。
- candidate 凭据访问管理接口或以正文伪造审批人：403，不能自审或借执行 token 激活。
- 有权限且不同于提交者的审批人：正常审批/激活；审计身份等于服务端验证身份。
- 修改契约/binding 或并发重放：批准修订不匹配时拒绝，不出现错误响应后仍写入的新地址。
- 重启、凭据轮换/撤销、代理或非白名单 Host：认证不绕过；重放不产生重复管理副作用，敏感数据不出现在日志与返回正文。

先登记验收并在原实现取得业务 Red，再实现 Green，最后跑 FIX.md 全套门禁；HTTP、浏览器、真实身份提供方分别记录，不互相替代。认证校验不引入无限等待；未来如用远程身份服务，必须有请求期限、取消和失败关闭语义，无后台无限重试。
