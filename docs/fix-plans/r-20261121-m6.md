# R-20261121-M6：SSE 落后显式恢复，禁止游标越过缺口（待批准）

日期：2026-11-23（America/Vancouver）。基线：origin/master `175e07b26e71a8b56b3ab75f475b8184432bf85e`。

状态：助手建议，待明确批准。依据 [FIX.md](../../FIX.md) 第 0.5/4 节与 [PREFLIGHT](../fencing/PREFLIGHT.md) 第 1 节，涉及高风险文件、L2 行为或已有断言冲突，本轮只提交方案。台账状态仍 open；本轮为源码核对，未独立复现失败、未新增回归或实施修复，不声称 Red→Green。

## 问题与依据

[日报 M6](../review/2026-11-21.md)：`server/src/desktop_api.rs::desktop_events` 使用 item.ok()? 静默吞掉 BroadcastStream 的 Lagged；之后继续投递较新事件，客户端 cursor 越过未收区间。`runtime/src/bus.rs::publish` 先广播再入写队列，单次 flush 也不能证明刚广播的事件已经入队。assistant_delta 还只广播、不持久化，不能把这类片段 ID 当成可恢复游标。

权威设计：[AI Desktop DESIGN §5](../ai-desktop/DESIGN.md)、[历史决定 67](../DECISIONS.md)；[事件契约](../contracts/events-and-trace.md) E2/E3/E4，规定去重、先持久化后投递、过期明确告知。不更改契约，不宣称临时流式片段可逐片重放。

## 推荐方案与范围

1. 在 desktop_api 的私有有状态 SSE 生成器中显式处理 Lagged：发一个**不含新事件游标**的 resync_required 控制消息，然后终止该订阅；不能再送缺口之后的事件。控制消息字段/前端约定须批准并登记。客户端保留最后成功应用的持久事件游标，不能把控制帧当新 cursor。
2. **可恢复游标只来自持久流**：B2 live 将广播视为唤醒信号，从 SQLite 读取最后已提交游标之后的事件，并以持久顺序构造信封；不直接用广播事件 ID 推进恢复位置。读库失败明确结束/报错，不默默跳过。为覆盖“广播先于入队”，设置有界周期补读，即使最后一次唤醒过早也会补到已提交事件；不能用任意 sleep 假装提交屏障。查询需批量、背压受控，防止慢客户端无限积累内存。
3. 临时 assistant_delta 维持独立的临时语义，不推进持久 cursor。若要在同一 B2 流交付且现有 DTO 不支持，先审批兼容字段/事件类型；不能把永不落库的 ID 作为恢复 token。旧 /api/events 行为保持兼容，首轮不改 Bus 全局发布顺序。
4. 前端 `web/src/api.ts::subscribeDesktopEvents` 与调用方在控制帧/断开后关闭旧连接，用最后已应用 cursor 构造新 URL（不能指望 EventSource 自动重连更新固定 after 查询串）；410 触发任务/消息快照重取，保留草稿与已有事实。重连退避有上限、会话切换取消旧定时器和订阅，避免重复连接与跨会话写入。
5. 依赖高风险 store 私有批量读取/持久顺序支持。**已知 R-20261121-M7** 的 created_at 排序与 rowid 游标不一致会影响这一前提：本轮只列依赖，不追加 M7 事件或声称处理第四项。M6 的完整“无遗漏无重复”验收须等待 M7 的独立批准与修复，或另行批准调整切片范围；不能在本条里暗修 M7。需要 store 接口或公开 DTO 变化时纳入实施审批；不新增事件表、不改 orchestrator。

备选：仅在 Lagged 断开，改动更小，但仍留下 live ID 未提交、临时片段不可重读等窗口；仅扩大广播容量只是降低发生概率。推荐显式恢复加持久游标边界，并保留有限周期补读。

## 验收（Given / When / Then）

- Given 可注入的小容量广播和已确认订阅，When 用同步屏障制造确定性落后，Then resync_required 无新 cursor 且随后 EOF，不再推进到缺口后的 ID。
- Given 客户端最后成功应用的持久 cursor，When 控制消息后手动重连补读，Then event_id 集合与相同保留窗口的 SQLite 事实一致，合并去重，无跨会话事件；本验收依赖 M7 顺序前提。
- Given 广播发生但写队列尚未入队、随后提交，When 无更多广播，Then 周期补读仍能收到，不发送不存在的持久 cursor；读库故障明确结束，不错误确认。
- Given 临时 delta、过期 cursor、读库失败和会话切换，Then 分别不推进恢复点、410 重取快照、可观测错误、旧重连任务及时取消。已有 RT-ADREPLAY-01～04 与 T-64 恢复流程保持断言。

批准后新增真实 HTTP SSE/客户端恢复业务 Red，冻结断言 Green，登记 CASES/功能地图与事件协议、跑全量 preflight；有界等待、同步屏障及自有 HTTP 服务 kill/wait，不通过大量发包碰运气制造落后。

## 风险与回滚

实施 L2，涉及持久事件读取、公开控制消息与重连语义；store 改动须先批。无表结构变化或迁移。回滚前关闭新恢复连接并取消轮询，恢复兼容客户端；回滚旧 live 路径会恢复已知丢事件风险，须明确告知并保留快照补读路径。正式取舍待批准后在实施 PR 记 docs/decisions/；本总结按 FIX §5 仅保留方案与台账。
