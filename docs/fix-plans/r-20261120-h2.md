# R-20261120-H2：取消后禁止领取生产写，迟到回执不得复活案例（待批准）

风险：L2且涉及MOM状态机，按FIX第0.5节、最新交接清单及AGENTS/PREFLIGHT只出方案。本轮不改业务代码。

## 问题核对

- `mom/engine.rs::cancel`清脚本队列、节点、审批与预留，却没有清DES远程pending。
- `mom/des/remote.rs::des_pending_writes`直接返回所有pending；`server/mom_des_connector.rs::dispatch_writes`只按仿真归属过滤，之后整批send_writes，不核对案例阶段。
- `des_record_write_receipt`失败分支无条件把stage改为PARTIAL，可覆盖CANCELLED/BLOCKED。

报告的取消后仍发三笔写为已复现；本轮做了代码路径核对，没有新增Rust测试或声称本轮独立复现。

## 推荐改动

1. **取消/关闭与清待发写原子化**：在`Engine::cancel/close`的同一次`Engine::update`事务内，按case_id移除尚未领取的远程pending。辅助函数放在remote.rs，操作同一Snapshot，不能先提交终态、再另起事务清队列。协同事项关闭成员的入口也要覆盖，不只改HTTP入口。
2. **发送前逐笔领取**：连接器不能拿一份旧pending快照就整批发送。每笔RPC前，锁内核对案例不是CANCELLED/CLOSED/BLOCKED、审批/修订仍适用且写仍在队列，原子领取该写并记录case版本/代次；领取失败就跳过。随后释放std Mutex再await网络，严禁持std Mutex跨await。
3. **明确竞态边界**：领取成功定义为“已进入在途”。取消先发生则无法再领取；领取先发生则取消不能承诺撤回外部调用。不能只做一次stage检查，却不说明检查与实际I/O之间的竞态。
4. **在途与排队分开**：取消清queued，已领取写保存最小的key/case_id/action_key/版本上下文用于回执和对账，标记已过时，不能把它重新放回可发送队列。现有幂等键继续使用，不借重试生成新键。
5. **回执终态守卫**：记录在途回执时再次核对版本/阶段。CANCELLED/CLOSED保持终态；BLOCKED不得被成功或失败回执拉成PARTIAL。可记录独立的迟到/待对账证据，但不能恢复审批、预留或宣称已补偿。失去pending的过时回执应安全识别，不能因首条异常丢掉其他案例的有效回执。
6. 复用连接器现有ops串行化；引擎的领取/取消状态为真正仲裁点。若实现发现仅靠现有结构无法提供上述顺序语义，应停下补方案，不偷偷增加持锁网络调用或新公开取消接口。

## 风险、取消语义与回滚

外部工厂已接受的写不能靠本地CANCELLED自动回滚。推荐语义是“取消阻止未领取写；已领取写可以完成，但只记录迟到与待对账，不改终态”，并明确展示不可撤回的事实。若要求“取消返回后物理上零新I/O”，需要取消等待在途收尾或工厂支持撤销，超出本次最小修复。

快照默认值和代次恢复必须可重复。回滚代码时不能把已取消queued重新激活；先停止相应仿真并保留待对账记录，再回滚单独提交。不能通过清空未知在途记录来声称已清理完成。
