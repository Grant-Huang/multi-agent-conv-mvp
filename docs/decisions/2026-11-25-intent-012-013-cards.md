**一句话结论**：临时提问吞掉任务草稿（013）与“离开再返回工作现场恢复”同属 CH-U2 草稿问题，并入 UXFIX-D 由同一实现者修；“我的助理”打开设置表单而非对话（012）改的是入口与面板结构，另开 UXFIX-G。

## 背景

UX-02 基线审查（#297 入库）在 `8dd64dc` 上发现两条新偏离：

- INTENT-2026-013（高，CH-U2 约束）：工作区“继续当前任务”与“独立话题”共用同一个输入框和同一份草稿；用户切到独立话题改写输入框提问后，切回任务时原草稿已丢失。
- INTENT-2026-012（中，CH-U1、CH-U5）：左栏“◇ 我的助理”打开“设置 → 我的 AI 助理”表单，没有对话入口；表单直接显示 Soul、Taste，并带“注入冲突（测试）”按钮。

## 问题

- 013 与 UXFIX-D 已有范围（008 旧草稿覆盖新输入、011 发送记录离开再返回丢失）都在草稿存取与工作现场恢复这一处代码，分两张卡会两头改 `draftStore.ts` 与工作区输入组件。
- 012 涉及入口路由、面板结构和设置文案，与 UXFIX-B（测试控件只在测试模式出现）只有“注入冲突（测试）”一个按钮重叠，混在一起难以分别验收。

## 决策依据

1. UX-02 基线审查第 2 节路线 B、C（013）与路线 A（012）的操作记录。
2. 代码事实：作用域切换在 `web/src/desktop/ScopeControls.tsx`，提示文案“独立话题：普通问答不创建新 Task”在 `web/src/desktop/WorkspaceComposer.tsx`，两种作用域共用同一个工作区输入框（推断：共用同一草稿键，实现者须先核实）。
3. 设计依据：`docs/ai-desktop/DESIGN.md` 第 2 节导航表要求助理头像、“与我的助理交谈”、主动消息打开**同一个人助理面板**；第 7 节把助理身份表单（含“沟通原则（Soul）”“质量偏好（Taste）”）放在设置中心。即：入口应进面板，表单只在设置中出现。
4. 宪章 `docs/PRODUCT.md` v1.4：CH-U1 对话随时可达；CH-U2 保护工作连续性（切换时保留草稿为约束）；CH-U5 用户不需要理解系统内部。
5. 用户 2026-11-25 确认按助手建议派卡。

## 定了什么

- UXFIX-D 再扩大一次，加入 INTENT-2026-013。
- 新开 UXFIX-G（INTENT-2026-012），交桌面线。
- UX-02 的欠账约束对应关系：UX-02-I2 → UXFIX-D；UX-02-I4 → UXFIX-G；UX-02-I3（临时问题得到回答）随 UXFIX-A 的会话接通一起核实，不另开卡。

## 简单设计

### UXFIX-D（再扩大）：草稿按作用域分别保存（INTENT-2026-013，CH-U2）

| 项 | 内容 |
|---|---|
| 做法 | “继续当前任务”与“独立话题”各有一份草稿，草稿键带作用域（例如 `task/{task_id}` 与 `topic/{task_id}`）；切换作用域时先保存当前草稿，再恢复目标作用域的草稿；独立话题发送后只清空独立话题草稿 |
| 先核实 | 服务端草稿 API `GET/PUT/DELETE /api/desktop/v1/drafts/{kind}/{scope_id}` 的 `kind` 是否已允许新取值；若需新增 `kind` 取值或改表结构，属于 HTTP 接口 / 数据库变更，须先出方案 |
| 验收（先 Red） | 新增 E2E：在任务作用域写草稿 → 切独立话题（输入框为空或为独立话题草稿）→ 提问并发送 → 切回任务，原草稿仍在；完成后 UX-02-I2 从欠账改为用例 E2E-UX02 的一部分或新用例 |
| 不做 | 不改独立话题“不创建新 Task”的规则 |

### UXFIX-G：“我的助理”打开可对话的助理面板（INTENT-2026-012，CH-U1、CH-U5）

| 项 | 内容 |
|---|---|
| 做法 | 左栏“我的助理”、助理头像、“与我的助理交谈”、主动消息都打开同一个人助理面板（DESIGN 第 2 节）：面板顶部为对话输入与最近消息，“调整助理”链接进入设置中心的“我的 AI 助理”分类；关闭面板恢复下层界面、焦点与草稿 |
| 文案 | 面向用户的标签改为用户语言（例如“沟通方式”“判断标准”），Soul、Taste 只作为字段说明或不显示；这会改 `ai-desktop/DESIGN.md` 第 7 节表单字段的展示名，实现者在同一 PR 内更新设计文档并在 PR 正文说明 |
| 测试控件 | “注入冲突（测试）”按 UXFIX-B 的规则只在测试模式出现；若 UXFIX-B 先合并则本卡不再处理 |
| 验收（先 Red） | 新增 E2E：工作区写草稿 → 点“我的助理” → 面板中对话输入可编辑 → 关闭面板，草稿与任务 ID 不变；面板中不出现“Soul”“Taste”字样；完成后 UX-02-I4 从欠账改为用例 |
| 不做 | 不改个人助理身份的存储与接口；不实现主动消息的新类型 |

## 没选什么

| 做法 | 为什么没选 |
|---|---|
| 013 单独开卡 | 与 008、011 同属草稿与工作现场恢复，同一处代码，合并修可避免冲突 |
| 012 并入 UXFIX-B | B 只管测试控件可见性；012 主要是入口与面板结构，验收标准不同 |
| 把临时提问挪进助理面板以绕开 013 | 改变了工作区“独立话题”的既有设计，属于产品方向调整，未讨论；先按作用域分存草稿修复约束 |
