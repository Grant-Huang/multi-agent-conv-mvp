**一句话结论**：设置里「沟通原则（Soul）/ 质量偏好（Taste）」视作已确认风格——保存即确认、全部会话（含旧会话）下一轮即生效，与 L3 风格记忆同卡渲染、同一套护栏句与预算；种子默认值视作「未设置」不注入；个人质量偏好 ≠ 组织 taste。

## 背景

设置面板有 Soul / Taste 字段且保存成功，但回答路径从不读取——用户改了等于没改（INTENT-034）。能影响回答的只有 kind=style/preference 的个人记忆（需确认入口 #347）。

## 定了什么

1. **方案 a**：设置字段作为已确认风格进入风格卡（与 L3 风格记忆同一套生效与护栏规则）。
2. **确认语义**：保存即确认（用户主动保存 = 确认动作，与 5.2b「推导式判定」一致）；全会话生效（不沿用记忆的「确认晚于会话创建不回填」——设置是持续生效的配置而非一次性沉淀，用户预期是「改了下一轮就变」）。
3. **默认值 = 未设置**：种子默认 soul / taste 不注入（否则每个会话凭空多出风格卡）；用户显式修改或清空后才生效 / 停用（清空字段即可停用，可控）。
4. **边界**：个人「质量偏好」是个人风格（CH-G2 个人层）；组织判断标准（taste）属组织（CH-G2 组织层），只能经发布流程带版本管理，**不出现在个人设置里、也不由个人设置注入**。
5. 来源 id：`profile:soul` / `profile:taste`（回答所用记忆可说明，CH-G1）。
6. 验收：RT-USTY-07（默认不注入 / 显式设置即生效 / 来源 id / 护栏句仍在）。

## 没选什么

| 做法 | 为什么没选 |
|---|---|
| 方案 b（移除设置字段，统一走记忆） | 用户已有数据作废、表达一条风格要多步（保存记忆 + 确认入口 #347 未就绪）；设置字段保存即生效更符合直觉与 CH-G1 |
| 默认值也注入 | 每个会话凭空多出风格卡，破坏「沉淀可见可控」（用户没设置过东西却看到风格卡） |

## 出问题先看

- 设置改了回答没变：查 `session.materials` 事件 style 段是否含 `profile:soul` / `profile:taste`；确认字段值不等于种子默认值且非空。
- 风格卡挤占风险提示：护栏句与 ≤200 token 预算沿用 5.2b（RT-USTY-04 口径）。
