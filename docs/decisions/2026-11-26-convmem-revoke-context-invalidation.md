**一句话结论**：个人记忆撤回时，所有**未终态**任务 context 中该记忆的资料段同步摘除（段空去段、块空去整块）；批准、重试、重启续跑都从库读 context，因此全部生效；已终态任务 context 保留原件供审计（L2 任务记录不可改口径不变）。

## 背景

S6-exec 把会话资料完整块（含个人记忆正文）随任务持久化在 `tasks.context`（当时拍板「保存时点语义，重试不刷新」）。夜间评审复现：撤回个人记忆后，待批任务批准时执行者仍拿到已撤回记忆正文——违反宪章 CH-G2e（撤回后不再使用，约束级）。

## 决策依据

1. 用户 2026-11-26 会话拍板（见「来源」）。
2. 宪章 CH-G2e（用户 2026-11-25 确认，约束级）：记忆本人可查、可改、可撤，撤回后不再使用——权威顺序高于 S6 决策的设计细节。
3. 评审建议方向二选一：执行时按撤回状态过滤（触及 `orchestrator.rs` 续跑路径）或撤回时清扫（不动 orchestrator）。用户选后者：改动面最小、语义等价。

## 定了什么

1. **撤回即失效**：`revoke_desktop_memory` 同步清扫未终态（非 COMPLETED / FAILED / CANCELLED）任务中该记忆的资料段——**清扫范围含 `tasks.context` 与 `tasks.exec_material` 两列**（#360 改版后执行资料独立存于 exec_material 列，submit 快照、批准 / 重试 / 续跑注入本机执行者）；清扫失败不阻断撤回但记 `materials.context.cleaned` 事件。
2. **机制**：store 层字符串段摘除（`strip_memory_from_context`，按 `来源：{id}（个人记忆` 条目粒度；兼容移除片 2 修正前的判断清单遗留行）；不做 context 结构化改造、不触及 orchestrator.rs。2026-11-26 晚间 #360 改版（exec 资料分离）后由本决策扩展覆盖 exec_material 列。
3. **审计边界**：已终态任务 context 保留原件——「记录发生过什么」的 L2 口径不受影响；被撤回记忆不再被**使用**即可满足 CH-G2e。
4. **修订声明**：[S6 决策](2026-11-24-convmem-s6-exec-materials.md)第 4 条「重试不刷新」对个人记忆部分自本日起按本决策执行；回执等非记忆资料仍保持保存时点语义。
5. 验收用例：RT-EXEC-06（撤回后批准 → 执行请求与 tasks.context 均不含正文与 id；持久 context 已清扫即覆盖重试与重启续跑——三者同源于库中 context）。

## 没选什么

| 做法 | 为什么没选 |
|---|---|
| 执行时按撤回状态过滤重渲染 | 触及 orchestrator.rs 续跑路径（高风险清单，须另批方案）；需 context 结构化改造 |
| 维持保存时点语义 | 违 CH-G2e 字面；评审与宪章均不支持 |
| 撤回时连带改写已终态任务 | 破坏 L2「任务记录保留原件供审计」口径 |

## 出问题先看

- 撤回后仍有记忆正文出现：查 `materials.context.cleaned` 事件是否记录、`strip_memory_from_context` 是否命中（条目行首格式必须为 `来源：{id}（个人记忆`）。
