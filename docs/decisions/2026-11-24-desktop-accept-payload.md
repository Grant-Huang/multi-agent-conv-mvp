| 项目 | 内容 |

| 来源 | 用户确认（PR #233 明确勾选 M5 实施范围） |

| 影响范围 | ai-desktop 的 B1 可靠受理 |
| 相关设计 | [AI Desktop DESIGN §5](../ai-desktop/DESIGN.md#5-扩展协议与数据模型)；[实施方案](../fix-plans/r-20261121-m5.md) |

**一句话结论**：保留现有操作唯一键，只在会话、正文、scope、task_id 都相同时重放数据库记录；否则 409。

## 背景

B1 已将操作和用户消息同事务保存，但只比较正文；换会话、目标任务或发送范围仍被当成同一次发送，返回字段还会混入本次请求的归属。

## 问题

相同正文并不代表相同目标。同一个操作键指向两个会话时，第二个会话没有消息，却收到已受理回执，用户无法发现目标错位。

## 决策依据

1. [日报 R-20261121-M5](../review/2026-11-21.md) 及 `cf8d793` 的 `store.rs::accept_desktop_request`：仅 `committed == text`，Replay 归属字段来自新请求。
2. [PR #233](https://github.com/Grant-Huang/multi-agent-conv-mvp/pull/233) 的“需要人决定”明确勾选 M5：保持唯一键、完整载荷比较、异载荷 409、库中字段重放。
3. 历史决定 66 保留 dispatch_count=1 与消息同事务；本次新增 RT-ADACCEPT-05～08 锁定完整载荷、并发及重启语义，结果见[证据](../testing/evidence/r-20261121-m5.md)。

## 定了什么

- 唯一键不变，不新增租户/身份方案或队列迁移。
- 正文保留原有 trim；scope、task_id 不增加隐式归一化，HTTP 默认值仍由原解析逻辑应用。
- 比较与返回在同一事务完成；Replay 使用库中的全部字段，Conflict 不写消息、不启动新的分流。
- HTTP 保留 operation_conflict 与现有 ID，提示“不同请求载荷”，不回显已有正文。

## 简单设计

受理事务按操作键查询原记录 → 完整载荷相同则返回原记录；不同则返回 Conflict；无记录才插入操作和用户消息。后续执行成功/失败语义仍由独立的 M2 方案处理。

## 没选什么

按会话扩展唯一键会让跨会话同键创建第二次发送，违反本条 409 验收；不将 M2 队列或 M6 SSE 恢复混入本次修复。

## 影响与后续

Store/HTTP 行为、四个新用例与功能地图同步；无迁移，无新增异步任务。全量检查、已知基线失败与是否可推送如实写证据；问题关闭由评审确认。

## 出问题先看

RT-ADACCEPT-05～08、原操作的 request_id/message_id、HTTP 409 code；不要把缺少分流结果误归因为幂等载荷校验。
