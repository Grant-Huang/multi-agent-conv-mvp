# 决策 2026-11-24-acceptance-round-numbering-ar-prefix

| 项目 | 内容 |
|---|---|
| 日期 | 2026-11-24 |
| 来源 | 用户确认（对话：对「验收轮改用独立前缀 AR-N」提议答复「按你的建议来」） |
| 状态 | 生效 |
| 影响范围 | 主线 #2（独立复跑与跨组场景独立验收）的验收轮编号与证据文件命名；不影响实现线任务卡编号（其竞争问题另议） |
| 相关设计 | [五线分工](2026-11-22-five-workstreams.md)、验收记录目录 `docs/testing/evidence/` |

## 背景

五线并行推进（[2026-11-22-five-workstreams](2026-11-22-five-workstreams.md)）后，多个会话在同一仓库并行开任务卡与验收轮，编号取用无集中登记。

## 问题

验收轮与各线任务卡共用 `T-` 序列，并行舰队下竞态撞号频发且已入合并历史：领号前查重（worktree / PR / PLAN）无法防住「检查后、合并前」的并发推送窗口，验收台账出现一号两事。

## 决策依据

- T-81 双占：#241（第 1 线，记忆探针）与 #249（第 4 线，WP7 重启语义）——已入合并历史。
- T-82 险撞：本线 #245 及时避让改 T-83（第 1 线 `cursor/ai-desktop-t82-home-snapshot` 在途）。
- T-87 双占：#257（第 1 线 NexusOps 方案卡）与 #258（本线验收记录）——已入合并历史。
- T-85 双占：#254（本线验收）与 #264（第 4 线实现卡 WP7 方案 C）——已入合并历史。
- 上述各例均可由 PR 标题/分支名核对；来源标「助手观察 + 用户确认采纳建议」。

## 定了什么

1. **主线 #2 的验收轮编号改用 `AR-N` 前缀**（AR-1 起，仅第 2 线使用），与任务卡 `T-` 号彻底解耦：任务卡号表达「做什么工作」，AR 号表达「第几次独立验收轮」。
2. 证据文件命名沿用现风格：`docs/testing/evidence/arN-cross-group-acceptance.md`（如 `ar1-cross-group-acceptance.md`）；PR 标题格式 `docs(testing): AR-N 跨组场景独立验收记录（主线 #2）`。
3. 已合并历史（T-60/63/65/66/80/83/85/87/88 等验收轮）**不回改**；引用旧轮按内容与 PR 号消歧。
4. 实现线任务卡继续用 `T-` 序列；**实现线之间的撞号问题不在本决策范围**（T-81/T-85 双占涉及实现卡，建议各线领号时也建领号台账或分段取号——待相关线自行采纳或用户另行规定）。

## 没选什么

| 做法 | 原因 |
|---|---|
| 全舰队统一领号台账文件 | 跨线协调成本高、依赖各线自觉；本决策先解决第 2 线自身可解耦的部分 |
| 验收轮继续用 T- 序列并加强查重 | 查重防不住并发竞速窗口，T-87 实证失败 |

## 影响与后续

- 第 2 线下一轮起以 **AR-1** 开始计数（对应基线 `8f8d3d2` 及之后）。
- GAP_ANALYSIS / 围栏登记表不涉及编号，无需改动。
- 若实现线后续也撞号，可参照本决策为任务卡引入线内前缀（如 `L4-T-…`），另行决策。
