# 各线领单改由电脑定时任务驱动，不再依赖会话内的 /loop

| 项目 | 内容 |
|---|---|
| 日期 | 2026-11-27 |
| 来源 | 用户确认：<br>- 用户反馈“还是不能长期自动领任务”，现象是“有的领任务，有的不领任务，领了任务的也没完全做完”；<br>- 在“系统定时任务驱动 / Remote Control 推送 / 保留 /loop 加看门狗”三项中选了助手推荐的“系统定时任务驱动”。<br>脚本做法、2 小时间隔与各线错开时间为助手建议，待用户试运行后确认 |
| 状态 | 有效（待用户在本机安装并试运行） |
| 影响范围 | 新增 `scripts/lines/`（脚本、自测、说明）；派工决策第 11 条“拉取”；`docs/fencing/INTEGRATION_PIPELINE.md` 第 6.1 节时刻表 |
| 相关设计 | [scripts/lines/README.md](../../scripts/lines/README.md)（运行方式的权威说明） |

**一句话结论**：每条线用自己的目录，由电脑的 cron 每 2 小时调用一次 `scripts/lines/line-tick.sh`，以非交互方式接着该目录最近的会话跑一轮“同步、查单、认领、推进、写进展”；会话内的 `/loop 2h` 只作补充。

## 背景

派工决策第 11 条（2026-11-27 早些时候）要求各线在会话里运行 `/loop 2h` 定期查单。

## 问题

用户反馈 `/loop` 方式仍然不能长期自动领单：有的线领、有的不领，领了的也没有做完。

## 决策依据

1. **工具事实**（本会话读取 Claude Code 定时工具 `CronCreate` 的说明，`/loop` 基于它）：
   - “Jobs live only in this Claude session … the job is gone when Claude exits”——会话退出即失效；
   - “Jobs only fire while the REPL is idle (not mid-query)”——会话一直在做事时不会触发查单；
   - 循环任务 30 天后自动过期。
   这三点分别对应“有的线不领”（终端关过或重启过）和“领了没做完”（会话停在某处后，没有外部力量再推它一下）。
2. **派单数据**（2026-11-27 约 06:00 UTC 核对 21 张开着的派工单）：16 张有含“认领”字样的留言，未认领的是 3 张 `queued`、无线标签的 #458、第 5 线的 #440；多张已认领的单最后一条留言停在 02:21 UTC，之后没有进展。
3. **CLI 事实**（本会话 `claude --help`，版本以用户本机为准）：`-p` 非交互运行；`-c/--continue` 接着当前目录最近的会话，目录里没有会话时新开一个（已实测）；`--permission-prompts none` 让本该弹窗的操作直接被拒，不会卡住等人。
4. **用户意见**：见“来源”。

## 定了什么

1. **驱动方式**：用户本机 cron 每 2 小时调用一次 `line-tick.sh <线号> <该线目录>`，6 条线错开 10 分钟（:07、:17 … :57），避开整点与半点。
2. **每线一个目录**（建议 `git worktree`），因为 `--continue` 按目录找会话；接着上一轮的会话，保证“做到一半的单”有人接着做。
3. **无人值守的边界**：
   - 未放行的命令一律拒绝，不卡住；
   - 本机 `deny` 强推和 rebase；
   - 提示词要求先重读 `AGENTS.md`，不合并 L1～L3，遇到“先停下来问人”的事项写进 Issue 后停下。
4. **超时、并发与清理**：
   - 单轮超过 100 分钟终止（先 TERM，30 秒后 KILL）；
   - 同一条线只跑一个，上一轮未完则跳过；
   - 残留锁自动清理；退出时总是释放锁。
5. **人工对话**：用户要直接和某条线对话时，先放一个暂停文件，聊完删掉，避免两边同时写同一个会话。
6. **验证**：`scripts/lines/line-tick.test.sh` 用假的 `claude` 覆盖参数、日志、并发跳过、残留锁、超时、暂停、参数校验（20 项）。

## 没选什么

| 做法 | 为什么没选 |
|---|---|
| 只保留会话内 `/loop` | 会话退出即失效、忙时不触发，正是本次问题的原因 |
| Remote Control 推送 | 要求各线会话一直开着，没有解决“终端被关”的问题；可作为补充 |
| 每轮开全新会话（不 `--continue`） | 每轮都要重新读上下文，做到一半的单容易被另起炉灶 |
| claude.ai 云端定时任务 | 各线跑在用户本机，依赖本机的仓库、服务和登录状态，云端会话访问不到 |
| `--dangerously-skip-permissions` | 无人值守时风险过大；改为本机白名单放行常用命令 |

## 出问题先看

- 某线一直没动静：先看 `~/.agentnexus-lines/logs/line-N-日期.log` 有没有“开始 / 结束”记录（没有则是 cron 没触发，检查 crontab、PATH、电脑是否睡眠）；再看是否有暂停文件；再看日志里是否有权限被拒。
- 某线反复超时：看日志中它卡在哪一步，必要时调大 `LINE_TICK_TIMEOUT_SEC` 或拆小派工单。
