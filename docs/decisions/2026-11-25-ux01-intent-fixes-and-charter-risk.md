**一句话结论**：UX-01 基线审查中 4 条高优先级 / 约束类偏离交给桌面线修复（UXFIX-A～D），每张卡以把对应欠账约束改为确定性用例为验收；`docs/PRODUCT.md` 列入风险策略 L3；下一步先在 #270 之前的版本上校准守护者，再铺开其余旅程。

## 背景

宪章 v1.4（#292）新增体验原则 CH-U1～U6。体验地图试点（#294）在 UX-01 旅程上做了第一次产品意图审查，发现 INTENT-2026-001～008。其中 4 条属于“约束”（违反即应阻断）或高优先级，需要实现层修复；另外，改宪章时风险分级只判 L0，与宪章第 7 节“每次修改都要用户确认”不一致。

## 问题

- 首页最显眼的 AI 入口问了得不到回答（CH-U1）。
- 生产界面暴露测试控件（CH-U5）。
- 窄屏看不到工作区对话输入（CH-U1）。
- 有其他会话旧草稿时，新输入的草稿间歇被覆盖（CH-U2）。
- 宪章改动不触发人审（治理缺口）。

## 决策依据

1. 审查报告的证据（`docs/review/product-intent/2026-11-25-ux01-baseline.md`）：
   - INTENT-001：`web/src/App.tsx:646` 写死“问答（模拟，留在桌面）”，无开关；同环境 `/api/health` 显示模型可用。
   - INTENT-003：`web/src/desktop/WorkspaceView.tsx` 约 120～150 行无条件渲染“动作审批模拟”等按钮；证据面板有“身份 alice / bob / carol”“空列表夹具”。
   - INTENT-005：390 宽下工作区对话输入在首屏以下。
   - INTENT-008：E2E-UX01 与完整桌面套件同跑 2 次失败 1 次，返回后为另一会话的旧草稿；加前置清理后连跑 3 次 33 passed。
2. 风险分级实测：`python3 tools/ci/risk_classify.py` 对只改 `docs/PRODUCT.md` 的 #292 判 L0；影子审查同样判 L0（#292 评论）。新增测试 `test_real_policy_charter_needs_owner` 在修改策略前失败（1 failed），修改后 `tools/ci` 114 passed。
3. 用户 2026-11-25 确认：派卡给桌面线、宪章纳入风险策略、先校准。

## 定了什么

- 4 张卡交给桌面线（见下方“简单设计”），每张以对应欠账约束转为确定性用例为准出。
- `config/risk-policy.toml` 的 L3 治理规则加入 `docs/PRODUCT.md`；体验地图与产品意图审查报告仍为普通文档。
- INTENT-002（工作区发送无对话）先核实真实任务是否同样如此，不在本批派卡；INTENT-004、006、007 留在审查台账，随后续旅程一并处理。
- 守护者先做校准：在 #270 合并之前的提交上重跑 UX-01，统计能否检出当时已知的首页问题，再决定是否铺开 UX-02～UX-12。

## 简单设计

### UXFIX-A：首页问答接真实会话（INTENT-2026-001，CH-U1）

| 项 | 内容 |
|---|---|
| 做法 | 首页“问答”走与“＋ 新会话”相同的真实会话接口，回答显示在 S1 浮层（不离开桌面）；模型不可用时显示明确的不可用状态（CH-P8，不静默回退到模拟文本）；删除写死文本，或在 `MOCK_REGISTRY.md` 登记并说明替换计划 |
| 验收（先 Red） | 新增 E2E：首页问答后浮层出现助手回答，且无整页跳转、首页卡片仍在；模型不可达时显示不可用说明。完成后把 UX-01-I5 的首页部分从欠账改为用例 |
| 不做 | 不改工作区发送（INTENT-002 先核实） |

### UXFIX-B：测试控件只在测试模式出现（INTENT-2026-003，CH-U5）

| 项 | 内容 |
|---|---|
| 做法 | 工作区的“动作审批模拟 / 异步 Run 恢复 / 语音模拟 / 跨端续接模拟 / 受理模拟”与证据面板的身份切换、“空列表夹具”，只在测试模式下渲染。测试模式由服务端告知前端（与 `desktop.test_fixtures` 一致，例如经已有的桌面配置或能力接口返回），不另设前端常量 |
| 验收（先 Red） | 组件测试或 E2E：测试模式关闭时上述控件数量为 0；开启时现有 E2E 不变（断言不放松） |
| 不做 | 不删除这些 Mock 面板本身（E2E 仍需要） |

### UXFIX-C：窄屏工作区对话输入在首屏可见（INTENT-2026-005，CH-U1）

| 项 | 内容 |
|---|---|
| 做法 | 宽度小于 768 CSS px 时工作区单栏，任务信息默认折叠，对话输入固定在可视区底部；“助理消息”在窄屏可收起，默认不挤占工作区 |
| 验收（先 Red） | 新增 E2E（390×844）：进入工作区后对话输入的包围盒完全在视口内；草稿恢复不变。完成后把 UX-01-I6 从欠账改为用例 |
| 不做 | 不改宽屏布局 |

### UXFIX-D：旧草稿不覆盖新输入（INTENT-2026-008，CH-U2）

| 项 | 内容 |
|---|---|
| 做法 | 先写确定性复现：另一会话以较高版本写入旧草稿后，本会话在取回草稿前后快速输入并离开再返回。再修 `web/src/desktop/draftStore.ts` 的合并规则：任何一方的文字都不得无提示丢失；冲突时保留本地输入，并提示“另一会话 / 设备有不同的草稿”供用户选择。另核实 PUT 未带 `expected_version` 时直接覆盖他人草稿的行为；若需把 `expected_version` 改为必填，属于 HTTP 接口变更，须先出方案 |
| 验收（先 Red） | 新增 E2E 复现并通过；去掉 `web/e2e/experience.spec.ts` beforeEach 中的草稿清理，完整桌面套件加 UX-01 连跑 3 次全部通过；UX-01-I7 从欠账改为用例 |
| 不做 | 不改草稿表结构（若必须改，另出方案） |

## 没选什么

| 做法 | 为什么没选 |
|---|---|
| 8 条发现一次全部派卡 | INTENT-002 需先核实；004、006、007 为原则类或仅测试环境，随后续旅程处理更省成本 |
| 由审查会话直接改产品代码 | 审查者不应修自己发现的问题（CH-P4 执行者不当自己的裁判的同理）；由桌面线实现、守护者复核 |
| 把 `docs/contracts/**` 也一并列入 L3 | 合理但本次未讨论，作为后续建议 |
| 先铺开 UX-02～UX-12 再校准 | 审查方法未经校准就扩大范围，误报和漏报会被放大 |
