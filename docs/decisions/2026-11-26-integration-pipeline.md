**一句话结论**：
- 待合并 PR 设上限（每线 3 个含 L0；全仓 12 个只数 L1～L3）；
- L0 改动 CI 绿后由作者所在线自动合并，冲突自行合并 master 消除；
- 第 2 线建自建简易合并队列和集成 agent；
- CI 分 T0～T3 四层，按路径分流、合并前做组合验证，高风险改动合并前跑 E2E；
- 测试基于夜间全绿的基线 tag，冻结版本、不冻结开发。

## 背景

2026-11-26 已有六条研发线并行开 PR。现有 CI 对每个 PR 跑全量，浏览器 E2E 只在夜间跑；分支保护要求分支与主干同步，每合并一个 PR，其余 PR 都要重跑。

## 问题

- 待合并 PR 积压，互相冲突，导致 CI 反复重跑。
- 高风险改动合并后才在夜间发现问题。
- 测试会话基于移动中的 master，结果难以复现。

## 决策依据

1. **用户意见**：见“来源”。
2. **代码事实**：
   - `.github/workflows/ci.yml` 的 `on: pull_request / push` 对所有 PR 跑同一组作业（`rust` 含 `cargo test --locked --workspace`），无路径过滤；
   - `nightly-e2e.yml` 仅 `schedule: 30 10 * * *` 与手动触发；
   - `scripts/enable_branch_protection.sh` 设定 `"strict": true`、`required_approving_review_count` 默认 0。
3. **运行事实**：2026-11-26 #409 因 #417、#395 先合并，为跟上主干重跑两次 CI（PR 事件记录）。
4. **平台事实**：GitHub 搜索接口显示本仓库 `owner.type = User`、公开。原生 Merge Queue 是否可用于个人账号仓库未能核实（本环境无法访问 docs.github.com）；助手了解为仅组织仓库可用（**推断**），因此先自建简易队列。
5. **风险策略**：`config/risk-policy.toml` 的 `[approvals]` 只给 L0 “可自动合并”。

## 定了什么

详细规则见权威设计 [INTEGRATION_PIPELINE.md](../fencing/INTEGRATION_PIPELINE.md)，要点：

1. **在制品上限**（第 3 节）：
   - 每线待合并 PR ≤ 3；
   - 全仓 L1～L3 待合并 PR > 12 时各线暂停开新开发任务（L0 不计入全仓数）；
   - 高严重度修复、CI 修复、安全修复例外。
2. **合并**（第 4 节）：
   - L0 CI 绿后由作者所在线自动合并；L1～L3 按审批要求；
   - 冲突由作者合并 master 消除，涉及高风险文件或语义取舍时停下来问人。
3. **队列**：第 2 线建简易合并队列与集成 agent（P1），不批准 PR、不改 L2/L3 业务逻辑。
4. **CI 分层**（第 5 节）：
   - T0 本地自检；
   - T1 按路径分流的 Fast CI；
   - T2 合并前对“主干 + PR”组合验证，L2/L3 加跑 E2E；
   - T3 夜间全量并打基线 tag。
   - 增量测试只按 crate 依赖图。
5. **定时任务分层**（第 6 节）：4 小时、每天、每周、每两周 / 每月各有明确任务和负责方。
6. **冻结版本**（第 7 节）：第 6 线、第 2 线、守护者的测试都基于基线 tag。
7. **实施顺序**：P0（规则 + 巡检统计 + CI 路径分流）→ P1（队列与基线 tag）→ P2（变更范围声明）→ P3（增量测试与合并前 E2E）。

## 没选什么

| 做法 | 为什么没选 |
|---|---|
| 全仓上限 18 个（计入所有 PR） | 6 条线 × 每线 3 个 = 18，全仓上限形同虚设；集成瓶颈来自代码类 PR，改为全仓 12 个只数 L1～L3（用户选定） |
| 立即把仓库迁到组织以使用原生 Merge Queue | 迁移涉及仓库地址、GitHub App 授权、各线配置；先用自建队列验证收益，需要时再迁（助手建议） |
| 新开一条“集成线” | 第 2 线职责本就是集成协调与 CI 健康，避免职责重叠 |
| 函数级增量测试 | 依赖分析不可靠，可能漏测；只做 crate 级 |
| L1 也自动合并 | 现在所有 PR 用同一账号，“审查人不是作者”无法在 GitHub 上实现；待独立审查身份就绪再议 |
| 测试期间冻结 master | 会阻塞开发；改为基于基线 tag 测试 |
