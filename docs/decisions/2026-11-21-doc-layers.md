# 文档分层：宪章与共享契约是刚性层，其余保持柔性；按低冲突方式推进

| 项目 | 内容 |
|---|---|
| 日期 | 2026-11-21 |
| 来源 | 用户确认（方向“认可”，并要求“制定计划，按计划推进”） |
| 状态 | 有效；其中修改 `AGENTS.md`、PR 模板、CI 的部分待单独批准 |
| 相关 | [文档体系整理计划](../DOC_SYSTEM_PLAN.md)、[产品宪章](../PRODUCT.md)、[共享契约](../contracts/README.md) |

- **问题**：产品主线一度分散（2026-11-16～19 约 6 条线并行，11-20 才收敛）；审批、取消、重启、追踪各特性各做一套；`DESIGN.md` 16 天没跟上系统；决策编号多次撞号；很多文档找不到入口。
- **定了什么**（用户确认）：
  - 分层：L0 产品宪章（`PRODUCT.md`，改动要用户确认）→ L1 架构与共享契约（`DESIGN.md` 第 0 节、`contracts/`，先出方案再改）→ L2 特性设计（普通 PR）→ L3 计划与任务卡 → 探索区（有到期日）。
  - 新决策一条一个文件（`decisions/`），`DECISIONS.md` 冻结为历史档案。
  - 推进方式：先加新文件、少动热点文件；新规则只管新内容；CI 规则先警告、后强制；共享契约从下一个里程碑起生效，不打断进行中的工作；不搬目录、不重新编号、不批量改文档头。
- **为什么**：刚性只留给难以回头的东西（定位、非目标、跨特性约定），其余保持可改；用机器检查守边界，而不是靠写文档的人或 agent 自觉。热点文件（`CASES.md`、`PLAN.md`、`features.json`、`DECISIONS.md`）三天内各被改约 60 次，避开它们才不给其他团队添乱。
- **没选什么**：一次性搬目录、全面套模板（约 400 处链接、要改 L3 文件）；把契约追溯到正在进行的里程碑；继续在 `DECISIONS.md` 末尾追加编号。
- **出问题先看**：[文档体系整理计划](../DOC_SYSTEM_PLAN.md) 的阶段状态；新特性是否在 `DESIGN.md` 第 0.3 节登记；新决策是否写进了 `decisions/`。
