## 一句话结论

无人值守的领单任务**禁止**执行 `gh pr merge` 与 `gh api`（合并队列改为「入队→判级→人工批准合并」）；低风险自动任务中，效果为 WorkspaceWrite 及以上且不在 `required_tools` 里的写工具调用**一律拒绝或转审批**；`scripts/lines/**` 提到 L3。

## 背景

2026-11-26 起五线（+第 6 线）并行舰队全速运转，#492 给无人值守领单任务放行了 `gh pr merge`/`gh api`；同日第 2 线合并队列（#433）上线后，队列 agent 具备自动合并他人 PR 的能力。周五深读（评审 #497）发现：写工具（`write_file` 等）没有运行时闸门。Claude Code 权限分类器同日实际拦截了队列 agent 的自动合并尝试（"Merge Without Review"）——平台侧行为与本决策方向一致。

## 问题

1. 队列/无人值守 agent 自动合并 = **自批与越权合并风险**（L1+ 卡可能未经批准入库；撞号/堆叠事故 #462 的教训放大）。
2. 注入的网页/工具描述可驱动模型调用 `write_file` 写工作区外或敏感位置（呼应 R-20261127-H4 符号链接越界，防线不重叠：H4 管路径边界，本决策管「能不能写」）。

## 决策依据

1. 用户确认（2026-11-27「按你的建议来」，采纳评审推荐口径：两条均为「不能」）。
2. 评审复现与推断：R-20261127-M12（#492 放行记录）、周五深读 3（无运行时闸门）。
3. 平台实证：2026-11-27 队列 agent 的 `gh pr merge` 被权限分类器以 "Merge Without Review" 拦截（本线留痕）。
4. AGENTS.md「不得批准自己写的改动」——自动合并他人 PR 在治理上等价于无审批合并。

## 定了什么

1. **合并队列**（#433）：所有等级一律**人工批准合并**；队列只做「入队→判级→催批→落后时更新分支→CI 复检→合后关卡与状态板」。L0 也不再自动合并（修订 #433 卡面「L0 绿即可合并」的口径）。
2. **scripts/lines 配置**：deny 列表加 `gh pr merge`、`gh api`；`scripts/lines/**` 风险等级提到 L3（随 M12 实施卡落地，需 CODEOWNERS 批准）。
3. **写工具运行时闸门**（MCP/工具模块，归第 4 线出方案）：WorkspaceWrite 及以上效果、又不在 `required_tools` 的调用一律拒绝或转审批；先出方案经批准再改。
4. 已在队列等待的 PR（#493/#494/#495/#496 等）不受影响，仍等人工批准。

## 没选什么

- 「L0 绿即可由队列自动合并」（#433 原口径）——平台分类器与评审同向否决，放弃。
- 仅限制 `gh pr merge`、放行 `gh api`——`gh api` 可达同一效果，限制无意义。

## 影响与后续
