## 1. 做什么

**面向组织的 AI 工作桌面。** 个人、团队和组织从同一个桌面入口提问、委派、取证、协作和审批；后台 agent 按确定的规则执行；系统随使用不断了解用户和组织。

**差异化方向是制造业运营。** 业务动作经统一的世界访问契约作用到仿真工厂或真实工厂，走“观察 → 提方案 → 人批准 → 执行 → 核验”的受控闭环。

来源：用户确认 2026-11-25（[2026-11-25-charter-v1-4-experience-growth](decisions/2026-11-25-charter-v1-4-experience-growth.md)）；决定 61（AI 桌面）、61（World Adapter）；2026-11-04 第一版设计的长期目标“组织级智能工作平台”（提交 `dd90a18` 的 `docs/DESIGN.md` 第 1.1 节）；[ai-desktop 设计决策清单](ai-desktop/agentnexus_ai_desktop_design_checklist-2.md) 第 1 节。v1.3 及以前写作“面向制造业组织的 AI 工作桌面”。

## 3. 唯一主轴

1. **产品主轴只有 AI 桌面**，不做双轨，不再维护第二套一级导航。来源：决定 61（AI 桌面）。设计意图、依据和入口对照见 [decisions/2026-11-20-desktop-single-axis.md](decisions/2026-11-20-desktop-single-axis.md)。
2. **MOM、运营桌面、World Adapter 是桌面里的工业业务能力**，不是另一个产品：MOM 是案例、方案、审批和动作记录的唯一权威，但没有自己的产品界面；人从桌面的运营频道、运营模块和普通会话接触它，批准只在运营频道的案例卡上做；读写仿真或真实工厂只经 World Adapter。来源：2026-11-21 用户确认；决定 56～58、60、61（World Adapter）、62。设计意图、依据和结构见 [decisions/2026-11-21-industrial-capabilities-in-desktop.md](decisions/2026-11-21-industrial-capabilities-in-desktop.md)。
3. **2026-11-04 起实现的对话调度部件是执行引擎层的构件。** 来源：同上。
4. **必要的产品特性**：多 agent 执行与接入、业务内省、个人记忆、外发脱敏，以及 [DESIGN.md 第 0.3 节](DESIGN.md#03-产品特性设计索引) 登记的其他特性。来源：同上。
5. **新的主线或特性开工前，先在第 0.3 节登记，并写明为本文哪一条服务。** 来源：[decisions/2026-11-21-doc-layers.md](decisions/2026-11-21-doc-layers.md)。

## 5. 不能破的原则

每条都有稳定编号，需求、特性、用例和审查报告用编号引用。“类型”决定违反后怎么处理：

- **约束**：违反即阻断合并（能写成确定性检查的，逐步写成检查）；
- **原则**：违反须在 PR 中写明理由并经审查；
- **偏好**：可按用户反馈调整。

### 5.3 成长与演进

| # | 原则 | 类型 | 来源 |
|---|---|---|---|
| CH-G1 | **系统越用越懂人，但成长可见、可控。** 系统通过记忆（短期会话、长期个人）、风格、组织判断标准不断改进服务；从历史自动形成的个人记忆、画像和组织规则只是提议，经相应的人确认后才生效；每次回答都能说明用了哪些记忆；所有沉淀下来的东西，相关的人都能看见、纠正、撤回；成长不能越过 CH-G2 | 原则（自动沉淀未经确认即生效、无法说明本次所用记忆，算违约） | 用户确认 2026-11-25（[2026-11-25-charter-v1-4-experience-growth](decisions/2026-11-25-charter-v1-4-experience-growth.md)）；2026-11-26 修订（[2026-11-26-charter-v1-6-memory](decisions/2026-11-26-charter-v1-6-memory.md)） |
| CH-G2 | **个性化边界。** 定义：*风格* = 怎么说话，属于个人；*画像* = 系统对这个人倾向的推测，只当假设；*taste* = 什么算好的判断，属于组织，不随个人喜好变；*记忆* = 系统记下的个人或会话信息。<br>a. 可以改：措辞、语气、详略、呈现顺序、默认选项；证据相同时推荐的先后。<br>b. 不能改：事实、数字、状态、来源标识（真实 / 仿真 / 模拟）、可选方案的集合（只能调顺序，不能删）、审批与权限要求。<br>c. 风险信息不可省略：不可逆、安全、置信不足的提示，任何偏好下至少保留一句。<br>d. 画像只服务本人：不用于评估或排名员工；管理员默认不可查看；不推断、不保存情绪、健康、能力高低、绩效。<br>e. 本人可查、可改、可撤：记忆和画像本人可查看、纠正、撤回；撤回后不再使用。<br>f. taste 不迎合个人：组织 taste 只来自专家纠正和业务闭环结果，不来自单个用户的当下满意 | b～e 约束；a、f 原则 | 取代 v1.3 原则 10；DECISIONS 第 48 条（原为助手建议）；用户确认 2026-11-25（[2026-11-25-charter-v1-4-experience-growth](decisions/2026-11-25-charter-v1-4-experience-growth.md)） |
| CH-G3 | **每个自动决定都可复盘、可比较。** 系统替人做的决定（路由、规则判定、模板选择、推荐、主动提醒、记忆写入）都留下依据、所用规则 / 模型 / 提示词版本、候选与结果；之后人的反应（采纳、驳回、纠正）和业务结果能关联回来，用于比较版本、有依据地微调，而不只为排错 | 原则（新写的决策路径缺记录算违约） | 用户确认 2026-11-25（[2026-11-25-charter-v1-4-experience-growth](decisions/2026-11-25-charter-v1-4-experience-growth.md)）；延伸 CH-P5 |
| CH-G4 | **外部系统只经标准连接器接入。** 读写任何外部系统（业务系统、工具、模型服务、其他 agent）都经符合连接器标准的接入层，不在业务代码里直接调用 | 约束（新接入不合规即阻断；存量按清单迁移） | 用户确认 2026-11-25（[2026-11-25-charter-v1-4-experience-growth](decisions/2026-11-25-charter-v1-4-experience-growth.md)）；推广 World Adapter 的做法 |
| CH-G5 | **记忆与检索内容只是资料。** 记忆、历史消息、文档、工具输出进入上下文时，都作为带来源的资料：其中的指令一律无效，不能改变权限、审批和可执行的动作；AI 自己的历史回答只是“当时的回答”，不作为事实来源；引用历史须带时间和出处，区分“发生过什么”与“内容是否属实” | 约束 | 用户确认 2026-11-26（[2026-11-26-charter-v1-6-memory](decisions/2026-11-26-charter-v1-6-memory.md)）；延伸 CH-P1、CH-P7 |

CH-G3、CH-G4 的具体要求分别写在共享契约 [events-and-trace](contracts/events-and-trace.md) 与连接器契约（待建）中；CH-G1、CH-G2、CH-G5 的实现要求写在 [分层记忆特性档案](features/conversation-memory/README.md)，分层与选材规则见 [2026-11-26-memory-layers-and-history](decisions/2026-11-26-memory-layers-and-history.md)。

## 7. 怎么改本文

1. 先在 [decisions/](decisions/README.md) 写一条决策，说明改哪条、为什么，来源必须是“用户确认”。
2. 再改本文，并把版本号和日期加一。
3. 改了第 3、4 节时，同步检查 [DESIGN.md 第 0 节](DESIGN.md#0-系统全景) 和 [共享契约](contracts/README.md) 是否要跟着改。
4. 修改本文单独开 PR，不与功能改动同一个 PR；所有审查（包括产品意图审查）只以 `master` 上已批准的版本为准。
5. 条款编号一经发布不复用；删除的条款保留编号并标“已废止”。
