## 🔴 高优先级

### R-20261110-H1（P1，已复现，L2）已激活的 agent 可被改写接入地址，绕过审批
- 位置：`crates/runtime/src/admission.rs:712-748`（set_binding 阶段限制为 `Contracted | Active`，714 行）；`crates/server/src/admission_api.rs` 的 `activate` 处理器先 `set_binding` 再 `activate`。
- 违反：I2（约束对所有入口生效）、I6（外部内容不得改变工具/执行目标）；设计意图是“Trusted 须人工审批后才能激活”。
- 失败场景：agent 已被审批并激活（Trusted）。任何调用方再 `POST /api/admission/agents/{id}/activate`，body 里给出新的 endpoint：set_binding 成功并落库，随后 `activate` 因阶段不是 Contracted 返回 409。调用方看到错误，但 ledger 里的 endpoint 已被改写；下一次 `register_a2a`（例如重启后的注册）会把任务发往新地址，且没有重新审批、没有 epoch 变化。地址不限制内网（可指向 `169.254.169.254` 之类）。
- 影响：已审批 agent 的执行目标被静默替换；返回 409 的接口产生了副作用（违反 I5 的精神）。
- 建议：见交接清单 1；另在 `set_binding` 里校验 endpoint 主机不是回环/链路本地/私网（或要求配置白名单）。
- 验收测试：Given agent 已激活且 binding=good，When 对其再调 activate（新 endpoint=evil），Then 409 且 binding 仍为 good，ledger 无 `admission.bound` 新事件。
- 复现片段（临时测试，已删除，供改成正式测试，放在 `crates/runtime/tests/admission.rs`，复用其中的 `ledger()/admit()/scores()`）：
```rust
admit(&l, "t1", TrustLevel::Trusted, scores(1.0, 1.0, 1.0));
l.set_binding("t1", A2aBinding{endpoint:"https://good.example/run".into(), role:"general".into(), agent_type:"ext".into(), max_concurrent:1}).unwrap();
l.set_binding("t1", A2aBinding{endpoint:"http://169.254.169.254/run".into(), role:"general".into(), agent_type:"ext".into(), max_concurrent:1}).unwrap(); // 目前成功
assert!(l.activate("t1").is_err());
assert_eq!(l.get("t1").unwrap().binding.unwrap().endpoint, "https://good.example/run"); // 目前失败
```
- 运行结果：`assertion left == right failed: 接入地址不应被改写 left: "http://169.254.169.254/run" right: "https://good.example/run"`。HTTP 层只读了处理器代码，没有起服务实测。
