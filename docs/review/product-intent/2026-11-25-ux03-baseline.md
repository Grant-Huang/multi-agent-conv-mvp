## 1. 结论

- **CH-U2 成立**：委派后留在桌面，首页输入立即清空可用；后台运行时可进出 SMT-03 工作区；无整页跳转（E2E-UX03）。
- **CH-U3 部分成立**：委派的任务出现在“我的工作”并更新为“已完成”；但**完成时没有任何助理消息**，首页受理提示仍停在“后台处理中”。
- **CH-P8 不成立（高）**：从“我的工作”卡片打开委派的任务，工作区显示的是 SMT-03 的模拟内容（“执行中（模拟）”“质量批次 SMT-03”“桌面首页 Mock”），看不到这件事真实的结果；真实结果只能从受理提示的“打开任务”或侧栏“最近”进入会话才看得到。
- **CH-U5 不成立**：受理提示显示 `task-…`、`conv-…` 原始编号；右侧任务面板显示 `VERIFYING`、`RUNNING`。

## 3. 发现

### INTENT-2026-014　从“我的工作”打开委派的任务，看到的是模拟内容（高）

- **违反**：CH-P8（约束：真实、仿真、模拟数据始终可辨，不静默回退到模拟）；CH-U1、旅程成功标准“做完后能直接看到结果”。
- **证据**：路线 C。代码事实：`web/src/desktop/WorkspaceView.tsx` 第 96～103 行任务信息写死为“执行中（模拟）／质量批次 SMT-03／桌面首页 Mock”，对任何任务都一样；真实任务 `GET /api/tasks/{id}` 返回 `status: COMPLETED` 和产物 `reports/verification.md`。
- **设计依据**：DESIGN 第 2 节导航表“首页卡片、关注任务、历史任务 → 共用按 Task ID 打开逻辑”；第 6 节“首版从 `TaskRecord.result`、核验和任务事件呈现可用结果”。
- **建议**：工作区任务信息、执行摘要按 Task ID 读取真实任务（状态、目标、结果与证据）；只有夹具任务（如 SMT-03）显示模拟内容并标“模拟”；卡片与受理提示的“打开任务”进入同一视图。
- **与已有发现的关系**：与 INTENT-2026-009（同一任务各处状态不一致）根因相近（工作区状态写死），建议同一实现者处理。

### INTENT-2026-015　任务完成时没有主动告知（中）

- **违反**：CH-U3（把重要的推到面前）；DESIGN 第 7 节“任务完成和关注建议更新消息及相关卡片”。
- **证据**：路线 B。任务已完成，卡片更新为“已完成”，但助理消息仍为原 3 条；首页受理提示仍为“后台处理中（已受理）”。
- **建议**：任务完成（或需要用户输入、失败）时，在助理消息里加一条普通优先级消息，带“查看结果”入口，按第 7 节规则不抢焦点；首页受理提示同步为完成状态或收起。

### INTENT-2026-016　输入为空时点“委派任务”会代用户委派默认任务（低）

- **违反**：CH-U1 的“委派”应是用户交代的事（推断）；宪章没有直接条款写“系统不得替用户编造任务”，**属于条款空白**，供宪章下次修订参考。
- **证据**：路线 D；代码事实 `web/src/desktop/S1AskBar.tsx` 第 32 行 `text.trim() || "继续调查并整理证据链"`。
- **建议**：输入为空时“委派任务”按钮不可用，或提示“先说说要做什么”。

### 新增证据（已有发现）

- INTENT-2026-004（内部术语）：受理提示显示 `task-…`、`conv-…`；任务面板显示 `VERIFYING`、`RUNNING`；工作区标题为“任务 task-70fd…”。
- INTENT-2026-009（状态不一致）：同一委派任务，卡片“已完成”、受理提示“后台处理中”、工作区“执行中（模拟）”。

### 符合项

- 委派不打断当前工作，首页输入立即可用（CH-U2、CH-U1）。
- 委派的任务自动出现在“我的工作”，状态最终更新（CH-U3 的卡片部分）。
- 真实结果在会话中可查看、可下载，有执行者与工具调用证据（CH-P5）。

## 4. 局限

- 审查者参与了宪章与 UX-01、UX-02 审查，读过部分前端源码，不是盲测；每周守护者会以盲测方式复查。
- 只覆盖 1440 宽。
- 模型为本地模拟服务，任务几秒内完成，无法检验“长时间运行”时的进度呈现、失败与需要输入的分支。
- 夹具重置不会清掉服务端真实任务，“我的工作”里会留下多次运行的同名任务（授权例外 EX-02，不算偏离）。
