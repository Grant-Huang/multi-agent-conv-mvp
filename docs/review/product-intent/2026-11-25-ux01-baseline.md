## 1. 结论

- **CH-U2 保护工作连续性：成立。** 草稿、任务、位置在专注切换、设置往返、离开桌面再返回后都恢复；全程没有整页跳转。已写成确定性用例 E2E-UX01（通过，10 步，0 次整页跳转）。
- **CH-P8 真实 / 模拟可辨：成立。** 卡片、状态、受理结果都标“模拟”。
- **CH-U1 对话随时可达：输入框始终在，但问了得不到回答**；窄屏下工作区输入被挤出首屏。
- **CH-U5 用户不需要理解系统内部：多处违反**，生产界面暴露测试控件与内部术语。
- **CH-U3 重要的推到面前：存疑**，最紧急的事项只在侧栏。

## 2. 三次探索的路线

| 次 | 设备 | 路线（agent 自选，只给目标） | 是否完成目标 |
|---|---|---|---|
| 1 | 1440 宽 | 首页卡片 → 工作区 → 证据 → 写草稿 → 专注 → 设置 → 返回桌面 → 再进入 → 发送调查请求 | 部分：找到异常与证据，连续性好；**请求得不到 AI 回答** |

## 3. 发现

### INTENT-2026-001　首页“问答”没有 AI 回答（高）

- **违反**：CH-U1（约束：对话随时可达，问了应有回答）。
- **证据**：首页输入“SMT-03 良率是不是有异常？”点“问答”，只出现绿字“问答（模拟，留在桌面）：…”。源码 `web/src/App.tsx:646` 写死该文本，没有任何开关，生产模式同样如此。同一环境的 `/api/health` 显示模型服务可用，侧栏“＋ 新会话”走真实会话接口。`docs/ai-desktop/MOCK_REGISTRY.md` 未见这个模拟回复的单独登记（第 34 行仅把“S1 浮层”列为运营 Mock 的受影响位置）——**待核**，若未登记还违反 CH-P9。
- **建议**：首页问答接入真实会话接口（与“新会话”同一路径），保留“模拟”标识只用于确实未就绪的后端；在 MOCK_REGISTRY 登记或注销。
- **需要谁决定**：桌面线负责人；是否作为下一张卡优先处理。

### INTENT-2026-002　任务工作区“发送”后没有对话（高）

- **违反**：CH-U1。
- **证据**：在 SMT-03 工作区发送“帮我分析 SMT-03 良率下降的原因”，输入框**下方**出现“已受理（模拟）：…”，没有回答，也没有对话记录。SMT-03 是夹具任务；真实任务的工作区是否有对话本次未核实。
- **建议**：先核实真实任务的工作区对话；夹具任务至少走与真实任务相同的对话展示，避免演示路径与真实路径体验不一致。

### INTENT-2026-003　生产界面暴露测试控件（高）

- **违反**：CH-U5、CH-U4；与 T-88（#270）“生产界面去测试控制”的目标不一致。
- **证据**：工作区固定显示“动作审批模拟”“异步 Run 恢复”“语音模拟”“跨端续接模拟”“受理模拟”按钮（`web/src/desktop/WorkspaceView.tsx` 约 120～150 行，未见开关）；证据面板顶部有“身份 alice / bob / carol”切换与“空列表夹具”按钮（开关情况本次未核实）。
- **建议**：这些控件只在测试模式（`desktop.test_fixtures` 或前端等价开关）下渲染；E2E 改用 API 触发。

### INTENT-2026-004　界面暴露内部术语（中）

- **违反**：CH-U5（原则）。
- **证据**：“O-Agent 执行摘要”“草稿与作用域按 Task 隔离（A2）”“上下文作用域”“纠正关联”“真实 ACL”；证据状态显示英文代码 `ok / failed / revoked / expired`；“固定任务 TASK-2026-018”重复两行；来源显示“桌面首页 Mock”。
- **建议**：按用户语言改写（如“执行进度”“已撤回”“已过期”）；阶段编号（A2）只留在文档。

### INTENT-2026-005　窄屏工作区对话输入不在首屏（中）

- **违反**：CH-U1（约束）；mom/UI_UX_PRINCIPLES UI16。
- **证据**：390 宽下进入工作区，S2 把屏幕切成两条窄栏，对话输入被挤到首屏以下；底部约一半被“助理消息”面板占据。草稿仍能恢复（CH-U2 成立）。
- **建议**：窄屏下默认单栏（任务信息折叠），对话输入固定在底部；助理消息在窄屏改为可收起。

### INTENT-2026-006　最紧急的事项不在首页主区（中，存疑）

- **违反**：CH-U3（原则：把重要的推到面前）。
- **证据**：右侧“助理消息”里有“紧急 · 产线联锁提醒：Line-A 安全联锁触发，请优先确认”，首页“为你关注”为空。两处数据来自不同夹具，真实环境是否同样如此未核实。
- **建议**：明确 P0 / P1 事项在首页主区的呈现规则（例如“为你关注”首位，或首页顶部横幅），写进 CH-U3 的设计层。

### INTENT-2026-007　夹具会话出现在用户可见位置（低，仅测试环境）

- **违反**：CH-U5。
- **证据**：侧栏“最近”出现“桌面首页 fixture”，手机顶栏标题也显示它；每调用一次快照夹具重置就新增一条。生产环境默认 `desktop.test_fixtures=false`，不受影响。
- **建议**：夹具会话不进“最近”列表，或复用同一会话。

### INTENT-2026-008　有其他会话的旧草稿时，新输入的草稿间歇被覆盖（高，根因未定位）

- **违反**：CH-U2（约束：切换时保留草稿）。
- **证据**：E2E-UX01 与完整桌面套件（`desktop.spec.ts`）一起跑时，2 次中 1 次失败：离开桌面再返回后，工作区输入框是 E2E-ADMEMW 在**另一个浏览器会话**写入并留在服务端的“纠错时应保留的草稿”，而不是本次刚输入的内容（断言在 `web/e2e/experience.spec.ts` 返回后的草稿检查处）。单独跑 UX-01、或只与 E2E-ADMEMW / E2E-ADSCOPE 配对各跑 3 次，均未复现；人为把取草稿请求延迟 1 秒、输入后立即离开，也未复现。说明触发条件与整套用例积累的服务端草稿版本或时序有关，根因未定位。另观察到：本地新输入以未带 `expected_version` 的 PUT 直接覆盖了另一会话的服务端草稿（“后写者胜”，另一会话的内容无提示丢失）。
- **相关代码**：`web/src/desktop/draftStore.ts` 的 `loadDraftRemote` 与 `pushDraft`（T-86 草稿上云，服务端权威加乐观版本）。
- **处理**：E2E-UX01 把“服务端无他人旧草稿”写成前置条件（先按当前版本清空 SMT-03 草稿），只检验本旅程自身约束；该场景单列为约束 UX-01-I7，标欠账。加前置条件后完整桌面套件加 UX-01 连跑 3 次，33 个全部通过。
- **建议**：桌面线定位根因并修复；修复后去掉前置条件中的清理步骤，把 UX-01-I7 改为确定性用例（另一会话先写旧草稿，本会话快速输入后离开再返回，断言新内容保留，且跨会话冲突有提示）。

## 4. 独立性与局限

- 审查者参与了宪章和治理文档的起草，且本会话早先读过 `FEATURE_MAP.md` 与部分前端源码，**不是“不知道正确路径”的盲测**。长期运行的守护者应使用独立会话与独立提示词。
- 三次探索变化的是路线和设备，不是同一路线的随机重复；成功率样本很小。
- 环境为 Mock 数据与本地模拟模型；体验证据为“模拟用户证据”，需与真实用户反馈对照。
- 计划中的校准（在 #270 之前的版本上跑同一旅程，检验能否发现当时首页的问题）**本次未做**，列入下一步。
