## 1. 结论

- **旅程主目标无法完成（CH-U2、CH-N2，高）**：对话里的任务完成后，没有任何入口进入该任务的工作区或专注模式；设计要求的“展开工作区”未实现（仓库中搜不到该文案）。
- **对话草稿不保存（CH-U2，高）**：离开对话再回来，写了一半的消息丢失。
- **对话页仍是 T-88 之前的旧壳（CH-U4、CH-U5，中）**：右侧“任务｜内省｜助手｜节点”四页签、“开发者模式”，进度列表直接显示工具调用的原始参数。
- **成立的部分**：在对话里展开右侧任务详情（执行者、路由、事件、结果、证据），对话输入与草稿不受影响，无整页跳转（E2E-UX04）。

## 2. 路线

| 路线 | 做法 | 结果 |
|---|---|---|
| A | “＋ 新会话”，发“写一份关于本地小模型选型的简短报告，保存成 Markdown”，等完成 | 会话中出现“任务结束：COMPLETED”、产物 `reports/verification.md` 的“查看 / 下载”。展开进度列表可见“第 1/6 步：调用工具 write_file，参数 {\"path\":…,\"content\":…}”。**没有“展开工作区”“专注”之类入口**。右侧为“任务 1｜内省｜助手｜节点”四页签与“开发者模式：关” |
| B | 在该对话输入“再补一段关于功耗的对比”（不发送），点右侧任务条目 | 右侧展开任务详情（执行者、路由“类别 L4 · 风险 medium”、事件、执行结果、证据、审查）；对话输入草稿不变 |
| C | 同 B 写草稿后，点左栏“我的桌面”→ 打开 SMT-03 → 返回桌面 → 从“最近”回到该对话 | **输入框为空，草稿丢失** |

另试：首页 S1“问答”的回复只是一行状态文字“问答（模拟，留在桌面）：…”，也没有“展开工作区”（与 INTENT-2026-001 同源）。

**排除的误报**：一次探索中首页“我的工作”只剩一张卡、SMT-03 消失。核实为测试环境重启后未重置快照夹具（`POST /api/desktop/v1/snapshot/fixture/reset` 后恢复），属于授权例外 EX-02 的测试数据问题，不算偏离。

## 3. 发现

### INTENT-2026-017　从对话 / 首页浮层无法进入任务工作区（高）

- **违反**：CH-U2；反目标 CH-N2（“任务与上下文连续的工作区”，而不是互不相通的页面）。
- **证据**：路线 A；`grep -rn "展开工作区" web/src` 无结果。设计 DESIGN 第 2 节：“浮层「展开工作区」：沿用 Conversation ID。已有 Task 时打开任务……返回浮层”；“S1 委派：用户主动展开工作区后进入任务”。
- **影响**：同一任务的结果在对话里，证据面板和专注模式在桌面工作区，两边不通；结合 INTENT-2026-014，从桌面卡片进去还看不到真实结果。
- **建议与派工**：对话中的任务卡与 S1 受理提示提供“展开工作区”，按 Task ID 打开同一工作区，返回回到来源对话。→ 第 1 线 [#313](https://github.com/Grant-Huang/multi-agent-conv-mvp/issues/313)（UXFIX-J，依赖 #303）。

### INTENT-2026-018　对话页仍是旧四页签与原始工具参数（中）

- **违反**：CH-U4、CH-U5。
- **证据**：路线 A、B；`web/src/App.tsx` 约第 825～835 行 `TabButton` “任务 / 内省 / 助手 / 节点”。T-88（#270）只整治了首页；校准盲测已把同一面板列为问题（[校准报告](2026-11-25-calibration-pre-t88.md) 第 3.2 节第 2 项“部分检出”），说明当时的整治范围有缺口。
- **建议与派工**：对话页右侧与首页一致；内省、节点、助手退到设置或开发者模式；进度用用户语言，原始参数下沉一层。→ 第 1 线 [#315](https://github.com/Grant-Huang/multi-agent-conv-mvp/issues/315)（UXFIX-L）。

### INTENT-2026-019　对话输入不保存草稿（高）

- **违反**：CH-U2（约束：切换时保留草稿）。
- **证据**：路线 C；`web/src/components/ChatView.tsx` 未使用草稿存储（文件中无 `draft`），而 `draftStore.ts` 与草稿 API 已支持 `kind = "conv"`。
- **建议与派工**：对话输入接入草稿存储，与工作区一致。→ 第 1 线 [#314](https://github.com/Grant-Huang/multi-agent-conv-mvp/issues/314)（UXFIX-K，与 #302 的合并规则一致）。

### 符合项

- 对话内任务进度、结果、产物查看与下载可用；任务详情按需展开（CH-U4 的“逐层展开”部分）。
- 查看任务详情不打断对话（E2E-UX04）。

## 4. 局限

- 非盲测；只覆盖 1440 宽；模型为模拟服务，任务几秒完成，长任务与失败分支未覆盖。
- 未覆盖“专注模式内再退回”的细节，因为入口不存在；入口上线后需重跑本旅程。
