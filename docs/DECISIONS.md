# 决策记录

本文件统一记录项目里"定下来的事"，方便以后回顾和排查问题：当时为什么这样做、谁定的、现在状态如何、要撤回该怎么做。
2026-11-18 用户决定：决策记录统一放在本文件。
计划和进度写在 [PLAN.md](PLAN.md)，架构写在 [DESIGN.md](DESIGN.md)；这里只记决定本身，详细数据用链接指过去。

## 怎么写

- **用简单的话**：不熟悉上下文的人也能看懂。第一次出现的术语，在该主题开头解释。
- **一条一个决定**，包含六栏：编号、日期、决定了什么、为什么、决定方、现在的状态 / 怎么撤回。
- **编号**：主题前缀 + 序号，例如 `FT-D1`。编号只增不改；决定被推翻时不删旧条目，在状态栏写"已被 X 取代"，再新增一条。
- **决定方**：
  - **用户**：用户明确说了；
  - **用户采纳**：助手提出，用户同意或照此推进；
  - **助手建议**：已写进计划，但用户还没有明确表态。有争议时以此为准，不能当成已确认；
  - **数据**：由实验数据直接得出，没有单独确认。
- **新主题**：在下面的索引里加一行，再新增一节。

## FT 前台提速

计划和实验数据见 [PLAN.md 的 FT 一节](PLAN.md)。年份均为 2026。

先说清几个词：
- **前台判断**：用户发来消息后，先由模型决定"直接回答、追问、派任务还是跟进已有任务"。
- **路由**：决定派任务后，再判断"交给谁（角色）、要哪些工具、风险多大、属于 L1–L4 哪一类"。
- **L1–L4**：由"需不需要取数工具"和"需不需要生成文档"两个问题组合而成。代码注释里叫"JEV 任务分类"（`crates/core/src/lib.rs` 的 `TaskClass`），**和 TypeSafe AI 的 Jev 模型无关**，只是同名。
- **开 / 关思考**：模型先写一段推理再给答案，准确率可能更高，但慢很多。
- **E0～E7**：实验配置组，定义见 `crates/server/src/bin/eval.rs` 的 `--variant`。E0 开思考，E1 关思考，其余在这两组基础上加某个手段。
