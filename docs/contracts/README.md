# 共享契约

| 项目 | 内容 |
|---|---|
| 层级 | D1（见 [DEV_STANDARD.md](../../DEV_STANDARD.md) 第 2、3 节） |
| 状态 | 三份均为**草案**，内容待用户确认后才生效 |
| 生效方式 | 确认后从下一个里程碑起约束新任务卡；进行中的工作不追溯，偏离处记录下来，在里程碑结束时收敛 |

## 什么是共享契约

多个特性都要用到、而且必须一致的约定，只在这里写一次。特性设计**引用**契约，不重新定义。特性需要偏离契约时，先改契约（要出方案、经用户批准），再改特性。

契约只写**不变量**（任何实现都必须满足的规则）和最小的字段约定，不写实现细节。每条不变量要能写成验收用例。

## 每份契约的结构

1. **范围**：适用于哪些特性。
2. **现状**：各特性现在怎么做的，附代码或文档位置。
3. **已确认的不变量**：来自用户已确认的设计或决策，注明来源。
4. **建议补充的不变量**（助手建议）：未经用户确认，确认后移到第 3 部分。
5. **待决定**：需要用户拍板的问题。
6. **验收**：每条不变量对应的用例编号（写用例时补）。

## 怎么改

- 改契约要出方案、经用户批准，并在 [decisions/](../decisions/README.md) 记一条决策。
- 确认后把“草案”改为“有效”，在 [DESIGN.md 第 0.3 节](../DESIGN.md#03-产品特性设计索引) 相关特性的设计里加上对契约的引用。
