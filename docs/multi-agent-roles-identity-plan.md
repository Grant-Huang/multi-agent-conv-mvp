## 2. 范围

**做**：统一服务端身份层（Principal 抽象 + 会话解析 + 授权范围），A7 过滤在桌面读模型与执行入口落地，撤回后缓存/预览清理；B1 按已声明路径实现（浏览器会话凭证）。范围以契约已确认不变量为界。

**不做（明确出界）**：
- 真实登录的排期与选型（SSO/密码存储）——契约「待决定 1」明确本轮不排期，仅在 S4 预留接口位；选型需用户单独拍板。
- 生产身份与角色映射（A6）——生产写入未开放；M3 前再定。
- 组织范围的具体授权模型（第 5 线 REQ-03/5.4 的设计物；本方案只预留 scope 字段）。

## 3. 分期

| 期 | 内容 | 交付物 | 验收 |
|---|---|---|---|
| **S1 身份层地基** | `Principal { id, kind: fixture|real, display_name }` 服务端抽象；axum 中间件统一解析：真人经浏览器会话（HttpOnly cookie + Origin 校验，B1），夹具头 `x-desktop-principal` 仅在显式开启的测试模式生效（B4 测试身份标注保留）；现有 `principal_or_local` / desktop_acl 的取身份逻辑收敛到该层（行为兼容，测试不放松） | `server/src/identity.rs` + 中间件；RT-IDEN-01（夹具与真人解析）、RT-IDEN-02（生产模式拒绝夹具头） | 既有 ACL/记忆作用域用例全绿（行为兼容） |
| **S2 授权范围与 A7 过滤** | `scopes` 契约化（read/approve/manage + 预留 org_scope 字段）；A7 过滤以一个通用策略入口落地：桌面读模型（会话、记忆、证据、任务）按 principal 过滤——desktop_acl 推广为通用 `authorize(principal, resource) -> Decision`；查询/引用/检索逐面接入 | 过滤中间件/查询参数注入；RT-IDEN-10～（逐面：未授权查询返回空/403 而非泄漏内容） | 契约 A7 上半（过滤）逐面用例 |
| **S3 撤回与清理** | 权限撤回（ACL revoke 已有）→ 证据预览与缓存失效：撤回事件挂现有事件总线，读模型侧失效缓存 | RT-IDEN-20（撤回后预览不可访问、缓存条目失效） | 契约 A7 下半（清理） |
| **S4 真实登录**（排期待契约「待决定 1」解除后单独立项） | 浏览器登录会话 → 真人 Principal（kind=real）；夹具身份迁移方案届时另定 | 登录端点 + 会话管理；A6 生产身份映射解锁 | 契约待决定 2 届时决策 |

## 4. 对其他线的解锁顺序

1. **S1+S2** → 解锁第 3 线 M4：业务写批准可绑定真实操作者（A6 前半：操作者身份存在），MOM 动作记录的 `decided_by` 从夹具名升级。
2. **S2**（org_scope 字段就位）→ 解锁第 5 线 REQ-03 / 5.4：组织范围读模型有了统一的过滤入口。
3. **S3** → A7 完整生效（通知/检索同样过滤）。
4. **S4**（另行立项）→ A6 生产写入前置完成。

各线在解锁前如需「身份形态」的应用层试验，一律用夹具身份并按 B4 标注「测试身份」，不得自建身份解析。

## 5. 风险与非目标

- **兼容风险**：现有 `x-desktop-principal` 测试口径被 S1 收敛后，各线在途测试不受影响（测试模式显式开启即兼容）；生产模式默认拒绝夹具头。
- **不做** SSO/密码学选型、组织授权模型设计、生产身份映射（各自出界，见第 2 节）。
- 不合并 Desktop 审批网关与 OpsCase 两入口（B3）。
