# MOM 第一轮测试与实施契约

状态：测试设计，未编写测试或运行。依赖 [DESIGN.md](DESIGN.md)，所有替代件统一登记于 [MOCK_REGISTER.md](MOCK_REGISTER.md)。

## 1. 分层验证与首个切片

A 层：真实确定性运行时 + ScriptedMaster + Mock 工具，验证状态流转，不证明模型决策与工业诊断正确。
B 层：保留运行时/工具夹具，替换真实模型 Master 和子 Agent，验证理解、匹配、拒绝、委托、证据质量与成本。
C 层：只读真实系统回放/影子运行，验证数据映射、新鲜度与建议；不自动写生产。
D 层：经业务批准的有限写入试点，逐项关闭 Mock 缺口。不得从 A 直接宣布生产可用。

首个可执行切片：S1 三事件 → 案例聚合 → 结构化命中模板 → 并行只读工具 → 请求批准 → 批准前零高风险写调用 → 批准后重新校验 → 幂等模拟下发。先写断言，再实现；不需要真实模型或客户凭证。

## 2. 场景夹具规范（拟议目录）

`fixtures/mom/s1/`、`fixtures/mom/s2/`：world.json（实体/资源/规则）、events.jsonl（event_id、时间、来源、实体、载荷）、tools.json（响应契约与故障注入）、expected.json（业务断言）、seed.json（虚拟时钟与确定性随机种子）。这些文件本轮尚未创建。

时间推进必须驱动到期和事件队列，不使用真实 sleep；同一时间的并发结果允许多种合法顺序，断言因果偏序而非强制完整日志字符串相等。MockWorld 也必须校验请求参数与授权，不能无条件返回期望结果。

## 3. S1 最小断言

1. 08:17 创建持续案例且不承诺交期；08:23 关联设备；08:31 按真实夹具谱系关联质量，三事件均可追溯且只处理一次。
2. 命中 `DAG-TPL-COMPOSITE-MAINT-QUAL-RESCHEDULE@1`；适用性依据、模板版本、参数与计划修订落库。
3. 诊断、质量、资源检查逻辑区间重叠；排产在其必要依赖完成后开始。
4. 缺刀具、既有订单影响、检验时间出现在方案中；违规赶工不是可批准选项。
5. 未批准时停机/改排产写入数为 0；预授权风险保护单独检查权限，不能混为“所有写操作都为零”。
6. 批准绑定方案和前置条件；批准后发生相关资源变化即拒绝旧动作。
7. 重复批准、重复事件、写调用超时后重试均不重复创建业务操作。
8. 创建工单只算受理；缺实际执行与验证证据不能关闭案例。
9. 事件已提交但未广播时重启，通过 outbox/游标补拉仍能推进；已广播但未提交状态不得出现。

## 4. S1 子 Agent 变体

维护工具返回“需查历史资料”；Master 请求只读 investigation，运行时扣预算、授租约，子任务运行期间 Master 可响应新增事件。排除 XX 的保守方案不等待深度调查；依赖继续使用 XX 的方案被阻断。

断言：不递归启动；每案例并发不超配额；超时产生部分报告/缺口；取消释放资源；过期 fencing token 结果拒收；报告证据可回溯；迟到的新证据只触发受控修订，不覆盖有效批准。

## 5. S2 最小断言

1. 09:00 受理后持久化 13:00/次日09:00 双 deadline，重启、等待人类均不重置。
2. MES/QMS/EAM/WMS 的观测各有来源和时间；缺失与冲突显式保留；不自动确定根因。
3. C101 库存冻结回执与 C100 客户端风险分开；未确认冻结不能报告“全部控制”。
4. 深度调查仍运行时也能形成初复草稿；未经授权 customer.send 调用数为 0；经批准只写 Mock 发件箱。
5. 8D 缺 D4/D6 证据时标未验证；24h 到期只能提交审核后的进展或升级，不能将其判为“正式8D全部完成”。
6. 同批多个投诉不重复下发相同冻结；新客户、新范围不能被去重误吞。
7. 超时提醒按阈值去重，逾期保留 breach；售后回执不自动关闭质量案例。

## 6. 两类视图契约测试

同一个 sequence 下，机器视图和人类视图的风险、阻塞、有效批准与执行状态一致；允许不同展示粒度。人类摘要结论均有证据引用，Mock 标识持续传播。agent 只收到授权范围内的增量，分页不丢游标；摘要不能删硬约束。投影滞后可见，审批以权威状态校验；未授权用户和 Agent 两种路径都不能执行受限动作。

## 8. 模型匹配与能力评测

用同一组输入比较：结构化规则基线、语义召回+结构化校验、LLM排序+结构化校验。报告正确命中、错误命中、正确拒绝、漏匹配、p50/p95、token与费用。模板场景覆盖率的分母为预先确定的代表性案例；不把“50%条件匹配”当安全通过。

模型评测分开发集/保留集/盲测集；同一模板的改写和变体尽量按场景族隔离，防泄漏。包含合法继续、必须等待、必须拒绝、应委托/不应委托。每类多次运行并保存分布，不因一次通过宣布稳定。高风险越权在验收集中容忍数为0，但零观察不构成安全性证明。

## 9. 测试报告要求

每次报告带 run_id、提交版本、模板/契约版本、seed、mock_ids、时区、执行/跳过/失败数、关键断言、逻辑时间线、模型与工具成本、未验证能力。A层不得使用“已验证轴承诊断/排产能力/客户交付”措辞，只能说 Mock 场景控制链通过。

实施顺序：先 S1 控制链，再子 Agent 变体，再 S2/SLA，最后真实模型和只读系统替换。各阶段完成后报告证据并再确定下一阶段范围，不改动现有 M1 里程碑进度。
