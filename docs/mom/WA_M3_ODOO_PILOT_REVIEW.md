## 本次申请范围

只申请在一个指定联调宿主上，为一个测试站点启用 `POST /api/world/prod/observe` 的 Odoo 工单单条只读查询。宿主上配置单独的真实世界和权威来源。依赖沿用已合并的 `mom-external-adapter` 固定提交 `5aa312939df2110ff3dda401b9021a0c1ad5a67f`。生产写、订阅、工作台接线和其他来源由各自切片评审。

| 决策项 | 提议 | 批准时需提供 |
|---|---|---|
| 调用身份 | 使用部署方认可的服务凭证，宿主校验签发方、受众、主体、截止时间，并在每次读取前核对当前授权和撤权状态。身份或撤权状态无法验证时拒绝请求。 | 联调宿主、签发方、受众、测试主体、撤权查询或授权配置刷新机制及生效时限 |
| 工单绑定 | 由服务端登记主体、租户、站点、世界、来源及不透明工单引用。给探针主体登记两条引用。第一条源端可读，第二条由独立源身份预先确认存在、对探针的源账号不可读。另备一个宿主侧未授权引用，用于验证 403。 | 测试世界、公开来源别名、样本负责人及安全交付绑定的渠道 |
| Odoo 凭据 | 使用独立的 Odoo 只读账号，授权范围覆盖所需制造工单字段。应用经部署方的密钥设施按引用取值，源凭据与调用凭据分别管理。 | 指定 Odoo 实例和数据库、只读账号负责人、部署环境中的密钥引用与轮换方式 |
| 出站 | 仅允许该站点的固定 HTTPS 目标和 Odoo JSON-2 工单查询。沿用连接器超时、响应大小限制及禁重定向。 | 网络白名单目标和端口、Odoo 路径、网络策略负责人 |

在审批记录中填写配置标识和负责人。实际凭据通过部署方批准的密钥渠道交付。来源地址和工单标识由宿主绑定解析。

## 验收顺序

1. 先运行服务层契约，记录各案例的来源调用数。缺失、失效及撤销凭据预期 401，跨世界或未绑定引用预期 403，以上来源调用均为零。上游故障预期 503，响应或记录错配预期 502，仅已绑定来源收到调用。验证公开包络不含源凭据、私有 ID 或原始诊断。
2. 在获批宿主运行 `node scripts/accept-m3-live-observe.mjs --single-site <bindings.json>`。保留 401、200、404、受信请求关联记录，以及另一源身份对 404 样本存在的确认。该证据通过后，正式真实来源计入 Odoo 1/3。
3. 复跑 M3 桩合同。OpenMES 和 Carbon 分别经站点批准及单站验收后，再运行默认三源探针，确认同一读取意图及三源合同。

回退时停用真实世界绑定、撤销测试主体及 Odoo 账号凭据，并移除该站点的出站授权。复查真实世界拒绝读取和既有桩合同。
