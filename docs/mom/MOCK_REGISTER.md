## 2. 不可用 Mock 掩盖的核心实现

以下是已实现并接受自动化测试的确定性被测对象，不以硬编码成功替代：公告板持久状态与事务/outbox、两类投影、DAG/关卡校验、认领租约与隔离、动作幂等账本、批准有效性、预算和取消。代码位于 `crates/runtime/src/mom/`；清单的 23 项不等于整个系统的开发工作量。

## 3. 当前 gap 与更新方式

- 清单共 23 项：PLANNED 0，MOCK 22，REAL_UNVERIFIED 1，REAL_VERIFIED 0。
- 两场景工具模拟、确定性运行时、HTTP 接口与人类界面已有测试；生产连通、真实模型决策和企业权限尚未验证。不能把 Mock 通过计作真实替换。
- S1 依赖 M01–M12、M14、M17–M23；S2 依赖 M01–M04、M07、M12–M23（范围和调用按实际任务裁剪）。
- 物理试验、现场维修、客户侧确认不能由软件自动替代；真实能力可以是可追踪的人类工作项与回执。
- 新增任何 Mock、脚本决策、模拟时钟、仿真数据源或假批准，必须在这里登记；测试报告列出实际使用的 mock_ids。
- 每关闭一项更新本表与计数，例如 `[x] | Mxx ~~原替代件~~ | … | REAL_VERIFIED：commit / report / date`；未完成真实替换的 Mock 保留未勾选。
- 不采用简单“完成项占比”作为上线评分；安全、授权、资源一致性等关键缺口任何一个未关闭都可能阻断上线。

## 4. 本次实现证据与明确差距

- M01–M16：`fixtures/mom/` 与 `mom/tools.rs`、状态化 MockWorld、动作账本。模拟领域计算和回执，不代表真实 MES/QMS/EAM/WMS/MRO 已连接。
- M17：持久 deadline、虚拟时间、提醒去重与 breach；需要推进仿真时间，不是墙钟定时服务。
- M18：ScriptedMaster 已运行，LlmMaster 有可选适配入口；当前真实模型只开放 wait/delegation 意图，模板选择与关卡由确定性代码控制。未做真实模型盲测或语义模板召回评测。
- M19：按需、非阻塞的脚本调查 worker，支持预算/配额/租约/取消/重启失效；没有把模拟报告当真实专业推理。
- M20：仅 fixture supervisor，可用本机 HTTP 操作。production 一次批准覆盖调拨、维修、改排产三项模拟动作，尚未实现逐动作分别授权；真实替换必须拆分授权，不能用此模拟批准证明职责隔离。无企业登录、职责分离与正式审批链，服务强制仅监听 loopback。
- M21：两份手工模板及已知/拒绝场景；尚未计算真实团队历史覆盖率。
- M22：`web/mom/index.html` 和页面交互测试，支持人类运营看板、决策、证据、Mock缺口、机器视图。企业访问控制未验收，故不勾选。
- M23：真实调用次数与硬配额，子任务按固定代价预留；未对账真实 token/金额。
- 证据入口：`crates/runtime/tests/mom.rs`、`crates/server/tests/mom.rs`、`web/src/mom.test.ts`；`tools/mom/smoke.py` 可重放并生成带 mock_ids 的功能报告。
- SQLite schema v1 为独立数据库；单进程仿真，跨实例陈旧写入会拒绝并要求重开。尚未提供多实例热加载和高可用调度。
