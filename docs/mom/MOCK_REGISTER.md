## 2. 不可用 Mock 掩盖的核心实现

以下是待实现的被测对象，不应以硬编码成功替代：公告板持久状态与事务/outbox、两类投影、DAG/关卡校验、认领租约与隔离、动作幂等账本、批准有效性、预算和取消。它们也全部未实现；清单的 23 项不等于整个系统的开发工作量。

## 3. 当前 gap 与更新方式

- 清单共 23 项：PLANNED 23，MOCK 0，REAL_UNVERIFIED 0，REAL_VERIFIED 0。
- 工具覆盖、生产连通、真实模型决策、人类界面均尚未验证；不能把文档数量或接口设计计作实现率。
- S1 依赖 M01–M12、M14、M17–M23；S2 依赖 M01–M04、M07、M12–M23（范围和调用按实际任务裁剪）。
- 物理试验、现场维修、客户侧确认不能由软件自动替代；真实能力可以是可追踪的人类工作项与回执。
- 新增任何 Mock、脚本决策、模拟时钟、仿真数据源或假批准，必须在这里登记；测试报告列出实际使用的 mock_ids。
- 每关闭一项更新本表与计数，例如 `[x] | Mxx ~~原替代件~~ | … | REAL_VERIFIED：commit / report / date`；未完成真实替换的 Mock 保留未勾选。
- 不采用简单“完成项占比”作为上线评分；安全、授权、资源一致性等关键缺口任何一个未关闭都可能阻断上线。
