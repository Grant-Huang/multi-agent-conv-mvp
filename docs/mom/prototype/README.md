# MOM 高保真交互原型

独立设计演示，入口 [index.html](index.html)。不替换 `/mom/`，不连接数据库、模型、工业接口、data-collection 或 RelOS；没有持久化。所有数值、人员、选择依据、事件、执行状态都是虚构示例。可直接打开 HTML。

## 三入口工作台

遵守 [UI / UE 设计原则](../UI_UX_PRINCIPLES.md)：

| 主入口 | 用户目标 | 原型交互 |
|---|---|---|
| 看板 | 共享态势、重要变化与承诺 | 事项卡、通知、风险摘要；人机料法环测作为筛选标签 |
| 任务 | 推动需要落实的动作 | 待我处理／进行中／受阻／已完成可折叠；已完成默认折叠，受阻展开 |
| 资源 | 看状态与缺失条件 | 全部摘要及人机料法环测聚焦；缺口与限制／全部状态切换；直接进入对应事项处置 |

统一范围为与我相关／本班组／本车间，样例分别包含2／1／3个事项。范围是过滤而非权限，原型不模拟企业身份授权。与我相关包含本人决定、责任与关注工作，并非只显示本人执行任务。

所有入口进入同一事项工作区：事项概览、处理进展、所需条件、方案与决定、承诺与交接。流程、交接、我的工作不再是一级入口。返回保留范围、维度、分组与滚动位置。

- 插单A、客户投诉C101、包装配送使用同一事项注册表；批准和调拨受理由共享演示状态派生，不在各视图维护副本。
- 受理刀具申请后任务转为进行中，资源仍显示等待实物交接；不会误显示已到位或允许生产。
- “人机料法环测”按业务分类；方法、环境与检测结果不能全部等同于可预留资源。共享检验组只维护一条对象记录。
- 已完成节点直接看结论、证据与通俗解释；等待条件直接处理调拨／检验；批准节点进入同一事项的方案页。
- 事项概览先呈现目标、情况、责任、下一步与关闭依据；依赖图与流程选择来源按需展开，不要求理解Agent。
- AI只有一个入口，须先选择事项；桌面侧栏可调宽，Pad／手机切换会话工作区；草稿与会话按事项隔离。
- data-collection → RelOS → 主Agent选已注册DAG → 校验 → 执行的来源链在“流程选择依据”可查，全部模拟。生成草稿不可直接执行。

### 文件与运行

直接打开 `index.html`，保持同目录的 `app.js`、`styles.css`，无需构建。复制到本地时请保留整个目录。HTML不再是单文件内嵌脚本，便于后续维护；上传的同事原型和早期评估仍作为历史参考。

浏览器检查使用静态服务器。例如在仓库根目录：

```bash
python3 -m http.server 18793 --bind 127.0.0.1 --directory docs/mom/prototype
# 在另一个终端，安装好web依赖与Chromium后：
node docs/mom/prototype/check-entries.cjs
node docs/mom/prototype/check.cjs
node docs/mom/prototype/check-nodes.cjs
node docs/mom/prototype/capture.cjs
```

支持 `PROTOTYPE_URL`；脚本运行依赖 `web/node_modules/@playwright/test`。新三入口与截图脚本支持 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`，其余默认 `/usr/bin/chromium`。

## 同事原型评估

参考用户提供的《制枢运营协作智能体_产品原型.html》，做了源码阅读和 Chromium 桌面 / Pad 检查；无 fetch、外部脚本和真实持久化，不能据“已接入 MOM / 实时”等字样认为已集成。

值得借鉴：

1. **制造语义充分。** 设备、订单、质检、维护与仓储围绕真实制造对象组织，优于直接暴露 Agent / 工具 JSON。
2. **人机料法环摘要。** 便于识别生产条件，适合作为总览和任务条件投影。本版补上“测”，避免把所有维度均视为可调度资源。
3. **数据口径与来源。** 指标附公式、周期、来源是很好的方向；需落实到具体快照、时间、新鲜度与真实/模拟标签。
4. **对象联动 AI。** 点击设备、风险和要素进入解释，优于让用户自己重述上下文。
5. **快反闭环、追溯和版本。** 保留触发—方案—执行—核验思想，以及受控工艺和批次追溯，适合转化为有类型的 DAG。
6. **设备空间布局。** 适合查找现场位置、异常区域；应作为可选现场视图，不代替流程图、资源时间视图。

需要调整：

| 观察 | 影响 | 本版处理 |
|---|---|---|
| 部门模块内含大量指标、战略地图、改善、台账与管理表单 | 不同岗位的每日操作路径过长 | 以我的工作和事项为入口，职能与指标作为后续按角色下钻 |
| 全局右侧 AI 与底部 AI 栏可以同时出现 | 会话入口重复，主界面被遮挡；本次1440×1000预览底栏高约208px | 单一会话，默认底部紧凑入口，展开为侧栏或小屏会话工作区 |
| 任务列表提示“勾选即完成并留痕” | 无法证明实际执行和验收 | 待执行、回执、核验分开；不设一键勾选现场完成 |
| 有快反阶段表，但没有 DAG 依赖图与执行选择链 | 不可理解并行、汇合、分支和阻塞传播 | 流程图＋节点详情＋选择依据＋决策记录 |
| 多处写“已接入”“实时”“AI 已研判”，源码为固定样例 | 易将演示能力误认为生产能力 | 常驻全模拟标识；会话标为脚本，来源链标为拟议集成 |
| 根因百分比、收益估算、因果归因有精确值 | 可能造成不适当信任 | 显示候选原因、待验证条件；不把模型置信度当因果概率 |
| “可回滚”用于泛化业务操作 | 已发货、停机、现场加工无法简单撤销 | 决策范围明确；后续生产实现需补偿流程，不能承诺统一撤销 |

## 可视化审查的采纳

参考用户提供《AgentNexus 可视化审查.md》。其 f26cd57 基线与早期评估的PR49状态均是历史记录，不能代表当前远端。当前原型以业务责任与动作作为主展示，技术执行主体在节点详情和来源中可查；候选流程与已注册可执行流程分开，审批说明动作范围与版本。

运行依赖图解释“执行关系”；流程选择依据解释“为什么选择及通过哪些校验”。无对应数据不得编造业务依据。这里全部是模拟证据，不展示模型内部思维链，不宣称已接入完整生产审计链。

## 评审路径

1. 看板 → 插单A → 方案与决定 → 核对范围并批准（模拟）→ 返回看板核对状态。
2. 任务 → 受阻 → 刀具调拨 → 模拟仓储受理 → 返回任务／资源核对“等待实物交接”。
3. 资源 → 全部摘要或某一维度 → 查看与处置 → 同一事项的条件；无需重新搜索台账。
4. 事项 → 处理进展 → 已完成节点看结果／证据／解释；等待节点直接处理缺口。
5. 处理进展 → 流程选择依据 → 查看data-collection／RelOS／Agent的来源与职责。
6. 客户投诉C101 → 处理进展／承诺与交接 → 追溯、冻结、回复与调查；不混用插单A的批准或交接内容。
7. 任一主入口切换与我相关／本班组／本车间，返回后保留范围与筛选。

## 节点直达处置修订

为减少信息链与跳转，点击节点直接打开同一事项的节点工作区，不再将详情插在图下方，也不要求先问AI。

| 节点状态 | 点击后的默认内容 | 后续操作 |
|---|---|---|
| 已完成：维护初筛、质量评估 | 完成结论、已做内容、未完成边界、下一步责任方 | 就地切换证据 / 通俗解释；AI为可选辅助 |
| 等待条件：资源可行性 | 缺失条件、责任方、下一次反馈、影响 | 直接处理刀具调拨、安排首件检验；返回同一条件清单 |
| 等待主管 | 直接进入方案评审 | 对具体版本和范围批准 |
| 等待上游 | 具体阻塞项 | 进入方案或条件处置，不跳到笼统台账 |

模拟仓储受理只改变申请受理状态，不补齐实物交接、首件结果或自动解锁。节点结果解释是固定说明，不需调用模型；AI可选入口保留节点上下文。关闭工作区返回原DAG位置。完整资源台账仍用于跨事项查看，而不是每次处理缺口的必经页面。

新增验收：`node docs/mom/prototype/check-nodes.cjs`；节点结果、证据、解释、直接条件处置、受理不等于完成、方案入口及手机工作区检查通过，原有交互检查亦通过。属于独立原型修订，没有修改生产运行时。
