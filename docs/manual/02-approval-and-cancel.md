# 02 审批与取消

## 场景 A：任务停在“待批准”

**什么时候会这样**：路由估计风险达到 `[orchestrator].approval_risk`（默认 `high`，如删除、对外发送、部署），或规则要求人工确认。此时任务**不会执行，也没有任何结果**，直到你批准。

**怎么做**

1. 在对话里或右侧任务卡片找到“**批准执行**”按钮。
2. 点击前先读按钮上方的审批说明：

   | 项 | 含义 |
   |---|---|
   | 将交给 | 执行者，按执行组顺序列出（主力/备份） |
   | 预计工具 | 路由**预估**会用到的工具；执行时 agent 可能用到它的其他工具，**不是硬限制** |
   | 为什么要批准 | 触发的规则说明 |
   | 完成后 | 批准后的下一步 |

3. 确认无误点“批准执行”，任务进入排队/执行。
4. 不想做：点“取消”（两步确认，见下）。

> 批准只对这一个任务有效。agent 在执行中再请求权限时默认自动允许（因为任务已通过规则与你的批准），每次请求都写入任务证据；想收紧可在该 agent 配置里设 `permission = "read_only"`。

## 场景 B：取消正在执行或排队的任务

取消是**两步确认**，防止误点：

1. 点“取消任务”（对话里）或“取消”（任务卡片上）。
2. 按钮变为“确认取消”，**3 秒内**再点一次才真正取消；超时自动恢复原样。
3. 任务状态变为“已取消”。

“待批准”的任务只在一处显示取消按钮，不会重复。

## 场景 C：任务超时

单个任务从**第一次分到 agent** 开始计时（排队不算），默认 1800 秒（`[orchestrator].task_timeout_secs`）。外部 agent 另有自己的 `timeout_secs`。超时后的具体状态与错误码以任务卡片和 [诊断页](06-troubleshooting.md) 显示为准。

## 注意

- 取消不保证已经发生的外部副作用可回滚（例如 agent 已写入的文件）。
- 取消只对任务本身生效，以界面显示的“已取消”和任务时间线为准。
