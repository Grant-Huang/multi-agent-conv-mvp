# 01 日常对话与委派任务

## 场景 A：简单提问，直接得到回答

1. 点左侧“＋ 新会话”（空会话会显示“试试这些”四条示例，点一条会填入输入框）。
2. 在“输入消息”框输入，**Enter 发送，Shift+Enter 换行**。
3. 简单问题（问候、闲聊、解释）由对话直接回答，边生成边显示（`[conversation].stream_replies = true`）。

系统不理解、需要更多信息时会**追问**，不会硬猜。

## 场景 B：让系统“做一件事”

例如：

- “帮我算一下 (1280 * 0.85 + 36) / 12”
- “写一份关于本地小模型选型的简短报告，保存成 Markdown”
- “在代码目录里写一个 Python 的斐波那契函数并附带测试”

发送后会发生：

1. 对话先给一句**简短回复**，说明它理解的你的意图（完整显示，不截断）。
2. 简短回复下面出现**走马灯**：收起时只显示最新一行进度，运行中行尾有转圈动画；点开从旧到新显示全部进度（不带步骤编号）。
3. 任务在后台执行：排队 → 执行中 → （需要时）审查中 → 已完成。状态同时出现在对话里和右侧“任务”页签。
4. 完成后，**交付消息**在走马灯之后出现；生成的文件作为**产物**列出，每个有“查看”和“下载”按钮。下载的内容与磁盘上文件一致。

> 代码类、文档类任务需经 Reviewer 审查。审查不通过会带问题清单自动返工（默认最多 1 轮，`[orchestrator].max_review_rounds`）。

## 场景 C：看任务到底做了什么

右侧“任务”页签是任务卡片列表（数字角标是任务数）。卡片标题行显示**执行者**；点开卡片可见：

| 区块 | 内容 |
|---|---|
| 执行者 | 哪个 agent、是主力还是备份、排队了多久、返工了几轮 |
| 时间线 | 事件按时间顺序，包括工具调用、权限请求、git diff 等证据 |
| 产物 | 文件列表，可查看、下载 |

任务失败时，对话里显示失败卡片：执行历史从旧到新，**失败原因并入历史末尾**。

## 场景 D：任务进行中补充要求

任务还在执行时直接继续发消息（“再加一个单元测试”“换成中文”）。系统会：

1. 先让路由与规则重新判断补充后的目标；
2. 判断通过后，取消旧任务并创建替代任务（目标合并）；
3. 判断失败（模型传输失败、格式失败、规则拒绝）时，**旧任务不受影响**。

> 已知限制：取消旧任务与创建新任务之间不是原子操作，极端情况下可能短暂两者并存。

## 场景 E：刷新、切换、窄屏

- 刷新页面会回到你上次选中的会话；各会话互不串内容。
- 窄屏（手机/平板）下，左栏变为抽屉，点顶部“☰ 会话”打开；选择或新建会话后自动关闭。
- 对话里等待超过 20 秒会提示“模型可能正在处理其他请求，请稍候。”

## 常见问题

| 现象 | 处理 |
|---|---|
| 发了消息没反应，左下角 LLM 是红色 | 模型服务没起来或地址不对，检查 `[llm].base_url`，见 [06](06-troubleshooting.md) |
| 要求改代码，回复“现在没有能写代码的助手” | 没有可用的 Coding agent，见 [03 接入与管理助手](03-connect-agents.md) |
| 简单问题也被委派成任务 | 模型小导致判断偏差，见 [07](07-model-and-eval.md) |
| 任务“完成”但内容不对 | 完成≠验收通过；查看任务卡片里的审查结论，必要时重新描述需求 |
