# 03 接入与管理助手（agent）

“助手”就是执行任务的 agent。系统通过 ACP（Agent Client Protocol）接入外部 agent。入口：右侧“**助手**”页签；也可以直接在对话里说。

## 场景 A：第一次打开，看看本机有哪些助手

首次打开页面，对话区顶部会出现“**发现的助手**”卡：列出系统在本机自动发现的助手及用途。点“知道了”关闭（只记在当前浏览器，不会再出现）；点管理则直接跳到“助手”页签。

启动时会自动发现这些预设命令（装了就会出现，无需配置）：

| 助手 | 角色 | 命令 |
|---|---|---|
| OpenCode | 写代码 | `opencode acp` |
| Hermes Agent | 通用 | `hermes acp` |
| pi | 写代码 | `pi-acp`（需第三方适配器，成熟度较低） |
| Claude Code | 写代码 | `claude-agent-acp`（先登录 Claude Code，再 `npm i -g @agentclientprotocol/claude-agent-acp`） |
| Codex | 写代码 | `codex-acp`（先 `codex login`，再 `npm i -g @agentclientprotocol/codex-acp`） |
| Cursor CLI | 写代码 | `cursor-agent acp`（先登录） |
| ZCode | 写代码 | `zcode-acp-server`（Node ≥ 22，先用 ZCode App 登录） |

## 场景 B：在“助手”页签接入一个已安装的助手

1. 右侧点“助手”，在“助手列表”里找到该助手一行（显示状态、来源、用途）。
2. 状态含义：已连通 / 未连通 / 不可用；已安装未接入 / 未安装 / 已停用 / 未检测。
3. 点该行“接入”→ 出现**确认卡**（“确认修改”）→ 点“确认”。**确认前不会写入任何东西。**
4. 出现**结果卡**（“修改结果”），显示是否已连通。
5. 想后悔：点“撤销上一次修改”，可连续撤销。

“停用”同理（先确认卡后生效）。**写在 `config.toml` 里的助手不能在这里停用**——它们由配置文件优先管理。

> 接入会把配置写入系统托管的文件并热更新注册表，不需要重启。

## 场景 C：没装的助手，怎么装

1. 在未安装的助手一行点“**看安装步骤**”，展开“安装步骤”区，每步命令旁有“复制”。
2. 在终端执行安装与登录。
3. 点“**我装好了，重新检测**”。系统会做一次握手检测，并用大白话告诉你结果。

检测结果分类：成功 / 未安装 / 需要登录 / 缺少依赖 / 握手失败 / 超时。检测超时后，被检测的进程会被结束。

## 场景 D：在对话里接入

在对话框直接说：

- “把 Claude Code 接进来”
- “接个写代码的助手”

需要先在 `config.toml` 打开 `[conversation] agent_management`。系统会：

- 说清楚了助手 → 直接出**确认卡**；
- 只说了角色/没说清是谁 → 出**选择卡**让你点选，再出确认卡；
- 需要安装 → 出**引导卡**。

确认后追加结果卡，刷新页面后卡片仍在。

## 场景 E：接入一个自定义的 ACP 助手

方式 1（界面）：“助手”页签底部“**添加自定义助手**”，填命令（如 `/usr/local/bin/my-agent`）、参数（如 `acp`）、角色（写代码 / 通用任务 / 审查），提交后同样先出确认卡。

方式 2（配置文件）：

```toml
[[acp.agents]]
id = "my-agent"
command = "my-agent"
args = ["acp"]
role = "coding"
```

可选项：`name`、`workdir`、`permission`（`allow_all` / `read_only` / `deny_all`）、`timeout_secs`、`env`、`max_concurrent`、`agent_type`。

## 场景 F：指定“由谁来做”

不指定时，每类工作用第一个可用的 agent（顺序：内置 → Codex → 本机 ACP → 节点）。指定一个：

```toml
[agents.assign]
coding = "opencode"
```

指定多个组成执行组见 [04](04-nodes-and-groups.md)。

## 场景 G：助手连不上，怎么排查

“助手”页签每行有“**排查**”：

1. 握手检测 + **只读**本机体检（服务/登录 shell 的 PATH、node 版本、凭证文件是否存在）。
2. 用大白话给出结论与修复步骤。**第 1、2 层默认不向外发送任何东西。**
3. 需要进一步求助时可：
   - **复制诊断包**，自己贴给别人或 AI；
   - **请其他助手帮忙**：每次先显示**完整预览**，你逐次同意才发送；帮手的回复还原后仅用于显示。若开启了外发检查（`[egress]`），发送前先脱敏，见 [05](05-research-mcp-egress.md)。

## 场景 H：没有可用的写代码助手时

在对话里让它改代码，系统会用大白话回复“现在没有能写代码的助手，这件事还没有开始做”，并建议先接入——任务**不会**被偷偷派给别人。

## 先体验：不装任何东西

用自带的模拟 ACP agent：

```toml
[[acp.agents]]
id = "mock"
command = "./target/release/an-mock-acp"
role = "coding"

[agents.assign]
coding = "mock"
```

然后说“帮我改代码”，任务面板里能看到工具调用、权限请求、git diff 等完整过程。

## 注意

- 这些助手用的是**它们自己的模型配置**，不会自动使用本地 llama.cpp。
- agent 请求权限默认自动允许，且每次记录在证据里；可用 `permission = "read_only"` 收紧。
- 真实各家 agent 的登录/依赖错误文字，分类规则可能需要按实际情况补充。
