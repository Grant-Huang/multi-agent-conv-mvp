# 04 多台电脑协作（节点与执行组）

当 agent 装在**另一台电脑**（macOS / Linux / Windows 均可）上时，把那台电脑作为“节点”接进来。几台电脑有同一种 agent 时，可组成“执行组”分担任务。

> ⚠️ 节点与主程序之间目前是**明文 HTTP**，只在可信局域网使用；跨网络请用 Tailscale 等私有网络。

## 场景 A：把另一台电脑接进来

1. **在那台电脑上**编译并运行节点程序：

   ```bash
   cargo build --release --bin an-node    # 在本项目里编译，再把 target/release/an-node 拷过去
   an-node
   ```

   它会自动发现本机的 agent，并显示**地址**和 **6 位配对码**。
2. **在主界面**右侧点“**节点**”页签：
   - 同一局域网的节点会出现在“局域网中发现的节点”，输入配对码点“配对”；
   - 网络屏蔽组播时，用“**按地址添加**”填 IP（如 `192.168.1.23`）和配对码。
3. 配对成功后，节点出现在“已配对的节点”，显示它的 agent 列表。那台电脑上的 agent 以 `agent名@节点名` 的形式可用，例如 `hermes@office-pc`。

## 场景 B：解除配对

在“已配对的节点”中点解除。**同样是两步确认**（第一次点变确认文字，再点才执行）。解除后该节点上的 agent 不可用。

## 场景 C：几台电脑组成执行组

```toml
[agents.assign]
general = ["hermes@office-pc", "hermes@mac-mini"]   # 第一个是主力，其余待命
```

规则：

- 只能放**同一类型**的 agent；
- 主力忙满时交给空闲的备份，都忙就**排队**；
- 离线的跳过；
- **执行出错直接报错，不换人重做**。

怎么确认生效：任务卡片的“执行者”一节会显示是**主力**还是**备份 N**（共几个）、排队时长。准确的 agent id 可在“诊断”页看到（需先开启开发者模式）。

## 节点自身配置（可选）

`an-node node.toml`，或命令行参数 `--port`、`--name`、`--workdir`、`--bind`、`--no-advertise`。节点日志在 `~/.agentnexus-node/logs/`；主程序与节点使用同一个 `task_id`，可以跨电脑串联排查。

## 常见问题

| 现象 | 处理 |
|---|---|
| 发现不了节点 | 网络可能屏蔽了组播（`[nodes].discovery = true` 依赖它），改用“按地址添加” |
| 配对码不对 | 以节点程序当前显示的 6 位配对码为准（输入框最多 7 个字符） |
| 节点上的 agent 显示不可用 | 看左下角该行的原因；节点离线时每 15 秒（`[nodes].refresh_secs`）刷新一次 |
